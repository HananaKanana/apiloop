## 修复：服务起来了但 mock 接口全部 404

**现象**：`mock start` 打印 "server start success"，端口能连，但所有 mock 路由 404。

**根因**：`router.js` 里已经带了包装外壳（第 1 行 `function setRouter(app){`，末行
`module.exports.setRouter = setRouter`），而 `lib/command.js` 的 `setRouter()`
无条件再包一层，生成的 `.router.js` 出现两层 `setRouter`：

- 第 1 行 / 第 4 行 各一个 `function setRouter(app){`
- 第 365 行 / 第 366 行 各一个 `module.exports.setRouter = setRouter`

模块作用域的 `setRouter` 解析到**外层**函数，第 366 行把 exports 覆盖成外层函数；
外层函数体里只有一个内层函数声明、从不调用它 → 一条路由都没注册。
而 `app.listen(port)` 在函数末尾照常执行 → 「起来了但没生效」。

**关键佐证**：`.router.js` 的 mtime（02:58）晚于 `router.js`（02:55），
说明服务确实读到了最新 router.js，排除「没重启」「cwd 不对」。
全局包 `~/.npm-global/lib/node_modules/server-mock/lib/command.js` 与仓库版本 diff 为空，
确认跑的是全局那份。

**改动**（commit d92fe6a，已提交未推送）：
- `lib/command.js`：包装前用 `/module\.exports\.setRouter/` 检测是否已包装，
  已包装则原样使用并打印 Warning，杜绝二次包装。
- `.gitignore`：新增 `.router.js`（每次 start 都会重新生成的产物，之前一直污染 git status）。
