## T18 项目备份与恢复 · 后端（backend）

### 背景
用户要能把整个项目备份下来、需要时恢复（误删、做实验前留底、搬到另一套部署）。另外云端可以每天自动备份。界面是 T20（T18 通过后才派）。
主会话已做（`248c0bf`）：`lib/api/backup.js` 空壳已挂到 `lib/admin.js`（云端、网关都挂）；`/backup/restore` 已加进 50 MB 请求体前缀。

**能复用的**：「复制为新项目」（`lib/api/copy.js` 的 `POST /projects/:pid/duplicate`）已经有整套「换 id、重写前置接口引用、复制测试集」的逻辑。恢复成新项目本质上是同一件事，**把能共用的部分提成函数**（可以新建 `lib/project-clone.js`），别另写一份。

### 接口约定

### 备份文件格式（JSON）
```json
{ "format": "apiloop-backup", "version": 1, "exportedAt": 1759650000000, "appVersion": "2.1.1",
  "project": { "name", "description", "variables", "extra" },
  "folders": [...], "apis": [...], "examples": [...], "expectations": [...], "environments": [...], "suites": [...] }
```
- 各实体保留原 id（恢复时换新 id），字段和库里的一致（含 `extra`）。
- **保密变量的值不进备份**：行保留（key、保密标记），值写空串；`secret_values` 表不导出。
- 不包含：成员、分享链接、评论、历史、回收站、运行记录、Cookie、个人偏好。

### `GET /projects/:pid/backup`（editor）
返回备份文件，`Content-Disposition: attachment; filename="apiloop-<项目名>-<yyyyMMdd-HHmm>.json"`（文件名里的项目名要处理非法字符、中文用 RFC 5987 `filename*`）。

### `POST /backup/restore`（请求体最大 50 MB）
```json
{ "backup": { ...备份内容... }, "mode": "new", "name": "可选，新项目名" }
{ "backup": { ... }, "mode": "overwrite", "projectId": "p_xxx" }
```
- `mode: "new"`：任何登录用户都能做，建一个新项目（当前用户是 owner），默认名「<原名>（恢复）」。返回 `{ project }`。
- `mode: "overwrite"`：**只有这个项目的 owner（或系统管理员）**能做。现有的目录、接口、环境、测试集**全部移进回收站**（用现有回收站的函数，这样还能救回来），再按备份写入；项目的名称、描述、变量、`extra` 用备份里的。成员、分享不动。返回 `{ project, trashed: { folders, apis, environments, suites } }`。
- 校验：`format` / `version` 不对 400「这不是 apiloop 的备份文件」；`version` 比当前支持的新 400「备份来自更新的版本，请先升级」；内部引用对不上（接口指向不存在的目录等）就丢掉那条引用而不是整体失败，返回里给 `warnings`。
- 全部写库在**一个** `handle.transaction(fn, { projectId })` 里（同步才会记下改动）；中途失败整体回滚。
- 网关上照常能用（读写本机库，离线也能恢复，之后同步上去）。

### 云端自动备份（只在云端跑，网关不跑）
- 系统设置：`GET / PUT /settings/backup`（PUT 只有管理员）：`{ "enabled": false, "hour": 3, "keepDays": 14 }`（`hour` 0–23，`keepDays` 1–90）。存在现有系统设置那张表 / 那套机制里（看 `lib/api/settings.js` 的 proxy 是怎么存的）。
- 每天到点给**每个项目**写一份备份到数据目录下的 `backups/<projectId>/<yyyyMMdd-HHmmss>.json`（数据目录就是 `data.db` 所在的目录，云端是 `./data`）；项目内容和上一份完全一样（按内容 hash）就不写；超过 `keepDays` 的删掉；项目已删除的那个目录在保留期过后也删掉。
- `GET /projects/:pid/backups`（owner 或管理员）：`{ "items": [ { "id": "20261005-030000", "at": 1759633200000, "size": 12345 } ] }`，新的在前。
- `GET /projects/:pid/backups/:id`：下载那份文件。`id` 只允许 `\d{8}-\d{6}`，防止路径穿越。
- `POST /projects/:pid/backups/:id/restore` `{ "mode": "new" | "overwrite" }`：等于拿这份文件调 `/backup/restore`。
- 定时器启动时算下一次的时间，用 `setTimeout` 链，别每分钟轮询；进程退出不影响。
- **网关**：`/settings/backup`、`/projects/:pid/backups*` 这几条是「只有云端有的」，网关上要转发给云端（看 `lib/gateway/account.js` 的 `cloudOnlyPath` / `forwardCloudOnly` 怎么做的，加进去）；没登录时返回 409「登录后才能看云端备份」。

### 要做的事
1. `lib/backup.js`（新）：导出、校验、恢复（new / overwrite）。
2. `lib/backup-scheduler.js`（新）：自动备份定时器、写文件、清理。在哪里启动它（云端进程启动处）如果不在允许路径里，先 `ateam ask`。
3. `lib/api/backup.js`：上面的路由。
4. `lib/project-clone.js`（新，按需）+ `lib/api/copy.js`：把复制项目的共用逻辑提出来，`/duplicate` 改用它，行为不变。
5. `lib/gateway/account.js`：转发云端专有的那几条。
6. 自测：建一个内容齐全的项目（目录嵌套、接口带示例 / 期望 / 断言 / 前置接口、环境含保密变量、测试集引用接口、gRPC / MQTT 接口的 extra），导出 → 恢复成新项目 → 逐项比对（数量、字段、id 都换了、引用都指向新 id、保密值为空）；overwrite → 原内容进了回收站、能从回收站恢复；坏文件、新版本文件、viewer 调 overwrite 的报错；把自动备份时间调到下一分钟跑一次，看文件、hash 去重、清理；网关上导出 / 恢复离线可用、`/projects/:pid/backups` 转发到云端。`/duplicate` 回归一次。

## T20 项目备份与恢复 · 前端（frontend，T18、T19 通过后）

### 用户看到的样子
- 项目设置加一个「备份」页签（`ProjectSettingsView.vue`，客户端和网页版都有）：
  - 「下载备份」：调 `GET /projects/:pid/backup` 下载；说明一句「不含保密变量的值、成员、分享、历史」。
  - 「从备份文件恢复（覆盖当前项目）」：只有 owner / 管理员能点；选文件 → 显示备份里的项目名、导出时间、接口数、环境数 → 二次确认（要求输入项目名确认）→ 调 `/backup/restore` overwrite → 提示「原来的内容在回收站里」，刷新目录树和环境。
  - 「云端自动备份」列表（`GET /projects/:pid/backups`）：时间、大小，每行「下载」「恢复成新项目」「覆盖当前项目」（覆盖同样二次确认）；没开自动备份时说明「管理员可以在系统设置里开启」；客户端没登录时显示后端给的提示。
- 项目下拉（`ProjectSwitcher.vue`）里加「从备份恢复成新项目」：选文件 → 预览 → 可改名 → 恢复 → 切到新项目。
- 系统设置（`SettingsView.vue`，管理员）加「自动备份」一节：开关、每天几点、保留几天。
- `warnings` 有值时列出来。
