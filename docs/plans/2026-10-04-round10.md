## 1. 代码片段多语言（session2）

### 要解决的问题

代码片段现在只有 cURL。前端、后端、测试同事要把接口接进自己的代码，还得自己把 cURL 翻译成 axios / requests / OkHttp。

### 用户看到的样子

- 代码片段面板（`CurlSnippet.vue`，可以改名成 `CodeSnippet.vue`）标题改成「代码片段」，上面一个语言下拉：
  **cURL**、**JavaScript – fetch**、**JavaScript – axios**、**Python – requests**、**Java – OkHttp**、**Go – net/http**、**PHP – cURL**、**C# – HttpClient**。
  选过的语言记在 `localStorage`（读写包 try/catch），下次打开默认还是它。
- 每种语言都带语法高亮（JavaScript 已经有；Python / Java / Go / PHP 用刚装的包；C# 用 Java 的高亮凑合，或者用 `@codemirror/legacy-modes` 里的 clike —— 那个包没装，**不要装**，用 Java 的就行）。cURL 保留上一轮做的高亮。
- 和 cURL 一样：变量换成实际值、鉴权和继承的鉴权都带上、公共请求头带上；没定义的变量原样保留并提示。
- 「复制」按钮复制当前语言的代码。

### 怎么做

- 服务端生成（和 cURL 同一份「准备好的请求」）：`lib/curl-export.js` 旁边新建 `lib/code-export.js`，先把请求整理成一个中间形状
  `{ method, url, headers: [[k, v]], body: { kind: 'none' | 'raw' | 'urlencoded' | 'form' | 'binary', text?, fields?, file? } }`
  （cURL 那份现在是边算边拼字符串，把「算」那一半抽出来共用），每种语言一个渲染函数。
- 接口：现在是 `POST /projects/:pid/send/curl`。加一个 `language` 参数（默认 `curl`，返回里多一个 `code` 字段，`curl` 字段保留给老客户端），
  或者新开 `POST /projects/:pid/send/snippet` —— 二选一，交接里说。
- 每种语言生成的代码要**真能跑**：字符串转义（引号、反斜杠、换行、中文）各语言规则不一样，逐个处理；JSON 请求体在 JS / Python 里
  直接写成对象字面量（`json=...` / `data: {...}`）更好读，解析不了的 JSON 就按原文字符串发。
  表单文件：各语言用各自的文件写法，路径就是请求里填的本机路径。
- 自测：在 scratchpad 里用本机有的 `node` 真跑一下 fetch / axios 两种生成结果（打一个本地回显服务，看收到的方法、地址、请求头、请求体和点「发送」一致）；
  其他语言本机有解释器的（`python3` 有）也真跑一下，没有的仔细读一遍转义。

## 2. 中文随机数据（session2，第 1 节之后）

### 要解决的问题

造测试数据时手机号、身份证号、中文名都要自己编。Mock 里有随机数据（`{{@cname}}` 这些），但那是给 Mock 返回用的，**发请求时用不了**。

### 用户看到的样子

- 请求的地址、参数、请求头、请求体、数据库操作语句里能写这些动态变量，**每出现一次生成一个新值**：

  | 写法 | 中文写法 | 生成什么 |
  | --- | --- | --- |
  | `{{$randomPhone}}` | `{{$手机号}}` | 11 位手机号（真实号段） |
  | `{{$randomIdCard}}` | `{{$身份证}}` | 18 位身份证号（地区码、出生日期合法，最后一位校验码正确） |
  | `{{$randomChineseName}}` | `{{$中文名}}` | 中文姓名 |
  | `{{$randomEmail}}` | `{{$邮箱}}` | 邮箱 |
  | `{{$randomDate}}` | `{{$日期}}` | 近一年内的日期 `YYYY-MM-DD` |
  | `{{$randomDateTime}}` | `{{$时间}}` | `YYYY-MM-DD HH:mm:ss` |
  | `{{$randomAddress}}` | `{{$地址}}` | 省市区 + 详细地址 |
  | `{{$randomCompany}}` | `{{$公司}}` | 公司名 |
  | `{{$randomBankCard}}` | `{{$银行卡}}` | 16 / 19 位卡号（Luhn 校验正确） |
  | `{{$randomCreditCode}}` | `{{$信用代码}}` | 18 位统一社会信用代码（校验位正确） |
  | `{{$randomPlate}}` | `{{$车牌}}` | 车牌号 |
  | `{{$randomIp}}` | — | IPv4 |
  | `{{$randomInt(1,100)}}` | `{{$整数(1,100)}}` | 区间内整数（不带参数时 0–1000，和现有的 `$randomInt` 一致） |
  | `{{$timestampMs}}` | — | 毫秒时间戳 |

- 输入 `{{$` 时自动补全列出这些（带中文说明），和现在补全变量的地方一样。
- 脚本里：`pm.variables.replaceIn('{{$手机号}}')` 能用（现在有没有 `replaceIn` 先看一下，没有就加）。
- 帮助里「变量」那节补一张表。

### 怎么做

- `lib/variables.js` 的 `DYNAMIC`：加上这些。生成逻辑能复用 `lib/mock-engine.js` 里的就复用（中文名、地址、公司……），身份证 / 银行卡 / 信用代码的校验位自己算。
- **变量名允许中文**：`NAME_PATTERN` 现在是 `[\w.\-$]`，不认中文 —— `{{$手机号}}` 会被当成「不是变量」原样留着。
  这一条**同时也修掉一个现有问题**：第八轮的数据驱动，CSV 列名是中文时（`账号`、`密码`）`{{账号}}` 不会被替换。
  改成认 Unicode 字母（`\p{L}`，正则加 `u` 标志），**前端 `web/src/utils/variables.js` 里变量高亮 / 缺失检查用的那份规则一起改**，两边要一致。
- 带参数的写法 `{{$randomInt(1,100)}}`：名字后面允许 `(…)`，只对动态变量生效；普通变量名里不允许括号。
- **同一个请求里 `{{$手机号}}` 出现两次是两个不同的值**（和 `{{$guid}}` 现在的行为一致），帮助里写清楚；要同一个值就先在请求前脚本里
  `pm.variables.set('phone', pm.variables.replaceIn('{{$手机号}}'))` 再用 `{{phone}}`。

## 3. 前置接口（自动登录）（session1）

### 要解决的问题

token 过期了，每个人每天都要先手动点一次「登录」接口再回来发请求；测试集每个都要在最前面加一个登录步骤。

### 用户看到的样子

- **项目设置**和**目录设置**里加「前置接口」：
  - 选一个接口（下拉 / 树选择，通常是登录接口）；
  - 什么时候调：☑「变量 `token` 没有值时」（变量名可填）☑「响应是 401 时，自动调用后重发一次」；
  - 一行说明：「前置接口要自己把 token 存起来（在它的『断言』页签里提取变量，或者写响应后脚本）。」
- 目录上设了就用目录的（最近的那层），没设往上找，一直到项目。接口自己可以在「设置」里勾「不使用前置接口」。
  **前置接口本身不会再触发前置接口**（不然登录接口自己就死循环了）。
- 发送时自动调了前置接口，响应面板的「控制台」里有一行「已自动调用前置接口「用户登录」（因为 token 没有值 / 响应 401）」；
  401 重发的那次，响应面板顶上一条小提示「token 失效，已自动登录并重发」。
- 测试集、批量运行里同样生效（测试集里提取的 token 留在这次运行的内存里，后面的步骤不会每步都登录）。压测不跑。

### 数据

- `projects.extra.preflight` / `folders.extra.preflight`：`{ apiId, whenMissing: 'token' | '', retryOn401: true | false }`。
  目录上可以显式设成 `{ apiId: null }` 表示「这个目录下不用前置接口」（挡住往上找）。
- 接口自己：`apis.extra.noPreflight: true`。
- 项目 / 目录 / 接口 DTO 顶层多给这几个字段，保存接口接受（合并进 `extra`）。复制项目、跨项目复制要把 `apiId` 换成新项目里的。

### 怎么做

- `prepare`（`createPreparer`）里：顺着目录链找到生效的设置；这次发的不是前置接口本身、也没有 `noPreflight` 时，
  **用同一个 prepare 再准备一份前置接口的请求**（同一个环境、同一个 `who`，带一个「不再找前置接口」的标记防止递归），放进 `prepared.preflight`，
  条件放进 `prepared.preflightRule`。
- `send-core.run`：
  1. 最开始（请求前的数据库操作之前）判断「变量 X 没有值」（用 `mergeScopes(scopes)` 那张表，空串也算没有）→ 先跑一遍 `prepared.preflight`
     （就是递归调 `run`，它自己的脚本、断言、提取、数据库操作都照常跑）；
  2. 把它对变量的改动（`changes.scriptState.variables`）并进当前这次的 `state.variables`（这样 `record` 写回库时 token 一起存下来，下次就不用再登录了）
     和 `scopes`（后面替换变量时用得上）；Cookie 增量也并进来（登录接口常常是种 Cookie）；
  3. 控制台加一行说明；
  4. **401 重发**：非流式（没有 `hooks.onChunk`）时在 `run` 里直接做 —— 主请求回 401、规则开着、这次还没跑过前置接口 → 跑前置接口 → 重发一次主请求。
     **流式（界面上点「发送」走的就是流式）没法在 `run` 里重发**（响应头已经推给浏览器了），所以由前端做：
     收到 401 且这个接口生效的规则里 `retryOn401` 开着 → 自动带 `options.forcePreflight: true` 再发一次（只重发一次），顶上给提示。
     `forcePreflight` 为真时 `run` 不看条件直接先跑前置接口。
- 前置接口失败（请求出错、它自己的断言没过）：主请求**照样发**（可能 token 其实还有效），控制台里写清楚前置接口失败的原因。
- 自测：用「登录接口在『断言』页签里提取 token」这种**界面上的真实配法**，不是脚本；覆盖：变量没值时调、有值时不调、401 重发（非流式 + 流式两条路）、
  前置接口本身不递归、目录覆盖项目、`noPreflight`、测试集里只登录一次。

**行为上要注意的**

- urlencoded 的请求体现在会显式带上 `Content-Type: application/x-www-form-urlencoded`（以前靠 curl 自己补）。
  cURL 输出因此多一行 `--header`，但发出去的头和以前完全一样；别的语言也能和「发送」逐字对齐。
- JSON 请求体在 JS / Python 里写成对象字面量（计划要求），所以字节上不是原文（空白不同、Python 的 `json=`
  会把非 ASCII 转成 `\uXXXX`），**解析后完全一致**。
- 表单文件：JS / Go / C# 都是「读本机路径」，路径就是请求里填的那个。
- Java / C# 的字符串把非 ASCII 转成 `\uXXXX`，源文件用什么编码都不会乱。

**自测怎么做的**

- scratchpad 里起临时云端 + 本机回显服务，打 `POST /send/curl` 拿代码，把生成的 fetch / axios / python
  **真跑一遍**，和点「发送」收到的请求逐项比对：方法 / 地址 / 请求头（Content-Type、自定义头、Authorization）/
  请求体（JSON 解析后、表单字段、multipart 的字段和文件内容、GET 无体）。
  四种请求体形态共 12 项，全部一致。
- Java：用 OkHttp 的桩类 `javac` 编译，四种形态都过。
- C#：`dotnet run` 真跑，四种形态都 200。
- Go / PHP 本机没有编译器，仔细读了一遍（Go 的 import 是按请求体形态动态加的，用不到的包不 import）。
- `npm test` 71 项全过；`npm run build:web` 通过；vite SSR 扫了 4 个 .vue（含新改的两个）全过。

**没做 / 拿不准的**

- C# 的 `MultipartFormDataContent` 会把非 ASCII 的**字段名和文件名**编码成 `=?utf-8?B?...?=`（.NET 自己的行为），
  和执行器发的原始 UTF-8 名字不一样。字段值是原样的，请求也能通。要完全一致得手工拼 Content-Disposition，这次没做。
- Node 的 fetch 不接受非 ASCII 的请求头值（undici 抛 ByteString 错）；执行器用的是 `http` 模块，能发。
  请求头里带中文时生成的 fetch 代码会直接抛错 —— 这是 fetch 的限制，不是生成的问题，没特殊处理。
- `web/src/api/apis.js` 不在第 0 节的「只有谁改」清单里，动之前看过 diff，只有我这一处注释。
- 八种语言的语法包是静态 import 进主包的（主包 2.1MB → 2.38MB）。没做懒加载，计划里也没要求。

#### 几个刻意的决定（审阅时重点看这里）

1. **「没配过」和「这一层不用」是两回事**。目录上 `preflight` 为 `null` = 跟着上层走；
   `{ apiId: null }` = 这个目录下不用（挡住往上找）。所以 `toPreflight` 对一个对象**不会**
   因为 `apiId` 为空就返回 null。界面上分别是下拉里的「跟随上层设置」和「不使用前置接口」。
2. **前置接口是「递归 prepare 出来的一整份 prepared」**，不是另写一套执行:
   它就是普通的一次发送（同一个环境、同一个 who、脚本/断言/提取/数据库操作都照常跑），
   `send-core.run` 递归调自己。`skipPreflight` 是**内部 extra 开关**，不是请求体的一部分
   （请求体是用户能改的），保证前置接口自己不会再触发前置接口。
3. **401 为什么分两条路**：流式的响应头在 `onReady` 就推给浏览器了，服务端再换一份响应
   等于说了两次话。所以非流式在 `send-core` 里直接重发；流式由前端拿到 `end` 事件里的
   `retryOn401` 之后带 `forcePreflight` 再发一次（**只重发一次**，`shouldRetry401` 里判的）。
4. **Cookie 也并进来**：登录接口常常是种 Cookie 而不是给 token。`lib/cookies.js` 的 jar 只开了
   `cookieHeaderFor` / `storeFrom` / `changes` 三个口子，所以是把 cookie 对象**倒回
   `Set-Cookie` 头**再喂 `storeFrom` —— 走别的路（直接改 jar 内部）会绕过 `initialByKey`，
   那些 cookie 永远不出现在 `changes()` 里、写不回库。
5. **前置接口失败不影响主请求**：请求出错、响应 4xx/5xx、它自己的断言没过，都只在控制台
   写一句原因（token 可能其实还有效）。
6. **数据驱动的那一行跟着走**：测试集每次 prepare 之后会把 `prepared.scopes.data` 换成
   当前数据行，而 `prepared.preflight.scopes` 是 prepare 那一刻算的。所以跑前置接口之前
   把 `data` / `transient` 复制过去 —— 登录接口可以用 `{{username}}` 这种来自数据行的值。

#### `'WS'` / 其它既有行为的兼容

- 前置接口的下拉**不列 WebSocket / Socket.IO 接口**（它们发不出 HTTP 请求）。
- 没配前置接口时，`prepared.preflight` 和 `preflightRule` 都是 `null`，`send-core` 里所有
  新增分支都不会进 —— 行为与以前**一个字都不差**（`npm test` 71 项全过是最低限度的证据，
  真正靠得住的是自测里「有值时不调」那几条）。

#### 没做 / 需要用户确认的

1. **`apiId` 指向的接口被删掉之后**：发送时当「没配过」处理（不再调、也不报错），
   设置页里会显示「前置接口已经删了，请重新选一个」。**没有做「删接口时顺手清掉引用它的
   preflight 设置」** —— 那要动删除那条路，影响面比这一节大。
2. **跨项目复制时，前置接口指向的接口没跟着一起复制过去的，整块设置会被去掉**（回到
   「跟着上层走」）。比如复制一个目录到别的项目，而这个目录的前置接口是项目根上的登录接口 ——
   目标项目里没有它，只能去掉。留在 handoff 里说明，没有更好的做法。
3. **同一接口的「变量没值时」只在一次执行的最开始判一次**：401 重发那条路不会再看条件
   （它就是「强制先登录」）。测试集里第一个步骤登录之后，后面的步骤看的是这次运行累积的
   变量 —— 如果测试集是**数据驱动、每行一个账号**，token 会被第一行拿走、后面几行不会重新登录，
   这是个已知的坑（要每行都登录得自己在脚本里清掉 token）。计划里写的是「一次运行只登录一次」，
   所以按计划做的。
4. **401 重发会写两条历史**（第一次 401 一条、重发那条一条）。没做「把两条合成一条」，
   两条留着反而能看出「这里发生过一次自动登录」。
5. **`/send/curl`（代码片段）和 GraphQL 内省显式跳过前置接口**：它们不发请求，
   没必要为它们多准备一份 prepared。
6. **没有做「前置接口也支持 Socket.IO / WebSocket」**，也不支持「一次配多个前置接口」。
