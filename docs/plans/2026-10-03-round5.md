## 1. 公共请求头（session1）

### 要解决的问题

很多接口都要带同样的请求头（`X-User-Info`、`X-Tenant-Id`、`X-Client-Version`），现在只能每个接口里各加一遍，
改一次要改几十个。鉴权和变量已经能在目录上设、往下继承，请求头还不行。

### 用户看到的样子

- **目录设置**（`FolderTab.vue`）加一块「公共请求头」，和目录变量同样的表格（名称 / 值 / 说明 / 启用）。
  一行灰字：「这个目录下的所有接口发送时都会带上这些请求头；接口里有同名的请求头时，用接口自己的。」
- **项目设置**（项目变量、项目鉴权所在的那一页）同样加一块，作用于整个项目。
- **接口的 Headers 页签**：在接口自己的请求头表格**下面**，灰色显示「继承的请求头」：名称、值、来自哪里（「项目」「目录 用户管理」），只读。
  被接口自己同名的请求头覆盖掉的那行加删除线，提示「已被接口里的同名请求头覆盖」。
  每行后面一个小按钮「在这里覆盖」：把这一行复制到接口自己的表格里，方便改值。
  没有继承的请求头时这一块不显示。
- Headers 页签上的数字角标只算接口自己的。

### 数据

- `projects.extra.headers`、`folders.extra.headers`：行数组，和接口请求头同一个形状 `{ key, value, enabled, desc }`。
- 项目 / 目录的 DTO 顶层多给 `headers`；保存接口接受 `headers`，合并进 `extra`（不冲掉 extra 里别的字段）。

### 发送时怎么合并

- 顺序「项目 → 外层目录 → 内层目录 → 接口」，**后面覆盖前面同名的**，名字**不区分大小写**。停用的行跳过。
- 在 `lib/api/send.js` 里做，和 `inheritAuth`、`resolveVariables` 放在一起，用同一个 `folderChain`。
  `/send`、`/send/stream`、`/send/curl`（复制为 cURL 也要带上）、WebSocket 握手都要生效 —— 找一下这几处是不是共用一个 prepare，共用就只改一处。
- 值里的 `{{变量}}` 照常替换（合并在变量替换**之前**做，这样继承来的值也能用变量）。
- 鉴权生成的 `Authorization` 头、Cookie 照旧由原来的逻辑加，公共请求头里写了同名的就以鉴权为准（和接口自己写 `Authorization` 时的现有行为一致，先看现在是谁覆盖谁，保持一样）。
- 历史里记的是合并后的请求头（这样历史能看出实际发了什么）。

### 其他地方

- **批量运行**：走的就是 `/send`，自然生效。
- **分享文档**：接口文档的请求头表格里加上继承来的（标「公共」），敏感值照样打码（`lib/api/shares.js` 已有规则）。
- **导出 OpenAPI**：继承来的请求头也作为 header 参数导出（`lib/openapi-export.js`）。
- **导出 JSON**：项目 / 目录的公共请求头放进导出文件里自己的字段（导入时读回来）；别的工具读不懂也没关系。

## 2. 全局查找替换（session1，第 1 节之后）

### 要解决的问题

后端改了版本前缀（`/api/v1` → `/api/v2`）、换了一个请求头名、某个参数改了名，现在只能一个个接口打开改。

### 用户看到的样子

- 入口：左上角项目名下拉里「查找替换」，或者快捷键 `⌘⇧F` / `Ctrl+Shift+F`。打开一个大一点的弹窗（或抽屉）。
- 上面：查找框、替换框；选项「区分大小写」「全字匹配」「正则」；范围多选：地址、请求头、Query / Path 参数、请求体、脚本、名称、说明（默认地址 + 请求头 + 参数 + 请求体）；
  目录范围：整个项目 / 选一个目录。
- 输入后自动搜（防抖 300ms），下面按接口分组列出命中：接口名（方法色块）、哪个字段、命中那一行的前后文（高亮命中的部分）、替换后的样子。
  每条前面有勾选框，默认全勾；每个接口一个总勾选框。
- 「替换所选（N 处）」→ 确认框：「将修改 x 个接口里的 N 处。替换会直接保存，不能撤销，确定吗？」
- 替换完：提示「已修改 x 个接口」，目录树、已打开的标签页刷新（已打开且有未保存修改的那个接口**跳过不改**，结果里列出来「这些接口有未保存的修改，没有替换」）。
- 只搜不替换也很有用：替换框空着就是纯查找，点结果打开那个接口。
- viewer 只能查找，没有替换。

### 接口

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `POST /projects/:pid/search` | viewer | `{ query, caseSensitive?, wholeWord?, regex?, fields: [...], folderId? }` → `{ matches: [{ apiId, field, location, line, start, end, preview }], total, truncated }`。最多返回 500 处，超了 `truncated: true` |
| `POST /projects/:pid/replace` | editor | `{ 同上的查找条件, replacement, targets: [{ apiId, field, location }] , skipApiIds: [...] }`。服务端**重新搜一遍**，只替换 targets 里列出的那些位置（按 apiId + field + location 对上），一个事务里做完，返回 `{ changedApis, changed }` |

- `field`：`url` | `headers` | `params` | `body` | `scripts` | `name` | `description`。
  `location` 定位到具体哪一处：请求头 / 参数是「第几行的名称或值」（比如 `headers[2].value`），请求体是 `body.raw`，脚本是 `scripts.test` / `scripts.prerequest`。
- 正则：用 JS 正则；写错了返回 400「正则写得不对：…」。替换串里 `$1` 这类分组引用照 JS 的规则。
- 搜索逻辑写成纯函数（`lib/search-replace.js`），输入接口 DTO 列表 + 条件，输出命中；替换也是纯函数，输入接口 + 要替换的位置，输出 patch。
- 不搜：示例、Mock 期望、环境变量（环境变量第 3 节能改）。保密变量不涉及。

## 3. 环境对比（session2，第 4 节之后）

### 要解决的问题

项目里有开发、测试、预发、生产几个环境，「测试环境少了一个变量」「两个环境的 host 写成了同一个」这种问题只能一个个点开环境看。

### 用户看到的样子

- 入口：环境下拉（右上角选环境的那个）最下面「对比所有环境」，以及左上角项目名下拉里「环境对比」。打开一个新标签页「环境对比」（和运行标签页一样是一种标签页，同一个项目只开一个）。
- 一张表：第一列是变量名（所有环境的变量名并集，按名字排序），后面每个环境一列，格子里是值。
  - 某个环境没有这个变量：格子显示灰色「（缺少）」，悬停「点一下给这个环境加上」，点了变成可输入。
  - 同一行各环境的值都一样：值显示成浅灰（「都一样」，不用看）；不一样的正常颜色。
  - 保密变量：显示 `••••••`，点眼睛看自己的值（和变量表一样的规则：只能看到自己的）。
  - 停用的变量：值加删除线。
- 格子可以直接改（单击进入编辑），改过的格子标黄；右上角「保存（N 处修改）」一次保存所有环境，「放弃修改」。
- 工具栏：「只看有差异的」开关（隐藏各环境都一样的行）；「补齐缺少的变量」：把所有环境缺的变量都加上（值为空），加完是未保存状态，用户填好再保存。
- 有未保存修改时关标签页要确认（用现成的标签页 dirty 机制）。
- viewer 只读。

### 怎么做

- 纯前端：用现有的环境接口读、`PUT /environments/:id` 一个个保存（只保存改过的环境）。保密值的读写走现有接口自然生效（第三轮第 3 节）。
- 内置「Mock」环境不进对比表。
- 保存时有一个失败了：已经成功的不回滚，提示哪个环境没保存成功，那一列保持未保存状态。

## 4. 接口评论和 @ 提醒（session2）

### 要解决的问题

前后端联调时的问题（「这个字段什么意思」「联调报 500 了」）散在聊天软件里，过几天就找不到，也和接口对不上。

### 用户看到的样子

- **接口标签页**：右上角（「代码」「保存」那一排）加一个「评论」按钮，带条数角标；点了右侧滑出评论面板（抽屉，不挡住请求编辑）。
  - 从上到下按时间排的评论：头像、名字、时间（「3 分钟前」，悬停显示完整时间）、内容（保留换行，网址可点击，**不渲染 HTML**）。
  - 底部输入框，`Ctrl/⌘ + Enter` 发送；输入 `@` 弹出项目成员列表（按名字过滤），选中插入 `@张三`。
  - 自己的评论可以编辑、删除；删除后那一楼显示「这条评论已删除」。管理员可以删任何人的。
  - 面板顶部一行灰字：「评论只在云端保存，所有项目成员都能看到。」
- **提醒**：右上角（头像左边）一个铃铛，有未读时红点 + 数字。点开下拉列表：
  「张三 在「用户登录」里提到了你：前 40 个字……」+ 时间。点一条 → 切到那个项目、打开那个接口、展开评论面板并滚到那条，同时标为已读。
  列表顶部「全部标为已读」。最多显示最近 50 条。
- 页面每 60 秒查一次未读数（切到后台时暂停，回来时立刻查一次）。
- 未登录（本机空间）时：评论按钮和铃铛都不显示。接口还没同步到云端（刚新建的）时，评论面板显示「这个接口还没同步到云端，同步后才能评论」。
- viewer 也能评论（只读成员正是最需要提问的人）。

### 数据（已建好：v13）

```
comments(id, project_id, api_id, user_id, body, mentions, created_at, updated_at, deleted_at)
  mentions   被 @ 的用户 id 数组（JSON）
  deleted_at 非空 = 已删除（列表里保留楼层）
notifications(id, user_id, project_id, api_id, comment_id, actor_id, created_at, read_at)
  每 @ 一个人一行；read_at 为空 = 未读
```

### 接口（只在云端；网关转给云端 —— `cloudOnlyPath` 加上下面这些路径）

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /apis/:id/comments` | viewer | 这个接口的评论（含已删除的楼层，已删除的不返回 body） |
| `POST /apis/:id/comments` | viewer | `{ body, mentions: [userId] }`。body 1–2000 字。mentions 只保留**项目成员**（管理员也算），自己 @ 自己不发提醒。返回新评论 |
| `PUT /comments/:id` | 作者本人 | 改内容；新 @ 的人发提醒，原来 @ 过的不重复发 |
| `DELETE /comments/:id` | 作者本人或管理员 | 标记删除（`deleted_at`），对应的未读提醒一起标已读 |
| `GET /projects/:pid/comment-counts` | viewer | `{ counts: { apiId: n } }`，目录树如果要显示评论数用得上（可选，先不显示也行） |
| `GET /notifications?limit=50` | 登录 | 当前用户的提醒，倒序；每条带 actorName、projectId、projectName、apiId、apiName、commentId、摘要、createdAt、read |
| `GET /notifications/unread-count` | 登录 | `{ count }` |
| `POST /notifications/read` | 登录 | `{ ids?: [...], all?: true }` |

- `:id` 是接口 id：评论接口要先确认这个接口在云端库里存在、并且属于当前用户能看的项目（用现成的 `guard(... byParam('api'))`）。
  不存在就 404 + `code: 'API_NOT_SYNCED'`，前端据此显示「还没同步到云端」。
- 所有返回里的名字只给显示名（`displayName`，没有就用户名）。
- 评论内容原样存，**前端显示时当纯文本**（不能 `v-html`），网址识别成链接时自己拆开拼节点。
- 提醒里的摘要：评论正文去掉换行，取前 40 个字。

**几个实现上的决定（审阅时重点看这几处）：**

1. **接口没同步到云端 → 404 + `code: 'API_NOT_SYNCED'`**，没用现成的 `byParam('api')`
   ——它的 404 没有 code，前端分不出「接口不存在」和「还没同步」。两种情况的处理一样
   （先同步），分成两种只会让人困惑。**不是项目成员**时也是同一个 404（和 guard 一个口径，
   不能让人拿 id 试出「这个接口存在」）。
2. **`PUT` 只有作者本人**（管理员也不行）：把别人的话改掉比删掉更糟 —— 删了至少还看得见
   「已删除」。`DELETE` 是作者本人或**系统管理员**（`user.role === 'admin'`）。
   计划里写的是「管理员」，我按系统管理员理解的；**项目 owner 目前删不了别人的评论**，
   要放开的话是一行的事（`access.atLeast(roleOf(...), 'owner')`）。
3. **`mentions` 在 PUT 时是整份替换**：不传就把原来的清掉。客户端每次都要带上
   （它本来就从正文里认一遍）。自测里专门有一条盯着这个契约。
4. **`@` 只保留项目成员**（管理员也算，他不在成员表里），自己 @ 自己既不进 mentions
   也不发提醒。**改评论只给「新 @ 的人」发提醒**：被去掉又 @ 回来的算新 @，会再发一条。
5. **摘要**：正文压掉空白、取前 40 个字（超了加省略号）。**评论被删之后摘要给空串** ——
   不然提醒列表里还挂着被删掉的正文。
6. **正文一律当纯文本**：`utils/comment.js` 只把 `http(s)://` 网址拆出来给组件拼 `<a>`，
   全程没有 `v-html`（`grep v-html web/src` 只在注释里）。
7. 评论数角标用 `comment-counts` **一个项目拉一次**，缓存在模块级 Map 里 ——
   请求标签页是按 activeKey 卸载重建的，不缓存的话切一次标签页就白拉一次。

**没做 / 想不清楚的：**

**接口 / 数据形状：**

- 存 `projects.extra.headers` / `folders.extra.headers`，行形状和接口请求头**完全一样**
  （`{ key, value, type, required, desc, enabled }`，由 `dto.toRows` 归一），所以前端两张表能直接拼。
- `PUT /projects/:pid` 和 `PUT /folders/:id` 的 body 多认一个 `headers`（数组；空数组 = 清掉）。

**合并规则（`lib/common-headers.js`，四个调用方共用这一份）：**

1. 顺序「项目 → 外层目录 → 内层目录 → 接口」，**越靠近接口越优先**；
2. **同名不区分大小写**（`X-Token` 与 `x-token` 是同一个）；
3. **停用的行照样算「这一层表过态」**：内层把某个头停用，就是把外层那个覆盖成「不发」。
   先按优先级定出每个名字的赢家，最后才把停用的丢掉 —— 否则用户在内层「关掉」一个头会发现它还在发。
4. 合并发生在**变量替换之前**（只是把行拼进 `spec.params.headers`），所以继承来的值里能写 `{{变量}}`。

**几个实现上的决定（审阅时重点看这几处）：**

1. **`Authorization` 谁赢**：公共请求头里写了 `Authorization` 时，它和「接口自己手写的」走同一条路 ——
   执行器先放用户的行、鉴权头用 `addHeaderIfAbsent` 补空缺，所以**公共头赢**。
   计划里说「先看现在是谁覆盖谁，保持一样」，这就是现在接口手写 `Authorization` 的行为，两边一致（自测有专门一条）。
2. **`requesting` 快照挪到合并之前**：历史里那份「用户当初怎么写的请求」不含继承结果，
   重放时按当时的项目 / 目录重新合并一遍；不这么做的话，之后在目录上改了公共头，历史重放还是老值。
   历史**实际发出的请求头**（`result.request.headers`）里当然是合并后的（自测有断言）。
3. **`/send`、`/send/stream`、`/send/curl` 共用 `prepare`**，所以只改了一处；WebSocket 是另一个
   `prepareSession`，单独改了那几行（只叠项目那一层）。
4. **导出 JSON 用 `x-apiloop-common-headers`**（和第四轮 `x-apiloop-skipped` 一个路子）：
   集合格式里没有「项目 / 目录级请求头」，用别人的字段名会和 Postman 自己的字段打架。
   折进 `extra` 也能往返，但项目那一层的 `extra` 是 `{ root, info }` 分层的、摊不到顶层，得单独处理。
5. **DTO 里的 `headersOf` 和 `common-headers.headersOf` 是两份 4 行的小函数**：`common-headers.js`
   要用 `dto.toRows`，`dto` 再回头 require 它就是循环引用（`module.exports = {}` 被后赋的新对象顶掉，
   拿到空壳）。读的是同一列、规则一致，就这么留着了。
