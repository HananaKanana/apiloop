## 1. YApi / Apifox 导入（session2）

### 要解决的问题

国内团队很多是从 YApi 或 Apifox 迁过来的。现在只能先在那边导出 OpenAPI 再导进来，目录分组、字段说明、Mock、示例会丢一大半。

### 用户看到的样子

- 导入弹窗（`ImportDialog.vue`）的格式列表里加两项：「YApi（JSON 导出文件）」「Apifox（`.apifox.json` 导出文件）」。
  选文件或粘贴，**自动识别**也要认得这两种（用户经常不知道自己拿到的是什么格式）。
- 和现有导入一样先预览：会导入多少个目录、多少个接口、几个环境；有哪些东西没法带过来（列出来，比如「3 个接口用了 YApi 的高级 Mock 脚本，没有导入」）。
- 导入到新项目或已有项目（和现有 JSON 导入一致）。

### 要带过来的东西

**YApi**（项目「数据导出 → json」，格式是分类数组：`[{ name, desc, list: [接口…] }]`）：

- 分类 → 目录（名字、说明）；
- 接口：`title` → 名字、`method`、`path`（YApi 的 `{id}` / `:id` 路径参数都认）、`desc` / `markdown` → 说明、`status`（`done` → 已完成、`undone` → 开发中）；
- `req_query` / `req_headers` / `req_params` → 参数表（带说明、是否必填）；
- `req_body_type`：`json`（`req_body_other` 是 JSON Schema 字符串，用里面的示例或按 Schema 生成一份请求体）、`form`（`req_body_form`）、`raw`；
- `res_body`（多半是 JSON Schema 字符串）→ 生成一条示例当 Mock 返回，字段的 `description` → 响应字段说明（第六轮那个功能）；
- `tag` → 忽略或放进说明。

**Apifox**（「导出 → Apifox 格式」，一个大 JSON：`apiCollection`（目录树 + 接口）、`environments`、`schemaCollection`（数据模型）、`apiTestCaseCollection` 等）：

- 目录树 → 目录；接口的方法、地址、名字、说明、状态、参数（query / path / header / cookie）、请求体（JSON / form / raw，引用了数据模型的要按 `schemaCollection` 展开）；
- 响应（`responses` 里的 Schema + `responseExamples`）→ 示例（第一个 2xx 设成 Mock 返回）+ 响应字段说明；
- 环境 → 环境（变量、`baseUrl` 变成 `host` 之类的变量，接口地址里用 `{{host}}`）；
- 前后置操作里的**自定义脚本** → 尽量转成我们的「请求前 / 响应后」脚本（Apifox 的脚本 API 和我们的 `pm.*` 基本一致）；别的类型（数据库操作、提取变量、断言）**能对上我们的可视化断言 / 提取的就转，对不上的列进「没有导入」**；
- 测试用例、测试场景：这一轮**不导**，列进「没有导入」。

两种格式的细节**以真实的导出文件为准**：找官方文档或开源仓库里的样例文件（YApi 是开源的，`server/controllers/` 和导出插件里能看到导出格式），
在 scratchpad 里造几份有代表性的样例跑通。字段对不上、不认识的，**宁可跳过并列出来，也不要导入一个错的接口**。

### 怎么做

- 解析写在 `lib/importers/` 下（或者 `lib/importers.js` 旁边新建 `lib/import-yapi.js`、`lib/import-apifox.js`），输出**和现有 JSON 导入一样的中间形状**，
  后面落库走现有导入的那一套（看 `lib/api/postman.js` 的 `/import/json` 和 `lib/api/openapi.js` 是怎么落库的），不要另写一套落库。
- JSON Schema → 示例 / 字段说明：现有的 OpenAPI 导入里有 `schemaToMock`、`bodyFieldsFromSchema`（`lib/importers.js`），能复用就复用。
- 文件可能很大（几十 MB 的 Apifox 导出很常见）：看现有导入的请求体大小上限够不够，不够告诉主会话。

## 2. 导出文档（session2，第 1 节之后）

### 要解决的问题

接口文档要给不用 apiloop 的人看（外包、甲方、测试），现在只能发在线分享链接或者导出 OpenAPI —— 对方要的往往是一个能打开、能打印、能放进项目资料里的文件。

### 用户看到的样子

- 项目名下拉「导出文档…」、目录右键「导出文档…」打开一个小弹窗：
  - 格式：**Markdown**（`.md`）/ **HTML**（单个文件，样式内联、不引外部资源、左边目录可点跳转）/ **Word**（`.docx`）；
  - 范围：整个项目 / 这个目录（从目录右键打开时默认这个目录）；
  - 选项：「包含示例响应」（默认勾）、「包含 Mock 地址」（默认不勾 —— 文件发出去以后 Mock 地址可能会变）、「只导出已完成的接口」（默认不勾）；
  - 一行灰字：「密码、token 这类值会自动遮住；环境变量的值、脚本不会导出。」
- 点「导出」直接下载文件，文件名 `项目名-接口文档-20261004.md` 这种。

### 文档内容

和分享文档页（第三轮第 4 节）**看到的内容一致**：按目录分章节，每个接口一节 —— 名字、方法 + 地址、状态和负责人、说明、
路径 / 查询 / 请求头参数表（名字、示例值、是否必填、说明）、请求体（JSON 原样、表单列成表）、示例响应、响应字段说明表。
开头一页：项目名、说明、导出时间、接口数量、目录（Word 用它自带的目录域，Markdown 用列表链接）。

**打码规则和分享文档完全一样**：直接复用 `lib/api/shares.js` 里的 `maskJsonText` / `maskUrlQuery` / `isSensitiveHeaderName` 这些（已经导出了），
不要另写一份 —— 两边各写一份迟早一个遮了一个没遮。

### 怎么做

- 服务端生成：`GET /projects/:pid/export/doc?format=md|html|docx&folderId=&examples=1&mock=0&doneOnly=0`（viewer），直接回文件（带 `Content-Disposition`）。
  先把「要导出的东西」整理成一个中间结构（章节 → 接口 → 各块），三种格式各写一个渲染函数，别三份各自去读库。
- 看分享文档页现在怎么拿数据的（`lib/api/shares.js` 的公开接口那一段），能抽出来共用就抽。
- Word 用 `docx`（已装）：标题分级、表格、代码块用等宽字体加浅灰底。
- HTML 里所有值都要转义（接口说明、示例响应都是用户 / 对方写的内容）。
- 客户端里也要能用：这是读本机库就能做的事，网关上照常挂，不用转云端。

## 3. 数据库操作（session1）

### 要解决的问题

测接口时经常要「先往库里造一条测试数据」「调完接口去库里看数据有没有写进去」「拿库里刚生成的验证码填进下一个请求」。现在只能开另一个数据库工具来回切。

### 用户看到的样子

**项目设置**加一块「数据库连接」：

- 列表：名字、类型（MySQL / PostgreSQL / Redis）、地址；新增 / 编辑 / 删除 / 「测试连接」。
- 每个连接的字段：名字、类型、主机、端口、用户名、密码、数据库名（Redis 是库号）。
- **每个字段都可以写 `{{变量}}`**，发送时按当前环境替换 —— 开发环境、测试环境连的是不同的库，就用环境变量区分；
  密码建议写成 `{{dbPassword}}` 并在环境里设成保密变量（设置页里写一句提示，填了明文密码时输入框下面黄字提醒「密码会同步给项目里所有人，建议用保密变量」）。

**接口的「断言」页签旁边**（或者在里面分一块）加「数据库操作」：

- 两组：「请求前」「响应后」，每组一张表，一行一个操作：启用 · 连接（下拉）· 语句（SQL 或 Redis 命令，多行输入框，可以写 `{{变量}}`）· 提取 · 删除。
- 「提取」：把结果里的值存成变量，写法和可视化提取一样（存到环境 / 项目、变量名、取值路径），路径基于结果：
  SQL 的结果是行数组，`[0].code` 就是第一行的 `code` 列；Redis 的结果是命令的返回值（字符串 / 数组），路径空着就是整个返回值。
- 执行顺序：**请求前的数据库操作 → 请求前脚本 → 发请求 → 响应后的数据库操作 → 可视化断言和提取 → 响应后脚本**。
  这样响应后的断言能用到刚从库里查出来的变量（比如断言 `code` 等于 `{{dbCode}}`）。
- 结果显示在响应面板的「控制台」里：每个操作一行（连接名、语句、耗时、返回几行 / 影响几行，SELECT 的前 5 行），失败的标红。
- 操作失败：请求前的失败了就**不发请求**（和请求前脚本出错一样），结果里写清楚是哪一条、为什么；响应后的失败了记一条没通过的测试结果「数据库操作：xxx」。

**只在客户端里执行**：网页版（云端发送）遇到数据库操作就跳过，控制台里给一句「数据库操作只在客户端里执行，这次跳过了」。
测试集运行、批量运行自然也会带上（它们走的是同一个 `send-core`），压测不跑。

### 数据

- 连接：`projects.extra.databases = [{ id, name, type: 'mysql' | 'postgres' | 'redis', host, port, user, password, database }]`。项目 DTO 顶层多给 `databases`，`PUT /projects/:pid` 接受，合并进 `extra`。
- 操作：`apis.extra.dbOps = [{ id, enabled, phase: 'pre' | 'post', connectionId, statement, extracts: [{ id, enabled, path, scope, name }] }]`。接口 DTO 顶层多给 `dbOps`，保存接口时接受；
  发送的请求体里也能带（界面上没保存的修改也要生效，和 `assertions` 一个口径）。
- **复制项目、跨项目复制接口**（第六轮的 `lib/api/copy.js`）：复制项目时连接跟着走；只复制接口到别的项目时，`connectionId` 在目标项目里找不到，运行时提示「连接不存在」就行。
- 导出 JSON / 分享文档 / 导出 OpenAPI / 导出文档：**不带数据库连接的密码**（JSON 导出时 `password` 置空）。

### 怎么做

- 执行写在新文件 `lib/db-ops.js`：`run(op, connection, variables, options) → Promise<{ ok, rows?, affected?, value?, timeMs, error? }>`。
  驱动用到时再 `require`：`mysql2/promise`、`pg`、`ioredis`。每次执行开一个连接、执行完关掉（不做连接池，简单可靠；测试集一次跑几十个也就几十次连接）。
  超时 10 秒；SELECT 最多取 100 行；Redis 命令按空格拆参数（支持双引号包起来的带空格参数）。
- `prepare`（`lib/api/send.js` 的 `createPreparer`）把这个接口用到的操作和连接配置（**还没替换变量的原文**）带进 `prepared`；
  执行时在 `send-core.run` 里按上面的顺序调用。变量替换用发送用的那张合并表（`mergeScopes` + 请求前脚本改过的值）。
- 「只在客户端执行」怎么判断：`prepare` 拿得到 `ctx.localSend`，把它放进 `prepared` 里（比如 `prepared.dbAllowed`），`send-core` 看它。
- 「测试连接」：`POST /projects/:pid/databases/test`（editor），请求体是一个连接配置 + `environmentId`（用来替换变量），只在客户端里挂，执行 `SELECT 1` / `PING`。
- 提取的结果并进脚本状态（`state.variables.environment / project`），和可视化提取完全一样 —— 这样写回、测试集里的内存变量都自动生效，不用另写。
- 写历史时：控制台里那几行照常存；语句里替换进去的保密值要打码（`prepared.secretValues`）。

## 4. Socket.IO 调试（session1，第 3 节之后）

### 要解决的问题

很多推送服务（聊天、通知、行情）用的是 Socket.IO，它在 WebSocket 之上有自己的协议（握手、事件名、确认），现在的 WebSocket 标签页连不上，或者连上了只看到一堆 `42["message",…]`。

### 用户看到的样子

- 新建接口时方法里多一个「Socket.IO」（和现在的 WebSocket 并列），打开是 Socket.IO 标签页，和 WebSocket 标签页长得差不多：
  - 地址（`http://host:port`）+ 路径（默认 `/socket.io`）+ 命名空间（默认 `/`）；
  - 连接参数：请求头、查询参数、`auth`（JSON）；传输方式「先长轮询再升级 / 只用 WebSocket」；
  - 「监听的事件」：一组事件名（默认监听全部，用 `onAny`）；
  - 发送区：事件名 + 参数（JSON，可以多个参数）+「等待确认（ack）」勾选，发了之后确认的返回值显示在消息列表里；
  - 消息列表：时间、方向（发出 / 收到）、事件名、内容（JSON 折叠显示）；连接、断开、重连、出错也作为一行显示。
- 地址、参数、请求头里可以用 `{{变量}}`，按当前环境替换。
- 保存的接口里记下「常用发送」（事件名 + 参数），下次打开一点就发。

### 怎么做

- 先读懂现在 WebSocket 是怎么做的：`lib/ws-sessions.js`（会话在服务端，浏览器和它之间怎么传消息）、`lib/api/ws.js`、`web/src/components/ws/`、`web/src/stores/ws.js`，
  以及方法 `WS` 在各处是怎么被特殊处理的（`lib/routes-store.js` 的 `METHODS`、`lib/api/send.js`、`lib/mock-runtime.js`、`lib/openapi-export.js`、`lib/api/postman.js`、
  前端 `utils/tree.js`、`stores/tabs.js`、`SuiteStepsPane.vue` 等，`grep "'WS'"` 能找全）。新方法起名 `SIO`，**每一处判断 `WS` 的地方都要想一下 `SIO` 该怎么办**
  （发送拦掉、测试集不能加、Mock 不处理、导出 OpenAPI 跳过、目录树图标……），交接里列出来改了哪些。
- 服务端会话照 WebSocket 那一套做，客户端用 `socket.io-client`（已装，v4，能连 v3 / v4 的服务端；v2 的老服务端连不上时给一句能看懂的提示）。
- 只在客户端里能连（和 WebSocket 会话同一个开关：云端 `SERVER_SEND=0` 时不让建会话）。
- Socket.IO 的 Mock 回放这一轮不做。
