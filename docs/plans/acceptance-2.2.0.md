# 2.2.0 验收清单

第十一到十五轮（gRPC 调试、gRPC 补全、Mock 录制、MQTT 调试、项目备份与恢复、国际化）。
主会话审阅时已经用真实服务实测过后端（真实 gRPC 服务、真实 MQTT broker、临时云端 / 网关），下面是**界面和整体流程**要你确认的部分。

准备：先升级云端（`git pull && ./deploy.sh up --cn`），再装新客户端。

## 1. gRPC 调试（客户端里）

- [ ] 目录树「＋ → gRPC」新建；方法下拉里也有 gRPC；目录树上的徽标是 gRPC（橙色）。
- [ ] 「服务定义」页签导入 .proto（多选两个互相 import 的文件）→ 服务 / 方法下拉出现方法；故意写错一行，红字提示带文件名和行号。
- [ ] 「生成示例」填进消息框 → 调用 → 响应区有状态（OK 绿色）、耗时、消息、Metadata、Trailers。
- [ ] 服务端流方法：消息页签是带时间的列表；调用中按钮变「取消」，能取消。
- [ ] 切到「服务端反射」→「从服务获取」（服务端要开反射）→ 方法列表出现；关掉接口再打开，不连服务端也能看到方法。没开反射的服务给出「服务端没开反射，请导入 proto 文件」。
- [ ] 客户端流 / 双向流：「连接」→ 发几条 →「结束发送」→ 双向消息列表（发出 / 收到能区分）和最后的状态。
- [ ] 「断言」页签加：状态码等于 0、某个 JSON 字段等于某值；调用后「测试结果」页签显示通过 / 失败；提取一个字段到环境变量，去环境里看值。
- [ ] 「复制为 grpcurl」内容对。
- [ ] 地址写错 / 端口不通，提示「连不上服务，检查地址、端口、TLS 开关」。

## 2. MQTT 调试（客户端里）

- [ ] 目录树「＋ → MQTT」新建；填 broker、用户名密码 → 连接，状态变「已连接」。
- [ ] 订阅 `t/+`，用别的 MQTT 客户端往 `t/a` 发消息，列表里出现；二进制消息显示「二进制 N 字节」，能看 base64。
- [ ] 发布 QoS 1 / 2、retain；「存为常用」再从下拉里选一次发。
- [ ] 密码写错 → 「用户名或密码不对，或者这个用户没有连接权限」；地址写错 → 「连不上 broker，检查地址和端口」。
- [ ] 往带 `#` 的主题发布被拒绝。

## 3. Mock 录制（客户端里）

- [ ] 顶栏录制按钮 → 填目标地址（可以从环境变量里选）→ 开始，显示代理地址，能复制。
- [ ] 把一个前端项目的接口地址改成代理地址，操作页面，列表每秒刷新出记录；带参数的路径能对上已有接口。
- [ ] 勾选几条保存：同一个接口录到的多条只建一个接口、加多个示例；保存后列表里「对应接口」立刻更新。
- [ ] 停掉真实后端，打新建接口的 Mock 地址，返回的是录到的内容。
- [ ] 换到另一个项目：顶栏是灰点，提示正在录哪个项目，不能在这里停。

## 4. 项目备份与恢复

- [ ] 项目设置 →「备份」→ 下载备份（文件名带项目名和时间）。
- [ ] 项目下拉 →「从备份恢复成新项目」选这个文件 → 预览 → 恢复 → 切到新项目，目录、接口、环境、测试集都在，测试集能跑、前置接口能用。
- [ ] 「从备份文件恢复（覆盖当前项目）」：要输入项目名确认；覆盖前浏览器先下载一份当前备份；完成后回收站里有原来的目录、接口、环境。
- [ ] 系统设置（管理员）→ 自动备份：打开、设时间和保留天数，保存后刷新还在。第二天「备份」页签里有云端备份，能下载 / 恢复成新项目。
- [ ] 随便拿一个别的 JSON 文件去恢复，提示「这不是 apiloop 的备份文件」。
