### 接口约定

### 数据（存在接口上，会同步）
- `api.method = 'GRPC'`（加进 `lib/routes-store.js` 的 `METHODS`）。
- `api.url`：`host:port`，可以带 `{{变量}}`；写成 `grpcs://host:port` 等于开 TLS，`grpc://host:port` 等于不开。
- `api.extra.grpc`（`dto` 里照 `toApiSio` 做一个 `toApiGrpc`，读写都过它）：
```json
{
  "protoFiles": [{ "name": "user.proto", "content": "syntax = \"proto3\"; ..." }],
  "service": "demo.UserService",
  "method": "GetUser",
  "tls": false,
  "metadata": [{ "key": "authorization", "value": "Bearer {{token}}", "enabled": true }],
  "message": "{\n  \"id\": 1\n}",
  "deadlineMs": 10000,
  "savedMessages": [{ "name": "查 1 号用户", "message": "{\"id\":1}" }]
}
```
  `protoFiles` 可以有多个，互相 `import` 时按 `name` 找；`google/protobuf/*.proto`（timestamp、empty、struct、wrappers…）不用用户提供也要能 import。

### `POST /__admin/api/projects/:pid/grpc/parse`（viewer 即可）
请求 `{ "protoFiles": [...] }`，成功：
```json
{ "services": [ { "name": "demo.UserService", "methods": [
  { "name": "GetUser", "path": "/demo.UserService/GetUser", "requestType": "demo.GetUserRequest", "responseType": "demo.User",
    "clientStreaming": false, "serverStreaming": false, "example": "{\n  \"id\": 0\n}" } ] } ] }
```
`example` 是按请求类型生成的 JSON 示例文本（嵌套消息展开、repeated 放一项、枚举取第一个值、字符串 ""、数字 0、bool false，循环引用要停住）。
解析失败返回 400，`error` 是看得懂的中文，带文件名和行号，比如 `user.proto 第 12 行：…`；import 了没提供的文件要说缺哪个文件。

### `POST /__admin/api/projects/:pid/grpc/call`（权限和 `/send` 一样）
请求：
```json
{ "apiId": "可选，有就用它所在目录的变量层级", "environmentId": "可选",
  "url": "...", "tls": false, "protoFiles": [...], "service": "...", "method": "...",
  "metadata": [...], "message": "JSON 文本", "deadlineMs": 10000 }
```
响应是 NDJSON（用 `lib/api/ndjson.js`），一行一个事件：
```
{"type":"start","target":"127.0.0.1:50051","tls":false,"missing":["token"],"note":"系统代理不作用于 gRPC，本次为直连"}
{"type":"metadata","metadata":{"content-type":["application/grpc"]}}
{"type":"message","data":{...},"at":1759650000000}          一元调用一条，服务端流每收到一条一行
{"type":"end","status":{"code":0,"name":"OK","details":""},"trailers":{...},"durationMs":12}
{"type":"error","error":"中文说明"}                          调用还没发出去就失败（proto 解析不了、找不到方法、消息不是合法 JSON…）
```
- 地址、metadata 的值、消息文本里的 `{{变量}}` 按和 `/send` 同一套变量层级替换（项目 → 目录 → 环境、保密变量、`{{$guid}}` 这类动态变量都要能用），没值的列在 `start.missing`。
- 失败的状态在 `end.status` 里，`details` 后面补一句中文提示：UNAVAILABLE「连不上服务，检查地址、端口、TLS 开关」、DEADLINE_EXCEEDED「超时了」、UNIMPLEMENTED「服务端没有这个方法」、UNAUTHENTICATED、PERMISSION_DENIED、INVALID_ARGUMENT 等常见的都给一句。
- 浏览器断开连接（取消）时要 `call.cancel()`，不留挂着的调用。
- 客户端流、双向流这一版不做：返回一行 `error`「这一版只支持一元调用和服务端流」。
- int64 一律按字符串收发（proto-loader 的 `longs: String`），枚举按名字（`enums: String`），`defaults: true`，`keepCase: true`。

### 其他地方对 GRPC 的处理
- `/send` 收到 GRPC 接口：和 SIO 一样拦掉，提示「gRPC 接口请在 gRPC 标签页里调用」。
- 导出 OpenAPI、导出集合 JSON：和 SIO 一样跳过并在说明里列出来。
- 测试集、批量运行：后端也要拒绝 GRPC 步骤（前端 T3 会在入口拦，这里是兜底）。
- 导出文档（`lib/export-doc.js`）：GRPC 接口写出地址、服务、方法、请求消息示例，不要报错或漏掉。
- 回收站、跨项目复制 / 移动、复制接口：`extra.grpc` 要跟着走（核对一下现有逻辑是不是整个 extra 都带上了）。

### 要做的事
1. `lib/grpc.js`（新）：proto 解析（字符串 → 服务清单 + 示例）、发起调用（一元、服务端流）、状态码中文提示。proto-loader 读的是文件：可以写到临时目录读完删掉，或者用 protobufjs 直接从字符串解析，自己选，但要能处理多文件 import 和 google 的公共类型。

## T2 Mock 录制 · 后端（session2）

### 背景
前端 / App 开发联调时，后端的接口经常还没写进 apiloop，或者后端临时挂了。Mock 录制：客户端开一个本机代理，前端把接口地址改成代理地址，
请求原样转发到真实后端，**同时把请求和响应记下来**；用户勾选后一键存成接口的示例（当 Mock 返回），没有的接口顺手建出来。之后后端挂了就切到 Mock 继续开发。
本任务做后端（代理、记录、保存），T4 做前端界面（T2 通过后才派）。

主会话已经做好的：`lib/api/record.js` 是空壳，已经在 `lib/admin.js` 挂上（只在本机网关 `ctx.localSend` 时挂路由）；
`lib/mock-runtime.js` 导出了 `sortBySpecificity(routes)`（Mock 注册路由的先后：固定路径段优先于 `:参数`），给录到的请求找对应接口时用同一个顺序。

### 接口约定（都在 `/__admin/api` 下，只有本机网关有）

### `POST /projects/:pid/record/start`（editor）
请求：
```json
{ "target": "http://localhost:8080/api", "environmentId": "可选，target 里的 {{变量}} 按它替换",
  "port": 0, "lan": false, "pathPrefix": "", "skipStatic": true }
```
- `target` 必须是 http(s)，可以带路径前缀（转发时拼在前面）。
- `port` 为 0 时从 47400 起往上找第一个空闲端口；指定了但被占用返回 400「端口 47400 被占用」。
- `lan` 为假只监听 `127.0.0.1`；为真监听 `0.0.0.0`（手机、别的电脑能连）。
- 成功：
```json
{ "recording": { "projectId": "...", "target": "http://localhost:8080/api", "port": 47400, "lan": false,
  "localUrl": "http://127.0.0.1:47400", "lanUrls": ["http://192.168.1.5:47400"], "pathPrefix": "", "skipStatic": true,
  "startedAt": 1759650000000, "count": 0 } }
```
- 已经在录（不管是不是这个项目）返回 409，`error` 说明正在录哪个项目、先停掉。整个网关同时只有一个录制。

### `POST /projects/:pid/record/stop`（editor）
停掉代理（关监听、断掉还连着的 socket）。**录到的记录保留**，方便停了再挑着保存。返回 `{ "recording": null }`。

### `GET /projects/:pid/record?after=<seq>`（viewer）
```json
{ "recording": { ... } , "lastSeq": 42, "entries": [ {
  "seq": 42, "id": "e_xxx", "at": 1759650000000, "method": "POST", "path": "/orders/1001", "query": "a=1",
  "status": 200, "durationMs": 35, "error": null,
  "request":  { "headers": { "content-type": "application/json" }, "body": "{...}", "bodyTruncated": false, "contentType": "application/json" },
  "response": { "headers": { ... }, "body": "{...}", "bodyTruncated": false, "contentType": "application/json", "binary": false },
  "match": { "apiId": "...", "apiName": "订单详情", "method": "GET", "path": "/orders/:orderNo" } } ] }
```
- `recording` 没在录时是 null；`entries` 只回 `seq > after` 的；`path` 不带 query；`match` 没对上是 null。
- 连不上目标时也记一条，`status` 为 0、`error` 写中文（「连不上 http://localhost:8080：ECONNREFUSED」），并给客户端回 502 和同样的中文。
- 最多留最近 500 条；请求体、响应体各最多记 1 MB（超出截断、`bodyTruncated: true`）；图片等二进制 `binary: true`、`body` 为空。

### `DELETE /projects/:pid/record/entries`（editor）
清空记录。

### `POST /projects/:pid/record/save`（editor）
```json
{ "items": [ { "entryId": "e_xxx", "apiId": "存到已有接口时给", "folderId": "新建接口放哪个目录，可为 null（根目录）", "name": "可选" } ],
  "paramize": true, "setMock": true, "environmentId": "可选" }
```
- 有 `apiId`：给这个接口加一个示例。示例名默认「录制 200 · 10-05 10:30」；状态码、`content-type` 等响应头（去掉 `set-cookie`、`content-length`、`content-encoding`、`transfer-encoding`、`date`、`connection`）、响应体；`responseType` 按 content-type 定（json / html / text）。`setMock` 为真时把接口的 Mock 返回指向这个新示例。
- 没 `apiId`：新建接口再加示例。方法、地址：`paramize` 为真时路径里纯数字、UUID、长串十六进制那种段换成 `:id`（同一路径多个就 `:id`、`:id2`…）；地址前缀如果 `environmentId` 对应环境（或项目变量）里有变量的值正好等于 target 的 origin（或 origin + 路径前缀），就写成 `{{那个变量}}`，否则写 target 原样；query 变成接口的 Params；请求体是 JSON 就存成接口的 raw JSON Body，请求的 `content-type` 带上。
- 二进制、流式（SSE）的记录不能存：这一条在结果里给 `error`，其他照存。
- 用和「把响应存成示例」（`lib/api/tree.js` 的 `POST /apis/:id/examples`）同一套 repo 函数；写库包在 `handle.transaction(fn, { projectId })` 里（这样同步才会记下改动）。
- 返回 `{ "created": { "apis": 1, "examples": 3 }, "results": [ { "entryId": "...", "apiId": "...", "exampleId": "...", "createdApi": true, "error": null } ] }`。

### 代理本身怎么做（`lib/record-proxy.js`，新）
- 单独起一个 `http.createServer`（**不走网关的安全闸门**，因为前端页面、手机 App 都要能连），只做一件事：把请求转发到 target，再把响应原样回给客户端。
- 转发：方法、路径（target 的路径前缀 + 请求路径）、query、请求体原样；`Host` 换成 target 的；去掉 hop-by-hop 头。响应头原样回，但：
  - 请求带 `Origin` 时，回 `Access-Control-Allow-Origin: <那个 Origin>`、`Access-Control-Allow-Credentials: true`、`Access-Control-Expose-Headers: *`（覆盖目标自己的 CORS 头）；
    `OPTIONS` 且带 `Access-Control-Request-Method` 的预检**在代理这里直接回 204**（允许方法、请求头按请求回显），不转发、不记录；
  - `Set-Cookie` 去掉 `Domain=`（这样 cookie 落在代理地址上，前端登录态能用）。
- 响应是 gzip / br / deflate 压缩的：给客户端回原始字节，记录时解压。
- `text/event-stream` 原样流式转发、不缓冲，记一条但 body 写「流式响应，未录制内容」。WebSocket 升级请求（`upgrade` 事件）用 net 管道原样转发，不记录。
- `skipStatic` 为真时不记（照样转发）：路径扩展名是 .js .css .map .png .jpg .jpeg .gif .svg .ico .woff .woff2 .ttf .html，或响应 content-type 是 html / javascript / css / image / font。`pathPrefix` 非空时只记这个前缀下的。
- 找对应接口：项目里的接口（排除 WS / SIO / GRPC），方法相同（或接口方法是 ALL）且路径匹配接口的 Mock 路径（`:参数` 匹配一段），按 `sortBySpecificity` 的顺序取第一个；请求路径先按客户端发来的路径比，比不上再试「去掉 target 路径前缀 / 加上 target 路径前缀」。接口的路径从 `lib/routes-store.js` 读到的 routes 里拿（看 `readRoutes` 怎么生成 `path`）。
- 停止时关掉 server、`destroy` 所有活着的 socket。

### 要做的事
1. `lib/record-proxy.js`：代理 + 记录 + 匹配。
2. `lib/api/record.js`：上面五个接口（保存逻辑可以放 `lib/record-proxy.js` 或另一个新文件，但要在允许路径内）。
3. 自测：临时目录里用 node 起一个「真实后端」（JSON 接口、带参数的路径、gzip 响应、Set-Cookie、一个 SSE、一个图片），起临时网关、开始录制，用 `fetch` 带 `Origin` 头打代理（含 OPTIONS 预检），
   把 `GET /record` 拿到的每一条打出来看；再调 `save`：一条存到已有接口、一条新建接口（核对 `:id` 参数化、`{{host}}` 前缀、Params、Body），然后开 Mock 访问一次新建的接口，确认返回的就是录到的内容。

### 不要做的事
- 不要改允许路径以外的文件（`lib/gateway/*`、`lib/mock-runtime.js`、`lib/api/tree.js` 都不改；前端是 T4 的事）。
- 不做 HTTPS 中间人（不装证书、不代理 https 的 CONNECT），target 是 https 可以（代理到 https 的后端），但代理自己只开 http。
- 录到的记录不落库、不同步（只在内存里，网关重启就没了）。

- 打开 GRPC 接口是 gRPC 标签页：

    - **Proto 文件**：文件列表（导入 .proto，可多选；也能「新建」后粘贴内容），点开能看和改内容，可以删除；任何改动后自动重新解析，解析错误红字显示在列表上方。

  - 响应区：状态（OK 绿色，其他红色，显示码名 + details + T1 给的中文提示）、耗时；页签「消息」（一元调用显示一个只读 JSON；服务端流显示列表，每条带收到的时间、可以展开）、「Metadata」、「Trailers」。
  - `start.missing` 有值时，像发送 HTTP 请求那样提示哪些变量没有值。
  - 「复制为 grpcurl 命令」：按当前地址、TLS、metadata、消息、服务 / 方法生成（`grpcurl -plaintext -d '{...}' -H 'k: v' host:port pkg.Service/Method`，带 `-import-path . -proto user.proto` 的写法提醒用户 proto 文件要在本地）。
- 网页版（`gateway.isGateway` 为 false）：能看、能编辑、能保存；「调用」灰掉，提示「网页版不能调用 gRPC，请在客户端里使用」；`/grpc/parse` 在网页版没有这个接口，服务 / 方法下拉就只显示已保存的那一个，并提示「在客户端里打开才能解析 proto」。
- 测试集「添加步骤」、批量运行、前置接口的选择里都排除 GRPC 接口（和 SIO 一样）。
- 标签页未保存的小圆点、关闭提示、切换接口时的状态保留，都和 Socket.IO 标签页一致。

## 共同规矩（每个任务都一样）

- 开工前读仓库根的 `CLAUDE.md` 和 `docs/HANDOFF.md`。用户可见的文字一律中文，界面和文档里不许出现「Postman」字样。
- **不要自己 git commit / add / push**，提交由 `ateam submit` 完成，只会提交本任务「允许改动的路径」。路径以外的文件一个都不要改；需要改别处就先 `ateam ask`。
- **不写新测试**。既有测试必须全过：`npm test`（71 个）。
- **不要改 `package.json` / `package-lock.json`**，依赖主会话已经装好（`@grpc/grpc-js`、`@grpc/proto-loader`）。用到时再 `require`（放函数里），别放文件顶部。不能用带原生模块（`.node`）的包。
- 不要提交、也不用管 `lib/web`（构建产物，主会话统一构建）。可以跑 `npm run build:web` 查语法，跑完 `git checkout -- lib/web && git clean -fdq lib/web` 还原。
- **绝对不要碰真实的 `~/.apiloop`**。要起服务自测就用临时目录：
  - 临时云端：`APILOOP_HOME=<临时目录>/x APILOOP_ADMIN_PASSWORD=adminpass123 node bin/server web --port 18xxx`
  - 临时网关：`APILOOP_HOME=<临时目录>/y node bin/server gateway --cloud=http://127.0.0.1:18xxx --port=18yyy`
  - 一次性探测脚本放系统临时目录（不进仓库），跑完删掉。
- 往接口的 `extra` 里写东西：**先读出原来的再合并**，不要整个覆盖。
- naive-ui 组件逐个 import，提交前核对模板里用到的 `n-*` 都引入了。
- **改了 `.vue` 文件**，提交前按 `CLAUDE.md` 里的办法用 vite SSR **带上真实形状的 props** 把组件跑一遍，再按那里写的「静态检查」查一遍「声明之前就用了」（`watch` / `computed` / 顶层调用用到后面才声明的 `const`）。这一类错误之前两次让 Body 一片空白。
- 前端用到 store 上的字段，先确认那个字段真的存在（以前出过 `gateway.isCloud` 根本不存在的事）。判断「是不是客户端里打开的」用 `useGatewayStore().isGateway`。
- 自测要走**用户真实会走的那条路**，拿真实数据跑一遍、把结果打出来看。
- 提交总结（`ateam submit`）里写清楚：改了哪些文件、每条验收标准怎么核对的、有什么没做或拿不准的。
