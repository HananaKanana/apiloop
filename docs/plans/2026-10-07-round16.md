## TCP / UDP 调试 · 后端

### 背景
硬件、物联网、游戏服务器这类接口不走 HTTP，apiloop 调不了。本任务新增两种接口方法 `TCP` 和 `UDP`，用来建连接、收发字节、看数据流。界面在后面的前端任务里做。
**照第十三轮 MQTT 那一套做**，会话模型完全一样（事件缓冲、seq、NDJSON 事件流、两个 60 秒倒计时、每人会话数上限、只有创建者能访问）。先读 `lib/mqtt-sessions.js`、`lib/api/mqtt.js`、`lib/api/dto.js` 的 `toApiMqtt` / `apiMqttOf`、`lib/api/tree.js` 保存 `extra.mqtt` 的地方，再 `grep -rn "'MQTT'" lib`，把每一处特殊处理都想一下 TCP / UDP 该怎么办，在提交总结里列出来。
只用 Node 自带的 `net` / `tls` / `dgram`，**不加依赖**。

### 接口约定

### 数据（存在接口上，会同步）
- `api.method` 是 `'TCP'` 或 `'UDP'`。
- `api.url` 的写法：
  - `tcp://host:port`（明文 TCP）
  - `tls://host:port`（TCP + TLS）
  - `udp://host:port`
  - 可以带 `{{变量}}`。
  - 方法和协议头对不上（方法 `UDP` 却写了 `tcp://`）时，按方法为准，只看 host:port。
- `api.extra.socket`，读写都经过 `dto.toApiSocket` / `apiSocketOf`。TCP 和 UDP 共用这一个结构，UDP 用不到的字段原样保存，不做处理：
```json
{
  "connectTimeoutMs": 10000,
  "tlsInsecure": false,
  "framing": { "type": "none", "delimiter": "\\n", "lengthBytes": 2, "endian": "be" },
  "sendEncoding": "text",
  "lineEnding": "none",
  "udp": { "bindPort": null, "broadcast": false },
  "saved": [ { "name": "查询状态", "payload": "AA 01 00 FF", "encoding": "hex" } ]
}
```
  - `framing.type` 决定**收到的数据怎样切成一条一条消息**（只对 TCP 生效，UDP 一个包就是一条）。
    - `none`：收到一块数据就算一条。
    - `delimiter`：按分隔符切。`delimiter` 用转义写法存，`\n`、`\r\n`、`\x00` 都要认。
    - `length`：长度前缀。`lengthBytes` 取 1 / 2 / 4，`endian` 取 `be` / `le`，长度值**不含**前缀本身。
  - `sendEncoding`：发送框的默认格式，取 `text` / `hex` / `base64`。
  - `lineEnding`：文本发送时自动加在末尾，取 `none` / `lf` / `crlf`。
  - `udp.bindPort`：本机绑定的端口，`null` 表示随机。
  - `udp.broadcast`：是否允许发广播。
  - `saved`：常用发送。
  - 非法值一律回到默认值（照 `toApiMqtt` 的写法）。

### 会话（路由形状照 `/mqtt`）
- **`POST /projects/:pid/socket`** 建会话。
  - 请求体：`{ apiId?, environmentId?, method: 'TCP'|'UDP', url, connectTimeoutMs, tlsInsecure, framing, udp }`。
  - 变量按 `/send` 同一套层级替换，包括保密变量和 `{{$guid}}` 这类。
  - 返回 `{ id: "sk_xxx", missing: [...] }`。
- **`GET /socket/:id/events`**：NDJSON 事件流，有这些事件：
  - `{"type":"connecting","method":"TCP","host":"1.2.3.4","port":9000}`。系统代理对它不起作用，所以和 MQTT 一样带上 `note`。
  - `{"type":"connected","local":{"address":"…","port":51234},"remote":{"address":"…","port":9000}}`。UDP 在 bind 成功后发这一行，不带 `remote`。
  - `{"type":"data","size":12,"text":"…或 null","base64":"…","from":{"address","port"},"at":…}`
    - 能原样转回 UTF-8 就给 `text`，否则 `text: null`，`base64` 总是给。
    - 单条超过 64 KB 截断，`size` 仍是原始大小，并带 `truncated: true`。
    - `from` 只在 UDP 才有。
  - `{"type":"sent","size":…,"text":…,"base64":…,"to":{"address","port"},"at":…}`：写进 socket 成功后再发这一行。
  - `{"type":"closed","reason":"remote"|"local"|"error"}`：TCP 对端关闭、自己断开、出错。closed 之后会话不再能发送，**不做自动重连**。
  - `{"type":"error","error":"中文"}`
  - 事件先缓存在会话里，页面晚连或重连时从头补发（照 MQTT）。
- **`POST /socket/:id/send`** 发送。
  - 请求体：`{ payload, encoding: 'text'|'hex'|'base64', to? }`。
  - `text` 可以带 `{{变量}}`，按建会话时的环境替换，替换后按 `lineEnding` 补行尾。
    - 行尾放在**请求体里传**（`lineEnding` 字段），不要读会话上存的值，因为界面上可以临时改。
  - `hex` 允许空格、换行和 `0x` 前缀；奇数位或有非法字符时返回 400「十六进制格式不对：…」。
  - `to` 只对 UDP 有用，可选 `{ host, port }`，不给就发到会话 url 上的地址。
  - TCP 在开了 `length` 分帧时，**发送也自动加上长度前缀**。
  - 返回 `{ ok: true, size }`。
- **`DELETE /socket/:id`**：断开连接并删掉会话。
- 常见错误要给中文提示：
  - 连接被拒绝（ECONNREFUSED）：「连不上，检查地址和端口」
  - 连接超时：「连接超时」
  - 域名解析不了（ENOTFOUND）：「域名解析不了」
  - 对端重置连接（ECONNRESET）：「对方重置了连接」
  - TLS 证书不受信任：「证书不受信任，可以勾选『忽略证书错误』」
  - UDP 端口被占用（EADDRINUSE）：「本机端口 N 被占用」
  - UDP 发广播但没开 broadcast：「要发广播请勾选『允许广播』」
- 这些路由只在本机网关上挂（照 `lib/admin.js` 挂 mqtt 的地方）。

### 其他地方对 TCP / UDP 的处理（和 MQTT 一致）

- `/send` 拦掉这两种接口，提示「TCP / UDP 接口请在它自己的标签页里连接」。

- 项目备份、复制、跨项目复制要带上 `extra.socket`，确认一遍。

## 后端提示国际化 · 框架 + 管理接口 / 网关 / 同步

### 背景
界面切到英文后，后端返回的错误提示还是中文。前端每个请求都已经带了 `Accept-Language`（`en` 或 `zh-CN`），后端一直没用上。
这项工作拆成三个任务：
- **本任务**：做框架，迁移 `lib/api/`、管理台 / 登录、网关和同步这几块。
- 下一个任务：迁移发送、断言、脚本、各种调试会话。
- 再下一个：迁移导入导出和备份。
所以框架要先定好，后两个任务照着用。

### 接口约定（框架，后两个任务也按这个写）
新建 `lib/i18n/index.js`：
```js
var i18n = require('../i18n');
i18n.m('有效期只能是 7 天、30 天或永久');            // 按当前语言返回
i18n.m('找不到接口「{name}」', { name: api.name });  // {占位符} 替换；参数值本身不翻译
i18n.mIn('en', '连接超时');                         // 显式指定语言（会话里用）
i18n.locale();                                      // 'zh-CN' | 'en'
i18n.middleware                                     // express 中间件
i18n.runWith('en', fn)                              // 在指定语言下执行 fn
```
- **以中文原文作键。**
  - 英文翻译放在 `lib/i18n/en/<区域>.js`，内容是 `module.exports = { '中文原文': 'English', ... }`，由 `index.js` 合并。每个任务只写自己区域的文件：本任务写 `api.js`、`gateway.js`，下一个写 `run.js`，再下一个写 `io.js`。
  - 中文语言下 `m` 原样返回（只做占位符替换）。英文下查不到就退回中文，所以漏翻不会报错。
  - 原文要一字不差：改了中文原文，就得同时改翻译文件里的键。
- **当前语言**用 `AsyncLocalStorage` 存。
  - `middleware` 解析 `Accept-Language`：以 `en` 开头的是 `'en'`，其他情况和没带都是 `'zh-CN'`，然后用 `als.run` 包住后续处理。
  - 在请求之外调 `m`（定时任务、同步引擎这类后台代码）时，用**最近一次请求的语言**。网关是单用户，这样后台消息也能跟着界面语言走。
  - 进程启动后还没收到过请求时，用中文。
- **拼接出来的句子**要改成整句加占位符。比如 `'找不到' + what` 改成 `m('找不到{what}', { what: m('接口') })`，或者干脆每种情况各写一整句。不要拆成半句翻译。
- 机器可读的 `code` 字段（比如 `SERVER_SEND_DISABLED`）保持不变。
- 英文用词照 `web/src/i18n/README.md` 的术语表（Folder、API、Environment、Test suite、Mock……），语气和前端英文一致，简短，以动词开头。
- **网关转发到云端的请求要带上 `Accept-Language`**（检查 `lib/gateway/cloud.js` 的 `headersForCloud`）。这样云端返回的错误，到了网关也是对的语言。

     - `send.js` 里只迁移它自己的校验文案；发送引擎（`send-core`、`executor`）产生的错误归下一个任务。
   - `lib/api/respond.js`，包括「服务端出错：」这种兜底文案
   - `lib/admin.js`、`lib/admin-auth.js`、`lib/auth.js`、`lib/access.js`

## 所有请求带上界面语言

### 背景
后端要开始按 `Accept-Language` 返回中文或英文提示，这是 backend 角色的另外三个任务。前端目前只有 `web/src/api/client.js` 和 `backup.js` 带了这个头，`stream.js`、`gateway.js`、`exportDoc.js` 这几处直接 `fetch` 的地方只带了 `CUSTOM_HEADERS`，没带语言。这些请求包括发送请求、各调试会话的 NDJSON 事件流、导出文档，它们拿到的提示就会一直是中文。

### 接口约定
- 所有发往本应用后端的请求都带 `Accept-Language`：界面是英文时带 `en`，否则带 `zh-CN`。判断照 `client.js` 现有的 `acceptLanguage()`。
