## 1. Mock 故障模拟（session2）

### 要解决的问题

前端要测「接口报错时提示对不对」「慢的时候有没有加载状态」「失败后会不会重试」，可 Mock 永远秒回、永远成功，只能临时去改每个接口的示例。

### 用户看到的样子

- **项目设置**加一块「Mock 故障模拟」：
  - 总开关「开启故障模拟」（关着时下面的设置保留但不生效）。顶部一行红字提示：「开启后，这个项目的 Mock 会按下面的比例故意出错，**所有调这个项目 Mock 的人都会受影响**。」
  - 一张规则表，每行：启用 · 故障类型 · 比例（%）· 参数 · 删除：
    - **返回错误**：状态码（默认 500）、响应体（默认 `{"code":500,"message":"模拟的服务器错误"}`）；
    - **随机延迟**：最少 / 最多毫秒（在原有延迟上再加）；
    - **超时**：等多久后直接断开（默认 30 秒），不返回任何内容；
    - **断开连接**：收到请求就立刻断开（客户端看到网络错误）；
    - **限流**：返回 429，带 `Retry-After` 头（秒数可填）。
  - 作用范围：整个项目 / 选几个目录 / 选几个接口（多选）。
  - 「快速预设」：「弱网（50% 延迟 1–3 秒）」「不稳定（10% 返回 500）」「全部失败（100% 返回 500）」，点了填进规则表。
- **目录树**：项目开着故障模拟时，左上角项目名旁边一个橙色小标「故障模拟中」，悬停说明，点了去设置。免得忘了关。
- **Mock 日志**：被故障命中的那条记录多一个标签「故障：返回错误 500」「故障：延迟 +1200ms」。
- **绕过**：请求带 `X-Apiloop-Fault: off` 头时不注入故障（方便自己调试时临时关掉）。设置页里写上这句。

### 数据

`projects.extra.mockFaults = { enabled, scope: { type: 'all' | 'folders' | 'apis', ids: [...] }, rules: [{ id, enabled, type, percent, status?, body?, minMs?, maxMs?, timeoutMs?, retryAfter? }] }`。
项目 DTO 顶层多给 `mockFaults`；保存接口接受，合并进 `extra`。

### 怎么做

- 在 `lib/mock-runtime.js` 的 `createHandler` 里、真正生成响应之前判断。每条启用的规则各自按比例掷一次骰子，
  命中的按「断开 > 超时 > 限流 > 返回错误」取第一个会结束请求的；延迟可以叠加在其他结果之前。
- 项目的故障设置怎么拿到：看 `routes-store` / `project-stores` 现在缓存了什么，能在 store 里顺带缓存项目的 `extra.mockFaults` 最好
  （项目改了会触发 store 的 change，见 `lib/db/index.js`）；不行就每次请求读一次项目行（一条主键查询，也可以接受）。
- 作用范围判断要知道这个 Mock 请求命中的是哪个接口、它在哪个目录下（目录要算上子目录）。
- SSE / WebSocket 的 Mock 先不管（只对普通 HTTP 响应生效），设置页里写清楚。
- Mock 日志的记录（`mockLog.record`）里加 `fault` 字段，前端日志抽屉显示。
- 比例的随机数：`Math.random()` 就行，不用可复现。

## 2. 项目分组和收藏（session1）

### 要解决的问题

项目多了以后，左上角下拉一长串找不到；常用的几个接口每次都要在树里翻。

### 用户看到的样子

- **左上角项目下拉**：
  - 顶部搜索框（按项目名过滤）；
  - 「收藏」区：收藏的项目，排最上面；
  - 然后按分组列出（分组标题可以折叠），没分组的放「未分组」；
  - 每个项目悬停时右边一个星标（收藏 / 取消）；
  - 底部「管理分组…」：弹窗里新建 / 改名 / 删除分组，把项目拖进分组（或者每个项目一个分组下拉，挑一种简单的做法）。删除分组 = 里面的项目回到「未分组」。
- **接口收藏**：接口右键「收藏」/「取消收藏」；目录树最上面一个「收藏」区（可折叠），列出这个项目里收藏的接口，点了打开。没有收藏时不显示这一块。
- **最近打开**：`⌘K` / `Ctrl+K`（现有的搜索接口弹窗）没输入时，列出最近打开的 20 个接口（跨项目，显示「项目名 / 接口名」），点了切到那个项目并打开。
- 这些都**只属于你自己**，不影响同事；在你登录的设备之间同步。未登录（本机空间）时也能用，只存在这台电脑，登录后合并上去。

### 数据（已建好：v14 `user_prefs`）

```
user_prefs(user_id, key, value, updated_at, deleted, dirty, seq)   主键 (user_id, key)
```

三个 key（value 都是 JSON）：

- `projectGroups`：`[{ id, name, projectIds: [...], collapsed }]`，数组顺序就是分组顺序；
- `favorites`：`{ projects: [projectId...], apis: [{ projectId, apiId }...] }`；
- `recent`：`[{ projectId, apiId, openedAt }]`，最多 20 条，新的在前。

一个 key 一行，「updated_at 大的赢」。两台设备同时改了同一个 key，后改的整份覆盖先改的 —— 可以接受（都是自己的操作）。

### 接口

| 接口 | 说明 |
| --- | --- |
| `GET /me/prefs` | 当前用户的全部偏好 `{ prefs: { projectGroups, favorites, recent } }`（没有的 key 给默认空值） |
| `PUT /me/prefs/:key` | `{ value }` 写一个 key（只认上面三个），返回新值 |
| `GET /prefs?since=<seq>` / `POST /prefs` | 同步用，**只在云端**，形状照 `/secrets`（`lib/api/secrets.js`） |

- `/me/prefs` 页面直接调，网关上读写的是**本机库**（不转发），这样离线也能用；同步由网关的同步引擎在后台做。
- 同步照你写的保密值同步（`lib/gateway/sync/secrets.js` + `lib/db/repos/secret-values.js` 里 dirty / seq / 墓碑那套）再写一份，
  或者把那套抽成能复用的两份 —— 你挑一个清楚的做法，**别把保密值的同步改坏**（改动前后都跑一遍你上次的 `/tmp/probe-secrets-sync.js`）。
- 未绑定空间并进账号（`mergeUnbound` / `bindLocalSpace`）：`user_prefs` 的 user_id 跟保密值一样换成账号并标 `dirty`。
- 前端：一个 `stores/prefs.js`，启动时 `GET /me/prefs`，改了就 `PUT`；后台同步拉到别的设备的改动后，
  状态里的 `dataVersion` 会变（看现在页面怎么跟着刷新项目和目录树的），这时重新拉一次偏好。
- 收藏的接口 / 项目被删了：显示时过滤掉（看不到的不显示），不用专门去清。
- 记「最近打开」：在打开接口标签页的地方记一笔（同一个接口再打开就挪到最前），合并成一次 `PUT`，不要每次打开都写（防抖 2 秒）。

## 3. GraphQL 自动补全（session2，第 1 节之后）

### 要解决的问题

现在 GraphQL 请求只是一个纯文本框，字段名全靠记，写错了发出去才知道。

### 用户看到的样子

- Body 选 GraphQL 时，查询编辑器上方一行：「Schema：未加载 [获取 Schema]」。点了用当前接口的地址、请求头、鉴权、环境变量发一次 introspection 查询；
  成功显示「Schema：已加载（12 个类型）· 刚刚 [刷新]」，失败显示原因（「这个地址不支持 introspection」之类）。
- 加载了 schema 后，查询编辑器里：
  - 字段名、参数名、类型自动补全（输入时弹出，`Ctrl+Space` 手动弹）；
  - 写错的字段标红波浪线，悬停看错误；
  - 悬停字段看类型和说明。
- 编辑器右边可以展开「文档」面板：从 Query / Mutation 开始一层层点进去看类型、字段、参数、说明（可以先做成简单的树，不用做得像 GraphiQL 那么全）。
- 变量编辑器（JSON）不用补全。
- schema 缓存在这个接口的标签页里（关掉标签页就没了），同一个地址的其他标签页可以共用（按 url 缓存在内存里）。

### 怎么做

- 前端编辑器是 CodeMirror 6：用 `cm6-graphql`（基于官方 `graphql` 包，提供补全、校验、悬停），装 `graphql` 和 `cm6-graphql` 两个依赖。
  先确认这两个包和现在的 CodeMirror 版本兼容，打包后的体积增加多少写进交接记录。
- introspection 请求**由服务端发**（网关里就是本机发，内网地址也行），复用现有发送流程：
  新接口 `POST /projects/:pid/graphql/schema`，请求体和 `/send` 一样（`request`、`apiId`、`environmentId`），
  服务端把 body 换成标准 introspection 查询，**不跑脚本、不写历史、不写 Cookie**，返回 `{ schema: <introspection 结果的 data> }`。
  对方返回了 `errors` 就把第一条错误的 message 给出来。响应超过 10MB 拒绝。
- 前端用 `graphql` 包的 `buildClientSchema` 把结果变成 schema，交给 `cm6-graphql`。
- 文档面板用 schema 对象自己画（类型 → 字段 → 参数），描述当纯文本显示，**不渲染 HTML**。
