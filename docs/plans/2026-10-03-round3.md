## 1. 回收站（session1）

### 要解决的问题

现在删目录、删接口是真删，而且会同步到全队。误删了没有任何办法找回。

### 用户看到的样子

- 左侧栏底部加一个「回收站」入口（图标 + 文字，有东西时显示条数）。点开是一个弹窗：
  - 列表：名称、类型（目录 / 接口 / 环境）、原来的位置、谁删的、什么时候删的；
  - 每行两个操作：「恢复」「彻底删除」；右上角「清空回收站」（要确认）；
  - 顶部一行灰字：「删除的目录、接口、环境在这里保留 30 天，团队成员都能看到和恢复。」
- 删除目录 / 接口 / 环境的确认框文字改成「删除后可以在回收站里恢复（保留 30 天）」。
- 恢复后：回到原来的目录；原来的目录也已经不在了，就放到项目根目录。提示「已恢复到 xxx」。
- viewer（只读成员）能看回收站列表，不能恢复、不能彻底删除（按钮不显示）。

### 数据（已建好：v9 `trash` 表）

```
trash(id, project_id, kind, name, location, payload, deleted_by, deleted_at, rev)
  kind     folder | api | environment
  location 删除时所在位置的文字，比如「user / 用户管理」，只给界面显示
  payload  JSON：{ "folder": [原始行...], "api": [...], "example": [...], "expectation": [...] }
           或 { "environment": [原始行] }
           原始行 = 同步用的那种格式（数据库列一一对应，下划线列名，JSON 列保持字符串），
           用 lib/sync/rows.js 的 rows.get / rows.list 那一套取
```

`trash` 是**第 7 种会同步的实体**（触发器已经建好）。要做的：

1. `lib/sync/rows.js` 的 `ENTITIES` 加 `trash`（`projectColumn: 'project_id'`，
   writable：`project_id, kind, name, location, payload, deleted_by, deleted_at`），`ORDER` 末尾加 `'trash'`。
2. 顺着 `lib/sync/index.js`（云端推送 / 拉取）和 `lib/gateway/sync/`（pull、push、apply、merge）推演一遍：
   新实体能不能正常推、拉、合并、删除。重点看有没有写死六种实体的地方（`index.js` 里对
   `example` / `expectation` 的特殊处理不用管）。
3. **兼容：** 新客户端连旧云端时，推 `trash` 会被旧云端拒绝。发版顺序是先升云端，所以可以接受，
   但要确认被拒时只是这几条推送失败、不会把整个同步卡死；卡死的话想办法让它跳过并记日志。
   旧客户端拉到 `trash` 的变更会忽略（`pull.js` 里有 `rows.has` 判断），确认一下。

### 接口（都挂在登录之后）

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /projects/:pid/trash` | viewer | 列表，按删除时间倒序。不返回 payload，返回 `{ id, kind, name, location, deletedBy: {id, displayName}, deletedAt, count }`，count 是里面有几个接口 |
| `POST /trash/:id/restore` | editor | 恢复。返回 `{ restoredTo: '位置文字', folderId?, apiId?, environmentId? }` |
| `DELETE /trash/:id` | editor | 彻底删除一条 |
| `DELETE /projects/:pid/trash` | editor | 清空 |

### 删除时写回收站

改现有的三个删除接口：`DELETE /folders/:id`、`DELETE /apis/:id`、`DELETE /environments/:id`。
在**同一个事务里**，先把这次真正会被删掉的行全部取出来存进 `trash`，再照常删除。

- 删目录有两种模式（`lib/tree.js` 的 `removeFolder`）：
  - `apis=delete`：整棵子树（目录、子目录、里面的接口、接口的示例和期望）都进 payload；
  - 默认的「move」模式：里面的东西挪到上一级，**只有这一个目录行**被删 —— payload 里就只有这一个目录。
- 删接口：接口行 + 它的示例 + 期望。
- 项目删除**不进**回收站（只有 owner 能删，本来就有确认）。示例单独删除也不进（太碎）。
- `deleted_by` 是当前用户 id，`location` 用目录链拼出来（「父 / 子」），根目录写「根目录」。

### 恢复

- **换新 id 插回去**，payload 内部的引用（`parent_id`、`folder_id`、`api_id`、`mock_example_id`、
  期望的 `example_id`）跟着改成新 id。原因：老 id 已经在同步的变更流水里标成删除，原样插回去会
  和各端的同步基线打架；换新 id 就是一次普通的新建。
- 插入用 `rows.insert`（只写认识的列，以后表加了列也能恢复老数据）。
- 顶层那个目录 / 接口的父目录：payload 里记的父目录还在就放回去，否则放根目录；position 放到同级最后。
- 恢复完删掉这条 `trash`。都在一个事务里。
- 环境：插回去，position 放最后。重名就在名字后面加「（恢复）」。

### 30 天清理

`lib/command.js:327` 附近（云端定时清理变更流水的地方）一起清 `deleted_at` 早于 30 天的回收站行。
网关不用自己清：云端清掉之后，删除会同步下来。未登录（unbound）的本机空间没有云端，在网关启动时清一次。

### 验收清单（给用户）

1. 删一个接口 → 回收站里有，恢复后回到原目录，示例、Mock 都还在。
2. 删一个带子目录的目录（选「连同接口一起删」）→ 恢复后整棵树都回来。
3. 先删接口，再删它所在的目录（只删目录、接口挪到上一级）→ 恢复接口时它回到上一级。
4. 两台客户端登录同一个账号：A 删，B 的回收站里能看到并能恢复；恢复后 A 那边也出现。
5. 只读成员看得到回收站，看不到「恢复」按钮。

## 2. 批量运行（session2）

### 要解决的问题

一个目录里几十个接口，想一口气按顺序跑一遍、看哪些断言没过（冒烟测试、改完后端回归一下）。

### 用户看到的样子

- 入口：目录右键菜单「运行」，目录标签页右上角「运行」按钮，项目根（目录树顶上的项目名 / 空白处右键）「运行全部」。
- 点了打开一个新标签页「运行：目录名」（标签页类型 `runner`，和接口标签页并列）。
  - 左边：要跑的请求列表（按目录树顺序，默认全选，可以勾掉），WebSocket 接口不列出来。
  - 右边上面是设置：环境（默认当前环境）、次数（1–100，默认 1）、每个请求之间等多久（毫秒，默认 0）、
    「有断言失败时停下来」（默认不勾）、「记到历史里」（默认不勾）。
  - 「开始运行」→ 按顺序一个个发，跑的时候按钮变成「停止」。
- 结果区：
  - 顶部汇总：一共几个请求、通过 / 失败的断言数、总耗时；
  - 列表：每次请求一行（第几次 · 方法 · 名称 · 状态码 · 耗时 · 断言 x/y），失败的标红；
    点开看每条断言的名字和失败原因、脚本控制台输出；
  - 过滤：全部 / 只看失败；
  - 点某一行的名称能打开那个接口的标签页。
- 运行结果只在这个标签页里，关掉就没了（不存库）。

### 怎么实现

**基本全在前端**，复用现有的发送接口：

- 每个请求：取接口详情（`GET /apis/:id`），像打开接口标签页那样转成发送用的 spec（找 `stores/tabs.js`
  里打开接口时的转换，复用，不要再抄一份），然后调非流式的 `POST /projects/:pid/send`，
  带上 `apiId`、`environmentId`、`mockBase`（和 `tabs.js` 的 `sendRequest` 一样）。
- 变量在请求之间传递：脚本里 `pm.environment.set` 的值服务端已经会写回（`writeBackVariables`），
  下一个请求自然读得到。跑完调一次环境 store 的刷新，让界面上的变量值跟上。
- 「停止」：用 AbortController 中断当前请求，后面的不再发。
- 「记到历史里」：**需要改 `lib/api/send.js`**：请求体的 `options` 里认一个 `skipHistory: true`，
  为 true 时不写历史（`record` 那一处）。批量运行默认带上它。**只改这一处，先做、尽早提交**（见第 0 节）。
- 断言结果、控制台输出就在发送接口返回的 `result` 里（`tests` 等字段，看 `lib/send-core.js`），直接用。
- 运行中切走标签页不能中断运行；关掉标签页要中断。

### 暂不做

- 数据文件（CSV / JSON 每行跑一次）。等这一版用起来再说。
- 拖拽调整顺序、保存运行配置、导出报告。

### 验收清单（给用户）

1. 目录右键「运行」→ 打开运行标签页，列表顺序和目录树一致。
2. 登录接口的「响应后」脚本里 `pm.environment.set("token", ...)`，后面的接口用 `{{token}}`，批量跑能串起来。
3. 有一个接口断言失败 → 标红，「只看失败」能筛出来，点开看到原因。
4. 次数设 3 → 每个接口跑 3 遍。跑到一半点「停止」能停。
5. 默认不勾「记到历史里」→ 历史里没有新增；勾上 → 有。

## 3. 保密变量（session1，回收站之后）

### 要解决的问题

现在变量表里已经有「保密」开关（`VarTable.vue` 的眼睛图标，行上 `secret: true`），但**只是遮住显示**，
值照样存进项目 / 环境、同步给全队、导出到 JSON 文件里。密码、私人 token 不该这样。

### 改成什么样

标了保密的变量：

- **值只属于自己**：客户端里只存在这台电脑；网页版存在服务器上，但只有自己能读到。
  同事能看到有这个变量（名字），值是空的，需要自己填。
- 不同步、不导出（导出的 JSON 里值为空）、不出现在分享文档里。
- 发请求时用自己的值替换，和普通变量一样。
- 变量表里保密的那一行，值输入框旁边一行小灰字（或悬停提示）：「只保存在你自己这里，不会同步给别人」。
- 第一次把一个有值的变量设成保密：值从共享数据里拿掉，存成自己的；**同事那边这个值会变成空**。
  打开开关时提示一句：「设为保密后，这个值只保存在你这里，其他成员需要各自填写。」

### 数据（已建好：v10 `secret_values` 表，不同步）

```
secret_values(user_id, scope, scope_id, key, value, updated_at)   主键 (user_id, scope, scope_id, key)
  scope     project | folder | environment
  scope_id  项目 / 目录 / 环境的 id
```

### 怎么做

- **写入**（保存项目变量、目录变量、环境变量的接口，以及 `send.js` 里脚本写回变量的 `writeBackVariables`）：
  `secret: true` 的行，把 value 存进 `secret_values`（当前用户），JSON 里那一行的 value 存成 `''`。
  建议在一处写一个 `lib/secrets.js`：`split(handle, userId, scope, scopeId, rows)` 返回去掉值的 rows 并写表；
  `merge(handle, userId, scope, scopeId, rows)` 把自己的值填回去。
- **读出**（返回给页面的项目、目录、环境）：用 `merge` 把当前用户的值填回去，页面不用改就能显示、编辑。
- **发送**：`send.js` 里 `resolveVariables`、`prepare` 里给脚本的各层变量，都要先 `merge`。
- **导出 JSON**：保密行的值输出空串（`lib/postman.js` 已经会输出 `type: 'secret'`，确认值是从库里读的空值）。
- **历史**：历史里存的是替换后的请求，会带上保密值。存历史前把这次用到的保密值（长度 ≥ 4 的）替换成 `******`
  （看 `lib/redact.js` 现在怎么遮 Authorization，放在一起）。
- **本机空间合并**（`lib/gateway/space.js` 的 `mergeUnbound`，未登录用的数据并进账号空间时）：
  `secret_values` 里旧用户 id 的行要改成新用户 id 一起带过去。
- **同步**：`secret_values` 不在同步实体里，什么都不用做；但确认推上去的变量 JSON 里保密行确实是空值。
- 删除目录 / 环境时，顺手删掉对应 scope_id 的 `secret_values`（不删也没害处，有空就做）。

### 验收清单（给用户）

1. 环境里加 `password`，设成保密、填值 → 发请求能用上。
2. 另一个账号（或另一台登录同一项目的电脑）看到 `password` 这个变量，值是空的。
3. 导出环境 JSON → 里面 `password` 的值是空的。
4. 脚本里 `pm.environment.set("password", "x")`（变量已标保密）→ 别人那边仍然看不到值。
5. 历史记录里看这次请求，保密值显示成 `******`。

## 4. 接口文档分享（session2，批量运行之后）

### 要解决的问题

给前端、测试或外部合作方看接口，现在只能导出文件发过去。要一个链接，打开就是只读的接口文档，对方不用注册账号。

### 用户看到的样子

**生成链接：**

- 目录右键菜单「分享文档」，项目根右键「分享整个项目的文档」。
- 弹窗：
  - 有效期：永久 / 7 天 / 30 天（默认 30 天）；
  - 「生成链接」→ 显示链接 + 「复制」按钮；
  - 提示：「打开链接的人不用登录就能看到这些接口的地址、参数和示例。保密变量和鉴权信息不会出现。
    分享的是云端的数据，本机还没同步上去的改动看不到。」
- 未登录（本机空间）时这两个菜单项不显示（分享依赖云端）。
- 项目设置页加一个「分享链接」区域：列出这个项目已生成的链接（范围、谁建的、什么时候、有效期至），
  每行「复制」「撤销」。owner / editor 能撤销，viewer 只能看。

**打开链接（文档页）：**

- 地址：`<云端地址>/#/share/<链接串>`，不用登录。
- 左边目录树（只有分享范围内的），右边选中接口的文档：
  - 名称、方法、地址（`{{host}}` 这类变量原样显示）、说明（`description`，按段落显示）；
  - Params / Headers 表格（名称、示例值、说明）；Authorization、Cookie、带 token / key / secret 字样的头，值显示成 `******`；
  - Body（JSON 美化显示）；鉴权只显示类型（「Bearer Token」），不显示值；
  - 示例：每个示例的名称、状态码、响应体；
  - 这个项目的 Mock 地址 + 复制按钮（对方可以直接拿去调）；
  - 「复制为 cURL」。
- 链接过期或被撤销：显示「这个链接已失效，请联系分享给你的人」。
- 页面顶部只有 apiloop 标志和项目名，没有登录入口、没有其他菜单。

### 数据（已建好：v11 `shares` 表，只在云端用，不同步）

```
shares(id, project_id, folder_id, title, created_by, created_at, expires_at)
  id         链接里的随机串，用 crypto.randomBytes(18).toString('base64url')（24 位）
  folder_id  空 = 整个项目
  expires_at 空 = 永久；撤销 = 删行
```

### 接口

**管理（登录后，只在云端；网关要转发给云端）：**

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /projects/:pid/shares` | viewer | 列表 |
| `POST /projects/:pid/shares` | editor | `{ folderId?, expiresInDays?: 7 \| 30 \| null }`，返回 `{ share: {id, ...} }` |
| `DELETE /shares/:id` | editor（项目的） | 撤销 |

网关：`lib/gateway/account.js` 的 `cloudOnlyPath` 加上 `/projects/<pid>/shares` 和 `/shares/...`，
这样客户端里的请求会转给云端（和成员管理、Mock 日志一样）。

**公开（不登录）：**

`GET /__admin/api/public/shares/:id` → 文档数据。挂在 `requireLogin` **之前**（参考 `lib/admin.js` 里
登录接口、下载接口是怎么放在登录前面的）。过期 / 不存在一律 404 + `{ ok:false, error:'这个链接已失效' }`。
返回内容在**服务端**就脱敏好（不要把原始数据交给前端再遮）：

**几个实现上的决定（主会话审阅时重点看这几处）：**

1. **跑的逻辑在 store 里，不在组件里。** 标签页正文是按 kind 渲染的，运行中切走会把
   `RunnerTab` 卸载掉 —— 逻辑放在组件里一卸载就断了，而计划明确要求「切走不中断」。
   状态挂在 `tab.runner` 上（`utils/runner.js` 的 `emptyRunner`），组件只是它的视图。
   「关掉标签页要中断」靠 `dropTab` 里 `abort(tab.runner.controller)` + 跑的那一段
   自己检查标签页还在不在列表里（`tabs.tabs.indexOf(tab)`）。
2. **`viewer` 也能运行**：右键菜单和目录页签的「运行」对只读角色都显示 ——
   服务端 `/send` 本来就是 viewer 权限，发请求正是只读角色要做的事。计划里没写这一条，
   按「谁能发请求谁就能批量跑」处理；要按角色藏的话是一行的事。
3. **接口详情按接口缓存**（`Map`），次数设 3 时同一个接口不会重复拉 3 次详情。
4. **环境在开跑那一刻定下来**（`runner.envId`，默认跟当前环境），跑的过程中用户改当前环境
   不影响这一次。
5. **间隔只加在两次请求之间**，最后一条后面不等；「有断言失败时停下来」在那一行跑完就停。
6. 次数 / 间隔在 `start` 里又 clamp 了一次（输入框打完字直接点开始时可能还没 clamp）。

**没做（计划里本来就排了「暂不做」）：** 数据文件（CSV / JSON 每行跑一次）、
拖拽调整顺序、保存运行配置、导出报告。

**要提醒主会话 / 用户的两点：**

1. 运行结果**不落库**，关掉标签页就没了 —— 这是计划要求的。
2. 批量运行走的是 `POST /send`，它受 `APILOOP_SERVER_SEND` 影响。
   网关（本机客户端）是开着的，没问题；**云端 `docker-compose.yml` 里
   `APILOOP_SERVER_SEND: ${SERVER_SEND:-1}` 默认是 1**，也开着。
   但如果哪天云端改成 `SERVER_SEND=0`，在云端网页版上批量运行会**每一行都报
   「云端不发送请求，请从本机的 apiloop 打开」** —— 这不是 bug，是那个开关的预期行为。
