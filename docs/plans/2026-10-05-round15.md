## T19 国际化 · 框架 + 顶栏和侧栏（frontend，T16 通过后）

### 背景
用户要界面支持中文和英文（先做这两种，以后可能再加）。前端几千处中文写死在组件、store、工具函数里。这一轮拆成几个任务：
**T19（本任务）搭框架、定规矩，顺便把 `layout/`（顶栏、侧栏、项目下拉、头像菜单……）和 `App.vue` 迁完当样板**；T21–T25 按目录并行迁移其余部分。
后端返回的错误信息这一轮先不管（仍是中文），下一阶段再做。主会话已装 `vue-i18n` v11。

### 框架约定（写进 `web/src/i18n/README.md`，后面的任务照着做）
- `web/src/i18n/index.js`：`createI18n({ legacy: false, locale, fallbackLocale: 'zh-CN', messages })`；导出 `i18n`、`t`（`i18n.global.t`，给 store / 工具函数 / 非组件代码用）、`setLocale(locale)`、`currentLocale()`。
- **按区域拆文件**：`web/src/i18n/locales/zh-CN/<区域>.js`、`web/src/i18n/locales/en/<区域>.js`，`export default { ... }`，用 `import.meta.glob(..., { eager: true })` 收集，区域名就是文件名，键写成 `t('<区域>.<键>')`。区域名和目录对应（`layout`、`request`、`grpc`、`stores`、`utils`……），**每个任务只写自己区域的文件**，并行时不会打架。
- 组件里 `const { t } = useI18n()`，模板里 `{{ t('layout.search') }}`；带参数用 `t('x.count', { n })`，复数用 vue-i18n 的 `|` 写法。
- 不翻译：用户数据（项目名、接口名、变量名）、代码、HTTP 方法、状态码、`{{变量}}` 写法、日志原文。
- 用 `computed` 包住依赖语言的选项数组（下拉选项、表头），**切换语言后要立刻变**，不能只在创建时算一次。
- 英文用词统一：Project、Folder、API（接口）、Environment、Variable、Mock、Test suite、Assertion、Extract、Example、Expectation、Workbench……在 README 里列一张术语表，后面的任务照用。界面和文档里不许出现「Postman」。

### 要做的事
1. 框架：`web/src/i18n/`（index.js、README.md、`locales/zh-CN/app.js`、`locales/en/app.js`、`layout.js` 两份）；`web/src/main.js` 装插件。
2. 语言选择：头像菜单里「语言 / Language」（中文 / English），存 `localStorage`（读写包 try/catch）；第一次打开按浏览器语言（`zh*` → 中文，其余英文）；切换后整个界面立刻换，不刷新页面。`<html lang>` 跟着改。
3. naive-ui 跟着切：`App.vue` 的 `NConfigProvider` 的 `locale` / `date-locale`（`zhCN` / `enUS`、`dateZhCN` / `dateEnUS`）。
4. `web/src/api/client.js`：每个请求带 `Accept-Language`（`zh-CN` / `en`），给下一阶段后端用。
5. 把 `web/src/components/layout/` 下所有组件和 `App.vue` 的界面文字迁成 `t()`，中英文都写全。
6. 自测：vite SSR 分别用 `zh-CN`、`en` 渲染 layout 下每个组件，确认英文时渲染结果里没有中文（注释除外）、中文时和改之前一样；写一个临时脚本核对 `zh-CN` 和 `en` 两份的键完全一致。

### 不要做的事
- 只动下面允许的路径；其他目录是 T21–T25 的事。不改后端。

（与 --accept 一致）

## T21 国际化 · 迁移：请求编辑和响应（frontend，T19 通过后）

### 背景
T19 搭好了国际化框架，规矩和术语表在 `web/src/i18n/README.md`（**先读它**），`components/layout/` 已经迁完可以照着看。
本任务把下面这些目录里的界面文字迁成 `t()`，中英文都写全。和其他迁移任务并行，所以**只写自己区域的语言文件**。

### 要做的事
1. 目录：`web/src/components/request`、`web/src/components/response`、`web/src/components/common`、`web/src/components/assertions`、`web/src/components/fields`、`web/src/components/scripts`、`web/src/components/preflight`。
2. 语言文件：每个目录一个区域，`web/src/i18n/locales/zh-CN/<目录名>.js` 和 `en/<目录名>.js`（比如 `request.js`）。
3. 所有用户看得到的文字都迁：模板文字、`placeholder`、`title`、tooltip、`message.success/error/warning` 的提示、对话框标题和按钮、下拉选项、表头、空状态说明、`aria-label`。注释不用动。
4. 依赖语言的选项数组、表头用 `computed` 包住，切换语言后立刻变。
5. 自测：vite SSR 带真实 props 分别用 `zh-CN`、`en` 渲染每个改过的组件，英文时渲染结果里不能有中文、中文时和改之前一样；临时脚本核对两份语言文件键一致；`npm run build:web` 通过；「声明之前就用了」静态检查。

### 不要做的事
- 只动允许的路径。不改后端、不改别的区域的语言文件。不翻译用户数据、代码、HTTP 方法、`{{变量}}`。
