## 响应筛选（JSONPath / 关键字） · 前端

### 背景
响应很大时（几百 KB 的列表），想找某个字段只能翻屏或者 ⌘F。现在要在响应 Body 上加「筛选」：
- 用 JSONPath（比如 `$.data.list[*].id`）只看需要的部分；
- 或者用关键字筛选。
筛选结果能一键复制。

纯前端任务。响应 Body 的显示在 `web/src/components/response/BodyViewer.vue`（还有 `JsonTreeView.vue`）。依赖 `jsonpath-plus` 主会话已经装好（devDependencies），直接 `import { JSONPath } from 'jsonpath-plus'`。

### 用户看到的样子
- Body 工具栏多一个「筛选」按钮（漏斗图标），快捷键 `⌘⇧K` / `Ctrl+Shift+K`，先确认没被占用。点开后，Body 上方出现一行筛选栏：
  - **模式切换：JSONPath / 关键字。**
    - 响应是 JSON 时默认 JSONPath，否则默认关键字。
    - 响应不是 JSON 时，JSONPath 灰掉。
  - **输入框**，输入后防抖 300 毫秒生效。
    - JSONPath 模式的 placeholder 写 `$.data.list[*].id`。
    - 关键字模式不区分大小写，旁边有「区分大小写」开关。
  - **右侧显示结果数量**：「12 个结果」/「没有匹配」。JSONPath 写错时，把错误显示在输入框下方，用红色小字，不要弹窗。
  - **「复制结果」按钮**，复制后提示已复制。
  - **「×」关闭筛选**，关闭后回到完整响应。
- **JSONPath 的结果：**
  - 只有一个结果时，直接显示那个值。
  - 多个结果时，显示成数组。
  - 用现有的 JSON 代码视图显示，带格式化和高亮，**只读**。
  - 每个结果旁边可以看到它的路径，比如 `$.data.list[3].id`。可以做一个切换「显示路径」：打开后结果显示成 `[{ path, value }]`，复制时也复制这个形状。
- **关键字的结果：** 只显示包含关键字的行，带行号，关键字高亮。
  - JSON 响应要先格式化成多行，再按行筛选。
  - 「复制结果」复制这些行，不带行号。
- **常用表达式：** 输入框获得焦点时，下拉显示这个接口最近用过的 5 条 JSONPath，存在 `localStorage`，按接口 id 分开存，读写都包在 try/catch 里。
- **持续生效：** 筛选条件跟着标签页走。重新发送请求后，筛选条件保留，自动作用到新响应上。
- **大响应：** 超过 `FORMAT_LIMIT` 的响应照样能筛选，计算放到 `requestIdleCallback` 或 `setTimeout` 里做，别卡住界面；结果超过 5000 行时只显示前 5000 行，并给出提示。
- 中英文都要有，用 `response` 区域。

## 响应另存为文件 · 后端

### 背景
接口返回图片、Excel、PDF、压缩包时，用户要能**预览**，也要能**保存成文件**。

现在的情况：
- `lib/executor.js` 把响应 Body 放进内存，最多 5 MB（`DEFAULT_MAX_BODY_BYTES`）。超出部分截断，并标上 `truncated: true`。非文本内容用 base64 返回给页面（`bodyEncoding: 'base64'`）。
- 页面上的「下载」用的就是这份内存里的内容。**所以超过 5 MB 的文件保存下来是坏的**，而且文件名一律是 `response.xxx`，没有用接口给的文件名。

本任务做后端这一半：
1. **完整的响应 Body 落一份临时文件**，给页面一个下载地址。
2. **从 `Content-Disposition` 里取出文件名**。

页面上的预览和保存是后面的前端任务。

### 接口约定
- **发送结果多两个字段**：`/send` 的普通结果，以及 `/send/stream` 最后那个结果事件里的 `response`，都加上：
  - `fileName`：从响应头 `Content-Disposition` 取出的文件名，没有就是 `null`。
    - `filename*=UTF-8''%E6%8A%A5%E8%A1%A8.xlsx` 要解码。
    - `filename="报表.xlsx"` 也要支持，包括后端直接发 UTF-8、或者按 latin1 发的中文。
    - 两种写法都有时，优先用 `filename*`。
    - 去掉路径部分，只留文件名本身，防止 `../`。
  - `fileId`：**只在「非文本」或「被截断」的响应上才有**，形如 `"rf_xxx"`；其他情况是 `null`。
    - 非文本的判断沿用 `isTextContentType`。
    - 这个文件里存的是**完整**的响应 Body，**解压之后**的，和页面上看到的一致。
    - 文件上限 200 MB。超过 200 MB 的部分不再写，结果里给 `fileTruncated: true`。
- **`GET /response-files/:id`**：下载这个文件。
  - 响应头：
    - `Content-Type` 用原响应的类型；
    - `Content-Disposition: attachment`，文件名是 `fileName`，没有的话用 `response.<扩展名>`；
    - `Content-Length`。
  - 只有发起这次请求的用户能下载，别人一律 404。
  - 文件不存在或已过期，返回 404「文件已过期，请重新发送」。
- **临时文件的存放和清理：**
  - 放在 `APILOOP_HOME` 下的临时目录，比如 `tmp/response-files/`。
  - 每个文件保留 1 小时。
  - 每个用户最多保留 20 个，超出删最旧的。
  - 网关启动时清空这个目录。
- **哪些发送会落文件：**
  - **只有页面上的发送**（`/send`、`/send/stream`）才落文件。
  - 测试集运行、批量运行、压测、前置接口这类内部发送**不落文件**：加一个选项，默认关，只在那两条路由上打开。
- 云端（`SERVER_SEND=1` 时也能发送）和网关行为一致。

### 要做的事
1. `lib/executor.js`：在读取响应的那条流上，加一路「写临时文件」。内存里那 5 MB 的逻辑不变。注意背压，写文件慢的时候不要把整个响应攒在内存里。
2. 新建一个模块，比如 `lib/response-files.js`：管文件的登记、下载、过期清理、启动时清空。
3. 在 `lib/api/send.js` 打开落文件选项，把 `fileId`、`fileName` 带出去。新增路由 `GET /response-files/:id`。
4. 自测：在 scratchpad 起一个 HTTP 服务器，通过临时网关（起法见 CLAUDE.md）发请求，把结果打出来。跑完删掉。要覆盖：
   - 返回 8 MB 的二进制：内存里那份截断，下载的文件完整，sha256 和原文件一致。
   - gzip 压缩的响应。
   - `Content-Disposition` 的几种写法（`filename*`、中文 `filename`、带路径的 `filename`）。
   - 文本响应没有 `fileId`。
   - 别人下载拿到 404。
   - 过期后拿到 404（把过期时间临时调小来测）。
   - 测试集运行时不落文件。
5. `npm test` 全过。

### 不要做的事
- 不改前端（`web/`），不改 `package.json`。
- 新文案用 `i18n.m()`（框架在 `lib/i18n/index.js`），英文写进新文件 `lib/i18n/en/files.js`。

## RabbitMQ 调试 · 后端

### 背景
用户要调 RabbitMQ：往交换机发消息、从队列收消息、看消息流。为此新增一种接口方法 `AMQP`，界面上叫「RabbitMQ」。这个任务只做后端，界面在后面的前端任务里做。

**会话模型照 MQTT 和 TCP / UDP 那一套做**：事件缓冲、seq、NDJSON 事件流、两个 60 秒倒计时、每人会话数上限、只有创建者能访问。动手前先读这几处：
- `lib/mqtt-sessions.js`、`lib/socket-sessions.js`、`lib/api/mqtt.js`
- `lib/api/dto.js` 的 `toApiMqtt`
- `lib/api/tree.js` 里保存 `extra.*` 的地方

然后 `grep -rn "'MQTT'\|'TCP'" lib`，每一处特殊处理都想一下 AMQP 该怎么处理，在提交总结里逐处列出来。

依赖 `amqplib`（v2，纯 JS）主会话已经装好。在函数里 `require`，不要放到文件顶部。

### 接口约定

### 数据（存在接口上，会同步）
- `api.method = 'AMQP'`。
- `api.url` 是连接地址，比如 `amqp://user:pass@host:5672/vhost`、`amqps://…`，可以带 `{{变量}}`。
- `api.extra.amqp` 存连接配置，读写都过 `dto.toApiAmqp` / `apiAmqpOf`，非法值回到默认值：
```json
{
  "username": "{{mqUser}}", "password": "{{mqPassword}}",
  "heartbeat": 60, "connectTimeoutMs": 10000, "tlsInsecure": false,
  "consumers": [
    { "mode": "queue", "queue": "orders", "exchange": "", "routingKey": "", "ack": "auto", "prefetch": 10, "enabled": true },
    { "mode": "exchange", "queue": "", "exchange": "events", "routingKey": "order.*", "ack": "auto", "prefetch": 10, "enabled": true }
  ],
  "saved": [
    { "name": "下单", "exchange": "events", "routingKey": "order.created", "payload": "{\"id\":1}",
      "properties": { "contentType": "application/json", "persistent": true, "headers": [ { "key": "x-src", "value": "apiloop", "enabled": true } ],
                      "correlationId": "", "replyTo": "", "expiration": "", "messageId": "", "priority": null } }
  ]
}
```
- `username` / `password`：地址里没写账号密码时，用这两个字段。
- `consumers` 每一项的 `mode`：
  - `queue`：直接消费一个已有的队列。
  - `exchange`：建一个临时队列（exclusive、auto-delete），用 `routingKey` 绑定到 `exchange` 上，用来「旁听」发到这个交换机的消息。
- `ack` 取 `auto` 或 `manual`。`prefetch` 只在 `manual` 时生效。

### 会话（路由形状照 `/mqtt`）
- **`POST /projects/:pid/amqp`** 建会话。
  - 请求体：`{ apiId?, environmentId?, url, username, password, heartbeat, connectTimeoutMs, tlsInsecure, consumers }`。
  - 变量替换和 `/send` 是同一套层级。
  - 返回 `{ id: "aq_xxx", missing: [...] }`。
  - 连上之后，把 `enabled` 的 consumers 逐个开起来。
- **`GET /amqp/:id/events`**：NDJSON 事件流，事件有这几种：
  - `{"type":"connecting","url":"amqp://host:5672/vhost"}`：地址里的密码要遮掉。
  - `{"type":"connected","server":{"product":"RabbitMQ","version":"3.13.1"}}`
  - `{"type":"consuming","consumerTag":"…","mode":"queue","queue":"orders"}`
    - `exchange` 模式还要带上 `exchange`、`routingKey`，以及临时队列的名字。
  - `{"type":"cancelled","consumerTag":"…","byServer":false}`：队列被删时 `byServer` 是 `true`。
  - `{"type":"message","consumerTag","deliveryTag","exchange","routingKey","redelivered","properties":{…},"payload":"文本或 null","payloadBase64":"…","size","at"}`
    - 内容能原样转回 UTF-8 时给 `payload`，否则 `payload: null`，只给 `payloadBase64`。
    - 单条消息最多 64 KB，超出截断，带 `truncated: true`。
    - `ack` 是 `manual` 时，事件里加 `pendingAck: true`。
  - `{"type":"published","exchange","routingKey","size","at"}`：用 confirm channel，broker 确认之后才发这一行。
  - `{"type":"returned","exchange","routingKey","replyText"}`：发布时带 `mandatory`，消息路由不到任何队列时发这一行。
  - `{"type":"acked","deliveryTag","action":"ack|nack|reject","requeue":false}`
  - `{"type":"closed"}`、`{"type":"error","error":"中文提示"}`
- **`POST /amqp/:id/consume`**：请求体同 `consumers` 的一项，返回 `{ consumerTag }`。
- **`POST /amqp/:id/cancel`**：`{ consumerTag }`。
- **`POST /amqp/:id/ack`**：`{ consumerTag, deliveryTag, action: 'ack'|'nack'|'reject', requeue }`。
- **`POST /amqp/:id/publish`**：`{ exchange, routingKey, payload, properties, mandatory }`。
  - `exchange` 为空字符串，表示发到默认交换机，这时 `routingKey` 就是队列名。
  - `payload` 文本可以带 `{{变量}}`，按建会话时的环境替换。
  - `properties.headers` 是 `[{key, value, enabled}]` 表格，要转成对象。
- **`POST /amqp/:id/queue-info`**：`{ queue }`，用 `checkQueue` 查，返回 `{ messageCount, consumerCount }`。
- **`DELETE /amqp/:id`**：断开连接并删除会话。
- **channel 出错要自动恢复**：amqplib 里一个 channel 级错误（比如队列不存在 404、参数不匹配 406）会把整个 channel 关掉。这时要：
  - 发一条 `error` 事件；
  - 自动重建 channel，并重新开起之前还在消费的 consumers；
  - 连接本身不断。
- **常见错误要给中文提示**：
  - 连不上：「连不上 RabbitMQ，检查地址和端口」
  - 账号密码错（ACCESS_REFUSED）：「用户名或密码不对」
  - vhost 不存在或没有权限：「vhost 不存在，或者这个账号没有权限」
  - 队列不存在（404 NOT_FOUND）：「队列 X 不存在」
  - 交换机不存在：「交换机 X 不存在」
  - 声明参数冲突（406 PRECONDITION_FAILED）：「参数和已存在的队列 / 交换机不一致：…」
  - TLS 证书问题
  - 心跳超时被断开
- 这些路由**只在本机网关上挂**。新文案用 `i18n.m()`，英文写进新文件 `lib/i18n/en/amqp.js`。

     - auto 和 manual 两种 ack，manual 下 nack 并 requeue 后会重新收到；

     - mandatory 消息路由不到时收到 returned；
     - 二进制消息；
     - 消费一个不存在的队列，channel 自动恢复，另一个 consumer 不受影响；
     - 账号密码错；
     - 别人的会话返回 404；
     - 删除会话后，broker 上的连接消失。
3. `npm test` 全过。
