## 1. 可视化断言和提取变量（session1）

### 要解决的问题

现在断言和「把 token 存进环境」都要写 JavaScript 脚本。测试同事、前端同事多数不会写，也记不住 `pm.*` 的写法。

### 用户看到的样子

**接口标签页加一个「断言」页签**（放在 Scripts 前面），上下两张表：

1. **断言**，每行：启用勾 · 检查什么 · 字段 / 名称 · 比较方式 · 期望值 · 删除。
   - 检查什么：状态码、响应时间（毫秒）、响应头、JSON 字段、响应文本。
   - 字段 / 名称：响应头填头名；JSON 字段填路径（`data.list[0].id`，也接受 `$.data.id`）；状态码、响应时间、响应文本不用填。
   - 比较方式：等于、不等于、大于、小于、包含、不包含、存在、不存在、为空、不为空、匹配正则、类型是（string / number / boolean / object / array / null）。
     按「检查什么」只列有意义的（状态码不给「包含」，存在 / 不存在只给响应头和 JSON 字段）。
   - 期望值：「存在」「为空」这类不用填。值里可以写 `{{变量}}`。
   - 表格下面一个「+ 添加断言」，以及常用的一键添加：「状态码是 200」「响应时间 < 1000ms」「code 等于 0」。
2. **提取变量**，每行：启用勾 · 从哪里取（JSON 字段 / 响应头 / 响应文本里的正则第 1 组） · 路径 / 头名 / 正则 · 存到（环境 / 项目） · 变量名 · 删除。
   - 存到「环境」时没选环境（或者选的是内置 Mock 环境）：提示「没有选环境，这个变量没有保存」，记到结果里，不报错。

**响应面板的 JSON 视图**：在某个字段上右键（或悬停出现的小菜单）：
- 「为这个字段加断言」→ 在断言表里加一行：JSON 字段 · 这个路径 · 等于 · 当前值；
- 「提取为变量」→ 在提取表里加一行：JSON 字段 · 这个路径 · 存到环境 · 变量名默认是字段名。
- 加完切到「断言」页签并高亮新加的那行。接口变成「有未保存的修改」。

**结果**：断言结果和脚本的测试结果显示在同一个「测试结果」里，名字自动生成（「状态码 等于 200」「data.token 不为空」），
来源标「断言」。提取的变量在控制台里输出一行「已提取 token = eyJ...（前 20 个字）」。批量运行自然带上。

### 数据

- `apis.extra.assertions`：`[{ id, enabled, source, path, op, value }]`
  - `source`：`status` | `time` | `header` | `json` | `text`
  - `op`：`eq` | `ne` | `gt` | `lt` | `contains` | `notContains` | `exists` | `notExists` | `empty` | `notEmpty` | `regex` | `type`
- `apis.extra.extracts`：`[{ id, enabled, source, path, scope, name }]`
  - `source`：`json` | `header` | `regex`；`scope`：`environment` | `project`
- DTO 顶层多给 `assertions`、`extracts`；保存接口接受，合并进 `extra`。
- 发送用的 spec 里也带上这两项（像 `scripts` 一样：标签页里没保存的修改也要生效）。

### 怎么执行

- 在 `lib/send-core.js` 里，**拿到响应之后、跑「响应后」脚本之前**执行（这样脚本里能用到刚提取的变量）。
  取消了、没有响应时不执行（和 `runTest` 一样的条件）。脚本开关（`options.scripts === false`）关掉时也不执行 —— 断言就是一种不用写代码的脚本。
- 断言结果推进 `state.tests`：`{ name, passed, error?, source: '断言' }`，和脚本的测试结果同一个形状（看 `lib/scripts/runner.js`）。
  只有断言、没有脚本时 `result.scripts` 也要有（现在是 `scriptsRan` 为真才挂，注意这个条件）。
- 提取结果写进 `state.variables.environment` / `state.variables.project` 的 `set`，并同步到 `scopes`（脚本读得到）。
  后面服务端的 `writeBackVariables` 会照常把它们存库 —— **保密变量也照样走 `secrets.applyChange`**，不用另做。
- 期望值里的 `{{变量}}` 用这次请求最终的变量表替换。
- JSON 路径解析写成纯函数，放 `lib/assertions.js`（断言判定 + 路径取值 + 提取都在这里），`send-core` 只负责调用。
  路径取不到值就是「不存在」；数字比较时两边都转数字，转不了就算不通过并写清原因（「期望值不是数字」）。
- 响应体太大（超过 5MB）时 JSON 字段类断言不解析，给不通过并提示「响应太大，没有解析」。
- 大数字：解析响应 JSON 时用 `JSON.parse` 的第三个参数保留超出安全范围的整数原文（`lib/openapi-export.js` 的 `keepHugeIntegers` 有现成写法），
  不然「id 等于 12345678901234567890」永远不通过。

### 其他

- 导出 JSON：断言和提取放进导出文件里自己的字段，导入时读回来。
- 分享文档、导出 OpenAPI 不包含断言。

## 2. 响应字段说明（session2）

### 要解决的问题

文档里只有示例响应，前端拿到 `{"code":0,"data":{"st":1}}` 不知道 `st` 是什么意思。

### 用户看到的样子

- **接口标签页加一个「响应说明」页签**：一张树形表格：字段路径（按层级缩进）· 类型 · 说明 · 必有（勾选）。
  - 顶部「从示例生成」：选一个示例（默认 Mock 正在用的那个），按它的 JSON 结构列出全部字段。
    已经写过说明的字段**保留说明**；示例里没有了的字段标灰色「示例里已经没有」，可以一键清掉。
  - 数组的元素写成 `list[]`（`data.list[].id`），不按下标展开。
  - 说明列直接编辑，改了算接口有修改（走「保存」）。
  - 也可以手动加一行（填路径）。
- **分享文档**：每个接口的示例下面加「响应字段」表格（字段 · 类型 · 说明）。没写过说明的接口不显示这一块。
- **导出 OpenAPI**：响应 schema 里的属性带上 `description`（按路径对上）。
- **导入 OpenAPI**：schema 里的 `description` 读进响应说明（以后从 Swagger 导入就自带字段说明）。
  「从 OpenAPI 同步更新」时：文档里有说明、本地没写的补上；本地写过的不覆盖。

### 数据

- `apis.extra.responseFields`：`[{ path, type, desc, required }]`，`path` 形如 `data.list[].id`。
- DTO 顶层多给 `responseFields`；保存接口接受，合并进 `extra`。
- 从示例生成字段树写成纯函数（前端 `utils/` 里一份即可，后端导入 / 导出各自按路径对说明）。

## 3. 跨项目复制 / 移动（session2，第 2 节之后）

### 要解决的问题

接口只能在项目内拖动。想把一组接口给另一个项目用、或者拆项目、或者拿一个现成项目当模板新建，现在只能导出再导入。

### 用户看到的样子

- 接口、目录右键：「复制到其他项目…」「移动到其他项目…」。弹窗：选目标项目（只列你在里面是 editor 及以上的项目，不含当前项目）→ 选目标目录（目录树，默认根目录）→「复制」/「移动」。
  完成后提示「已复制 x 个接口到 项目 B / 目录 C」，带一个「去看看」按钮（切到那个项目并定位）。
- 左上角项目名下拉：「复制为新项目…」→ 填新项目名（默认「原名 副本」）→ 复制整个项目：目录、接口、示例、Mock 期望、环境、项目变量、
  公共请求头、项目鉴权和脚本。**不复制**：成员（新项目只有你一个 owner）、历史、分享链接、评论、保密值（保密变量的名字在，值是空的）。
- 移动 = 复制到目标 + 原来的放进回收站（这样移错了能从回收站找回来）。弹窗里写清楚：「移动后，原项目里的这些接口会放进回收站。评论不会跟着移动。」

### 怎么做

- 复制的核心可以复用回收站：`lib/trash.js` 的 `captureFolder`（`delete` 模式）/ `captureApi` 收集原始行，
  `restoreNodes` 换新 id 插回去 —— 把它改成能指定「插到哪个项目、哪个父目录」，回收站恢复和跨项目复制共用一份。
  **跨项目时**原始行里的 `project_id` 要换成目标项目；Mock 期望引用的示例 id 照恢复的逻辑跟着换。
- 接口：
  - `POST /apis/:id/copy` 、`POST /folders/:id/copy`：`{ projectId, folderId?, move?: boolean }`。
    权限：源项目 viewer（复制）/ editor（移动）；目标项目 editor。一个事务里做完。
  - `POST /projects/:pid/duplicate`：`{ name }`，权限 viewer（能看就能复制一份给自己），返回新项目。
- 新项目的 slug、创建人、owner 按现有「新建项目」的逻辑来（看 `lib/api/projects.js`）。
- 客户端里（网关）全在本机库上做，同步照常把新数据推上去；目标项目必须是本机能看到的。

**几个实现上的决定（审阅时重点看这几处）：**

1. **`lib/openapi-export.js` 加了一条兜底：示例不是合法 JSON 时，按字段说明拼 schema 树。**
   导入进来的示例是 mock 模板（`{{@repeat(3)}}` 这种指令），`JSON.parse` 不认，
   按示例推出来的 schema 只有一个 `{ type: 'string' }` —— 说明根本没地方贴，
   「导入带说明 → 导出还带说明」这条链就断了。所以：**示例是 JSON 就按示例推结构、
   把说明贴上去**（说明里没写的字段也保留）；**不是 JSON 就按说明拼**（只出现说明里写过的路径）。
   两条路都验过。
2. **导出时把「必有」也标进 `required`**（计划里只写了 description）。不标的话，
   「必有」这一列导出去就丢了，而它和说明一样是给对接方看的信息。
3. **`responseFields` 和「状态 / 负责人」写在同一个 extra 合并块里**（`lib/api/tree.js`）：
   分成两块各自 `patch.extra = ...` 的话，后一块会用「读 api.extra 时那份旧值」
   把前一块盖回去。`lib/openapi-sync.js` 里也是同一个道理（快照 + 说明合成一份再写）。
4. **「从示例生成」空数组不列字段**：没有元素就不知道里面长什么样，硬写一个 `list[]`
   只是噪音（要的话手动加一行）。
5. 生成是**补齐不是覆盖**：已经写过说明的字段保留说明 / 类型 / 必有；示例里没有了的字段
   留着并标灰（自动删掉用户写过的东西太狠），要清有一键按钮。
