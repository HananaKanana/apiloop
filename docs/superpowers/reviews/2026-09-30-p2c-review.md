## 建议修

### S1. 会话状态搬到新 key 之后，之前建好的闭包里记的还是旧 key

- **位置**：`web/src/stores/ws.js` 中的 `startEvents` / `scheduleRetry`。`stale()` 用 `readers.get(key)` 来判断，重试计时器的回调里调用的是 `startEvents(key, state)`，这两处用的都是创建闭包时那个**旧的 key**。
- **推演**：「保存到目录」之后，`move` 已经把 `readers`、`timers` 都挪到了新 key 下，但闭包里的判断仍然按旧 key 来：
  - 已经连着的事件流一旦断开，`stale()` 会返回 true，所以**不会自动重连**；
  - 如果搬的时候恰好有一个重试计时器在等待，它触发之后会在**旧 key** 下开一条新的事件流。之后关闭标签页时，`closeFor(新 key)` 关不到这条流，要等服务端的会话被销毁之后，它才会断开。
- **修法**：闭包里不要记住 key，改为每次从 state 上读取当前的 key：在 state 上存一个 `state.key`，`move` 的时候同步更新它；`stale`、重试、`handleEvent` 都读 `state.key`。

## 0e2b895 补审

- **B4（要修，数据会丢）**：`EnvTab` 用 `watch(env, resetDraft)` 灌草稿。`envs.create()` 和 `envs.remove()` 内部都会调 `load()`，把 `environments` 整个换成新对象，于是**每个打开着的环境标签页**都会触发 `resetDraft`，没保存的修改被悄悄清掉，未保存圆点也跟着消失。复现：在环境 A 的标签页里改一个值、先不保存 → 在侧栏新建一个环境（或复制、删除另一个环境）→ 回到 A，改动没了。
