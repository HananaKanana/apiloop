## 必修

### M1. 旧配置导入不是原子操作，中途失败会永久留下一个空项目

- **位置**：`lib/legacy-import.js:139-176`
- **现象**：先建项目（第 4 步）、再灌数据（第 5 步）、最后记录已导入（第 6 步），三步是分开的事务。
  - 第 5 步抛错时，错误被吞进 warnings，第 6 步照样执行。
  - 进程在第 4 步和第 5 步之间被 Ctrl+C 打断时，第 6 步不执行，但下次启动在第 1 步就会凭 `source_dir` 找到这个空项目并直接返回。
  - 两种情况的结果一样：**项目永远是空的，而且再也不会重新导入**。文件头注释里「下次启动会从失败的边界重新走」的说法不成立。
- **实测**：让 `addMany` 抛错后，第一次调用返回 `warnings: ['导入接口失败：boom']`；第二次调用 `importedFrom: null`，项目里 0 条接口。
- **修法**：
  1. 在 `routes-store.js` 里把「route 落成 folder + api + 示例」的逻辑提成一个模块级、**不开事务**的函数：`insertRoutes(handle, projectId, { groups, routes })`。其中 groups 按顺序建顶层 folder，routes 用 `keepId: false` 规范化后落库。门面里的 `addMany`、`replaceAll`、`insertRoute` 改为在自己的 `write()` 里调用它。
  2. `importLegacyDir` 的第 4、5、6 步合进**同一个** `handle.transaction(fn, { projectId: null })`：建项目 → 加 owner → `insertRoutes` → 写 `legacy_imports`。任何一步抛错就整体回滚，并把错误抛给调用方。`command.js` 负责打印错误，并按「没有旧配置」的情况继续启动。
  3. 同步改正文件头的注释。

### M2. `/mock/` 后面跟非法百分号编码时返回 500，并暴露堆栈

- **位置**：`lib/mock-host.js:36`，`decodeURIComponent(match[1])`
- **实测**：`GET /mock/%E0%A4%A/x` 返回 500，响应里带 `URIError: URI malformed` 的堆栈。
- **修法**：解码失败时 `parseMockPath` 返回 `null`，把这种请求当成普通路径交给根项目处理。

## 建议修（这一轮一起改掉，都很小）

- **S1. `mock user reset-password` 没有清掉该用户的旧会话。**
  - 位置：`lib/command.js` 的 `resetPassword`。
  - 问题：重置密码往往是因为怀疑密码泄露，旧会话必须失效；管理台接口里的重置已经这样做了，命令行版本没有。
  - 修法：在同一个事务里调用 `sessionsRepo.removeByUser`。另外那行手动 emit 的 `change` 事件没有任何作用，删掉。
- **S2. `admin.js` 在没传 `handle` 时直接跳过登录校验。**
  - 位置：`lib/admin.js`，`if (handle) {...}`。
  - 问题：现在的调用方都传了 handle，但这种写法是「出错就放行」，以后有人漏传，管理台接口就完全不设防。
  - 修法：没有 handle 就直接 `throw`。
- **S3. `store.stopWatching()` 会停掉整个 handle 的轮询，影响同一个 handle 上的所有项目。**
  - 位置：`lib/routes-store.js:616`。
  - 问题：计划里约定它只摘掉本 store 自己的订阅。
  - 修法：改成空操作，并加注释说明「轮询由启动流程通过 `handle.stopPolling` 管理」；`test/routes-store.test.js:262` 相应改为调用 `handle.stopPolling()`。
- **S4. `--project` 找不到时，本应显示「（一个都没有）」的提示永远不会出现。**
  - 位置：`lib/command.js` 的 `resolveRootProject`。
  - 原因：`a + b.join(', ') || '（一个都没有）'` 的运算顺序不对，`||` 永远拿不到左边的空串。给 `join(...) || '...'` 这部分加上括号。
- **S5. `mock user add` 没有校验用户名格式。** 和接口一样，用 `^[a-zA-Z0-9_.-]{2,32}$` 校验，否则命令行能建出管理台接口不认的用户名。

## 遗留问题（P0 就有，不是 P1 引入的，顺手修）

- **L1. 管理台导入超过 100KB 的 OpenAPI 会失败，返回 413。**
  - 原因：`command.js:164` 全局挂的 `bodyParser.json()` 默认上限是 100KB，而它在 `admin.api` 自己的 `express.json({ limit: '4mb' })` 之前执行。
  - 修法：把两行全局 body parser 挪到管理台挂载**之后**，也就是只对 mock 和 `router.js` 生效。`test/server.test.js:32` 的挂载顺序同步调整。
