### B1：「云端不发送」的黄色提示永远不会出现

- 云端的 409 `SERVER_SEND_DISABLED` 是在 NDJSON 开始之前返回的，`stream.js` 把它转成 `Error`，`tabs.sendRequest` 的 `catch` 只存了 `tab.sendError = err.message`。状态码和 `code` 都在 `err.status`、`err.data` 上，没有存下来。
- `ResponsePanel` 判断的是 `result.error.code === 'SERVER_SEND_DISABLED'`，这个值永远不存在。所以实际显示的还是红色的 `sendError`。好在发送按钮本来就是灰的，这只是兜底路径。
- **修法：** `catch` 里同时存 `tab.sendErrorCode = (err.data && err.data.code) || ''`（`emptyLive` 里加上初始值），`ResponsePanel` 改成按 `tab.sendErrorCode` 判断；是 `SERVER_SEND_DISABLED` 时不显示红色的 `sendError`。

### B2：`-G` 加 `-d` 时，方法应该是 GET

`curl -G https://a.com/search -d q=hello` 解析出来是 POST。数据已经正确地变成了查询参数，但方法没跟着变。规则：有 `-G` 时，没有显式写 `-X` 就是 GET（有 `-I` 时是 HEAD）。

### B3：Windows cmd 格式（Chrome「复制为 cURL (cmd)」）完全解析错

输入（单行、LF 续行、CRLF 续行三种都试过，结果一样）：
```
curl ^"https://example.com/api/x?a=1^&b=2^" -H ^"accept: application/json^" --data-raw ^"^{^\^"k^\^":^\^"v w^\^"^}^"
```
现在的结果：地址是 `http://"https//example.com/api/x`，请求头是 `"accept: `，请求体被截断。

**原因：** cmd 格式是**两层**：
1. cmd 先处理 `^` 转义（`^"` → `"`，`^&` → `&`，`^{` → `{`，行尾 `^` 续行）；
2. 程序再按 Windows 的规则拆参数：`"` 是字符串的开始和结束，`\"` 是字面上的引号，`\\` 后面紧跟 `"` 时按反斜杠规则处理。

`scanCmd` 把两层合成了一层，把 `^"` 当成了字面上的引号字符，所以引号从来没有起「包字符串」的作用。

**修法：** 拆成两步：先整段去掉 cmd 的 `^` 转义和续行，再按 Windows 的参数规则切词。修完以上输入的期望结果：
- POST，`https://example.com/api/x`，查询参数 `a=1`、`b=2`；
- 请求头 `accept: application/json`；
- `body.raw` 是 `{"k":"v w"}`。

### B4：cURL 解析出的地址不带查询串，地址栏一编辑，查询参数就全没了（**计划写错了，审阅方的责任**）

- 计划里我写的是「`url` 是 origin + pathname，查询串放进 `params.query`」（照搬了 HAR 导入的做法）。但这个页面的约定是**地址栏带着查询串，和查询参数表双向同步**（`RequestTab` 的 `syncFromUrl` / `onQueryChange`）。
- 结果：粘贴或导入 cURL 之后，地址栏里看不到 `?size=10&page=1`；用户在地址栏里改任何一个字，`syncFromUrl` 按地址重新解析，所有启用的查询参数行都被清掉。
- **修法：**
  1. `parseCurl` 的 `url` 改成 `origin + pathname + search`（带查询串，不带 `#`），`params.query` 照样填；
  2. `tabs.specFromApi` 打开接口时做一次规整：如果 `api.url` 里没有 `?`，而启用的查询参数行不为空，就按 `onQueryChange` 同样的规则把它们拼进地址。这样 HAR、Postman 导入的老数据，在地址栏里也能看到查询串。这只影响显示，不改库里的数据。
- 审阅方同时修了服务端拼地址的一个老问题，见下面的 b2fbfb7。修完之后，「地址带查询串」和「地址不带、只有表格」两种存法发出去都是对的。

### B5：JSON 美化会改坏超过 16 位的整数

- `{"big": 12345678901234567890}` 美化后变成 `12345678901234567000`。`JSON.parse` 转成双精度浮点数，丢了精度。后端常用的长整型 ID（比如 19 位的雪花 ID）一美化就被悄悄改掉，发出去的请求是错的，很难察觉。
- 计划里只想到了 `1.0 → 1`，没想到大整数，这也是审阅方的疏漏。
- **修法（推荐）：** 不再用 `JSON.stringify` 输出，改成**只调整空白的重新排版**：
  1. 先用现在的办法（变量占位 + `JSON.parse`）**只做校验**，拿到错误位置；
  2. 校验通过后，按词法逐个读出词（字符串、数字、`true`/`false`/`null`、`{{变量}}`、标点），原样输出每个词，只在 `{ [ , :` 前后加换行和缩进。

  这样数字、字符串里的 `\uXXXX` 转义、变量都**一字不改**，按钮提示里「数字会按标准格式输出」那句也可以删掉。

### 小问题（顺手改）

- **N1：** 文本里本来就有 `__APILOOP_VAR_0__` 这样的字符串时会被误替换：`{"s":"__APILOOP_VAR_0__","v":{{x}}}` 美化后 `s` 变成了 `{{x}}`。按 B5 的改法（只用来校验）这个问题自然消失；如果保留占位，占位的前缀里要加一段确认文本里不存在的随机串。
- **N2：** `CodeEditor.vue` 里 `const theme = EditorView.theme({  '&': {` 被合成了一行，恢复换行。
- **N3：** `formatKeyHandler` 只在编辑器创建时、语言是 json 才加。在请求体里把语言从「文本」切到 JSON 之后，快捷键要能生效。确认一下语言切换时，扩展有没有重新配置。

### 确认没问题的

- **判断「是不是网关」：** 看状态码，并且要求返回的是带 `version` 的 JSON。直接打开云端时返回 HTML 也不会误判。根路径下没匹配到的请求，mock 日志不记，所以不会每次打开页面都留一条垃圾记录。
- **连接状态、云端地址对话框、版本横幅**（存在 `sessionStorage`，按版本组合记）、**局域网授权提示框**、**「未保存历史」标签**，都按计划做了。
- **cURL：** 附录里的三段解析结果和期望一致。连写参数、`--request=`、`-u`（密码里带冒号）、`--json`、`-F` 文件行、不带 Content-Type 的 `-d`、`-o` / `-m` 这类带值参数、不认识的参数、`-d @文件`、`-I`、双引号里的转义、不是 curl 的文本，都对。
- **地址栏粘贴：** 在捕获阶段拦截，抢在 CodeMirror 之前；只有以 `curl ` 开头的内容才处理，普通粘贴照旧。
- **JSON 美化：** `{{变量}}` 在值的位置、在字符串里、在数组里、整段就是一个变量、变量名里带空格或 `$`，都原样保留；出错时给出「第 N 行第 M 列」；空文本返回空。快捷键按物理键位（`event.code`）判断，避开了 Mac 上 ⌥F 会输入特殊字符的问题。

## 审阅方顺手修的：b2fbfb7（服务端拼地址，查询参数被发两遍）

- 审 B4 时端到端实测（临时起一个 apiloop，用 `/send` 发给回显服务器）：页面上地址栏带着 `?a=1&b=2`、表格里也有这两行时，目标实际收到的是 `/x?a=1&b=2&a=1&b=2`。原因是 `buildUrl`「两边都发」，而页面上两边永远是同步的，所以**每个带查询参数的请求，参数都发了两遍**。这是个老问题。
- 改成：有查询参数行（启用的、停用的都算）时，以行为准，去掉地址里的查询串和 `#片段`；一行都没有时，照旧用地址自带的（脚本改过地址时会清空查询参数行）。
- 执行器、云端发送、WebSocket、网关本机发送都走这一个函数。`npm test` 71/71。
