# 本地网关 G1：完整的本机发送（服务端）实施计划

> 给 session1。只用 `git commit -m ... -- <文件>` 提交自己的文件，不推送。**不写新测试**；既有测试（`npm test`，71 个）必须全部通过——它们就是这次拆分的回归网，**测试一行都不改**。

**目标：** 网关上发出去的请求和以前在云端发的完全一样：变量、继承的鉴权、前置/后置脚本、`pm.sendRequest`、Cookie、代理、上传的文件、历史、脚本写回变量，全都生效。区别只是**在用户的电脑上发出**。WebSocket 调试会话也挪到本机。

**设计稿：** `docs/design/2026-10-01-local-agent.md` 第 3.3 节。G0 的审阅记录：`docs/superpowers/reviews/2026-10-01-gateway-g0-review.md`。

## 全局约束

- **读库、写库留在云端，执行挪到网关。** 一次发送 = 云端 `prepare`（只读库）→ 网关执行 → 云端 `record`（只写库）。
- **云端自己发送时（`/send`、`/send/stream`）走的也是同一条链：** `prepare → 执行 → record`，在同一个进程里串起来。这样两种发送方式只有一份实现，现有测试就能证明拆分没改坏行为。
- `prepare` 返回的东西必须**能 JSON 序列化**：不能有函数、jar 对象、AbortController。网关拿到之后自己重建这些对象。
- 历史的脱敏（`forHistory`）、变量写回时的角色检查（只有 editor 才写），**只在云端做**。网关传上来的结果是原始结果。
- 根目录 `package.json` 不加依赖。

## 审阅重点

1. **行为一字不变：** 71 个既有测试一行不改、全部通过，就是证据。另外，用 `--server-send` 的方式（云端自己发），和经网关发，同一个请求得到的 `ExecResult` 结构必须相同（审阅方会对比）。
2. **`prepare` 不泄露别的项目、别的用户的东西：** 环境、接口必须属于这个项目（沿用现在的检查）；Cookie 只取「当前用户 × 当前项目」；文件只能是这个项目的上传目录和 `sourceDir` 里的。
3. **`record` 不能被拿来越权：** viewer 传上来的变量修改**不落库**（和现在一样）；`record` 里的 `apiId`、`environmentId` 同样要校验属于这个项目。
4. **网关的临时文件：** 上传的文件在本机落成临时文件发送，发完（成功、失败、取消）都要删掉。
5. **网关断开的各种情况：** 云端连不上时，`prepare` 失败要给出明确的错误事件；请求已经发出去但 `record` 失败时，页面照样拿到结果，`end` 事件里 `historyId` 为 `null`，并带上 `recordError`。

### Task 1：把 `lib/api/send.js` 拆成三段

**文件：**
- 新建 `lib/send-core.js`：执行那一段。云端和网关都用它，不碰数据库，不碰 `req` / `res`。
- 修改 `lib/api/send.js`：`prepareSend` 拆成「读库得到可序列化的 `prepared`」+「由 `prepared` 重建执行上下文」；`finishSend` 改成 `record`。
- 视需要修改 `lib/cookies.js`（或 Cookie jar 所在的文件）：加上 jar 的序列化和「增量」计算。

**接口：**
- `prepare(req, project, body) → prepared`（云端，`lib/api/send.js` 内部函数），`prepared` 的形状：
  ```js
  {
    project: { id, name },          // 只给执行需要的字段
    role,                           // 当前用户在项目里的角色
    apiId, apiName, environmentId,
    spec,                           // 已经继承好鉴权的 spec（inheritAuth 之后）
    requesting,                     // 写历史用的原始请求（和现在的 context.requesting 一样）
    options: { timeoutMs, followRedirects, scripts, cookies, proxy },
    scopes: { project, folders, environment },   // variables.fromRows 之后的普通对象
    steps: { prerequest, test },                 // collectSteps 的结果
    cookies: [ ...当前用户 × 当前项目的 cookie 行 ] | null,   // options.cookies === false 时为 null
    proxy: <proxySettings.get 的结果> | null,
    files: { '<src>': '<base64>' }               // spec 里引用到的文件，见 Task 3
  }
  ```
- `sendCore.run(prepared, hooks) → Promise<{ result, changes }>`（`lib/send-core.js`）
  - `hooks`：`{ signal, onHead, onChunk, fileRoots }`，流式回调和现在 `/send/stream` 用的一样；
  - 内部做现在 `prepareSend` 后半段 + `finishPrepare` + 脚本 + 执行 + 测试脚本 + `scriptFailureResult` 这些事；
  - `changes` 的形状：`{ scriptState, cookies: { set: [row...], removed: [{ domain, path, name }...] } | null }`。`scriptState` 就是现在 `writeBackVariables` 读的那一份。
- `record(req, project, payload) → { historyId, scripts }`（云端）
  - `payload`：`{ apiId, environmentId, requesting, resolvedAuth, result, changes }`；
  - 做现在 `finishSend` 做的事：写回变量（**角色检查在这里**）、应用 Cookie 增量、按 `forHistory(result, resolvedAuth)` 脱敏后写历史；
  - 返回的 `scripts` 就是现在 `result.scripts`（含 `variables.persisted`）。
- `/send` 和 `/send/stream` 改成 `prepare → sendCore.run → record` 串起来，**返回给前端的东西一个字节都不变**。

- [ ] 拆完跑 `npm test`，71 个全过，测试文件一行不动。
- [ ] 提交：`refactor(send): 发送拆成 prepare / 执行 / record 三段，执行部分移到 lib/send-core.js（G1）`

### Task 2：云端的 `prepare` / `record` 接口，以及云端发送开关

**文件：** `lib/api/send.js`、`lib/api/ws.js`、`lib/admin.js`（`/meta`）、`docker-compose.yml`

**接口：**
- `POST /projects/:pid/send/prepare`（viewer 起）：请求体和现在 `/send` 的一样（`request`、`apiId`、`environmentId`、`options`），返回 `{ prepared }`。
- `POST /projects/:pid/send/record`（viewer 起）：请求体是 `record` 的 `payload`，返回 `{ historyId, scripts }`。
- `POST /projects/:pid/ws/prepare`（viewer 起）：WebSocket 会话要的东西：解析好变量的 `url`、合并好鉴权和 Cookie 的 `headers`、`protocols`。也就是把现在 `/projects/:pid/ws` 里建连接之前的那一段拆出来。
- **云端发送开关：** 环境变量 `APILOOP_SERVER_SEND`，值为 `0` 时关闭以下接口，返回 409 `{ error: '云端不发送请求，请从本机的 apiloop 打开', code: 'SERVER_SEND_DISABLED' }`：
  - `/send`、`/send/stream`；
  - `/projects/:pid/ws`（建 WebSocket 会话）。
  - **不设置时默认打开**（现有测试、本机直接 `apiloop web` 的用法都不受影响）。
- `GET /meta` 多返回一个 `serverSend: true|false`。
- `docker-compose.yml`：`environment` 里加 `APILOOP_SERVER_SEND: ${SERVER_SEND:-0}`，并写一行注释说明「云端部署默认不发送，请求由本机网关发」。

- [ ] `npm test` 全过。
- [ ] 提交：`feat(send): 云端提供 send/prepare、send/record、ws/prepare；APILOOP_SERVER_SEND 控制云端是否发送（G1）`

### Task 3：网关的完整发送

**文件：** `lib/gateway/index.js`（可以拆出 `lib/gateway/send.js`、`lib/gateway/ws.js`）

**本机发送 `POST /__admin/api/projects/:pid/send/stream`：**
1. 带着浏览器的 Cookie（原样转发）调云端的 `send/prepare`。云端返回 4xx 时，原样把状态码和错误转给页面（还没开始写 NDJSON）；连不上云端时返回 502 `{ error: '连不上云端（<地址>）：…' }`。
2. `prepared.files` 落到 `<dataDir>/tmp/<随机目录>/` 下（保持原来的相对路径），这个目录作为唯一的 `fileRoots` 传给 `sendCore.run`。**发完一定删掉**：成功、失败、浏览器取消都要删，用 `finally`。
3. `sendCore.run` 流式写 `head` / `chunk` 事件，和现在完全一样。
4. 执行完调云端的 `send/record`，拿到 `historyId` 和 `scripts`，合进 `result`，再写 `end` 事件。
   - `record` 失败（云端连不上、返回错误）：`end` 事件照样写，`historyId: null`，`result.recordError = '历史和变量没有保存到云端：…'`。
5. **局域网授权提示（G0 审阅 N5）：** 不再只看 URL 里写的是不是私有 IP，而是从错误信息里取出实际连接的 IP（形如 `connect EHOSTUNREACH 192.168.17.3:8080`）来判断。
6. 去掉 G0 的 `gatewayRawSend` 标记。

**`prepared.files` 的约定（云端那一侧在 Task 2 里做）：**
- 只收集 spec 里实际引用到的文件：formdata 的文件行、binary 的 `file.src`；
- 路径必须在这个项目的上传目录或 `sourceDir` 里（沿用现在执行器 `fileRoots` 的判断）；
- 总大小超过 50MB 时，`prepare` 返回 413 `{ error: '要上传的文件太大（超过 50MB），暂时不能从本机发送' }`。

**WebSocket 调试会话：**
- `POST /__admin/api/projects/:pid/ws` → 网关调云端 `ws/prepare`，**在本机**用 `lib/ws-sessions.js` 建连接；
- `GET /ws/:id/events`、`POST /ws/:id/send`、`DELETE /ws/:id` → 都在网关本机处理，不转发。
- 会话只属于建它的那个浏览器会话：用浏览器 Cookie 里会话令牌的哈希当所有者标识，代替原来的 `userId`。

**脚本里的 `pm.sendRequest`：** 在网关里执行，自然也是从本机发出的，确认一下就行。
