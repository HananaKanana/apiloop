# P2c：界面整体打磨（参考 Postman） 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **本项目约定**
> - **不写新测试**，也不装浏览器驱动做验证、不截图比对；既有的 `npm test` 必须全部通过。界面效果由用户确认。
> - **只提交，不推送**；只提交自己的文件，不要用 `git add -A`、`commit -a`、`git stash`。
> - 每个 Task 结束都要执行 `npm run build:web`，并把 `lib/web` 和源码放在同一个提交里。

**来源**：用户反馈，界面整体要参考 Postman 调整，比如缩进、`{{变量}}` 变色、输入时能给出提示。截图里能看到的问题：
- 请求区的页签和内容区紧贴着左边缘，没有内边距；
- 参数表格末尾那行空行的复选框是勾选状态，看起来像一条已经启用的空参数；
- 地址栏里的 `{{host}}` 和普通文字看起来一模一样；
- 输入 `{{` 时没有变量补全；
- 「以下变量未定义」这条提示是关于请求的，却出现在响应区；
- 状态码、耗时、大小和响应区的页签分成了两行。

**执行者**：session2。排在 2.0.0 联调之后；这是用户直接提出的要求，所以作为 2.0.0 的一部分来做。
**文件范围**：`web/**`、`lib/web/**`。**不改后端**。

## 全局约束（视觉规范，所有 Task 都按这个来）

- **间距**：内容区统一使用 `12px 16px` 的内边距；页签条左边留出 16px；表格行高 32px；目录树行高 28px。
- **字号**：界面正文 13px；表头和辅助说明 12px，使用 `opacity: 0.6`；代码和响应体用等宽字体，12px。
- **请求方法的颜色**：新建 `web/src/utils/method.js`，导出 `methodColor(method)`，**全站只用这一份**。目录树的方法标签、地址栏的方法下拉、顶部标签页的标题，都从这里取颜色。

  | 方法 | 颜色 |
  | --- | --- |
  | GET | `#0cbb52` |
  | POST | `#ffb400` |
  | PUT | `#097bed` |
  | PATCH | `#623ce4` |
  | DELETE | `#eb2013` |
  | HEAD / OPTIONS | `#6b7280` |
  | WS | `#0ea5a4` |
  | 其他 | `#6b7280` |

  方法标签的样式：只有文字颜色，没有边框和底色；粗体，10–11px；宽度固定 44px，右对齐。这样各行的接口名能对齐。
- **变量的颜色**：通过主题变量定义，亮色和暗色主题下都要清晰可读。
  - `{{已定义}}`：绿色 `#0cbb52` 系；
  - `{{未定义}}`：红色 `#eb2013` 系；
  - `{{@mock 占位符}}`：紫色 `#623ce4` 系。

  都带一层浅底色，并加 2px 圆角。
- **状态码的颜色**：2xx 绿色、3xx 蓝色、4xx 橙色、5xx 红色、出错灰色。
- **暗色主题**：所有新加的颜色都要在暗色主题下检查可读性。暗色下使用对应的亮一些的色号，不能写死一个只在白底上好看的颜色。

## 审阅重点

1. **变量高亮和补全不能影响输入**：
   - 换成 CodeMirror 之后，地址栏必须是单行的：粘贴带换行的内容时，换行要被去掉；
   - 回车就是发送；**补全列表打开时，回车用来选中补全项，不发送**；
   - 光标、选中、撤销都正常；
   - 中文输入法组字的过程中，不能打断，也不能触发发送或补全。
2. **变量的解析和后端一致**：前端判断变量「已定义」时，优先级是「项目 < 目录（从外到内）< 环境」，和契约第 5 节相同。悬停提示和补全列表里显示值和来源，`secret` 变量的值要遮住。
3. **性能**：一个表格里有几十行参数时，编辑不能卡顿。可以只给「正在编辑、或者包含 `{{` 的格子」挂 CodeMirror，其余格子仍然用普通输入框；具体怎么做由你决定，但要满足这一条。
4. **只读角色**：viewer 下，这些新组件同样是只读的，也不弹出补全。

### Task 2：`{{变量}}` 高亮、补全与悬停提示

- [ ] 新建 `web/src/utils/variables.js`，导出下面两个函数：
  - `resolveScope({ project, folders, folderId, environment }) → Map<name, { value, source, secret }>`：按契约第 5 节的顺序合并变量；`source` 是「项目」「目录「x」」或「环境「x」」这样的文字；
  - `findVariables(text) → [{ from, to, name, kind: 'var' | 'mock' }]`：`{{@xxx}}` 属于 `mock`，其余属于 `var`。
- [ ] 新建 `web/src/components/common/VarInput.vue`：单行的 CodeMirror 6 编辑器。
  - **外观**：和 naive-ui 的小号输入框保持一致，高度、边框、圆角、聚焦时的颜色都一样。
  - **高亮**：用 decoration 给变量上色，颜色按全局约束。
  - **补全**（用户追加的要求）：使用 `@codemirror/autocomplete`。它是 `codemirror` 包自带的依赖，项目里已经有了，不需要新增。
    - 输入 `{{` 之后立即弹出补全列表；继续输入时按名字过滤，前缀匹配优先，其次是包含匹配；
    - 每一项显示三样东西：变量名、值的预览（最多 30 个字符，`secret` 显示为 `••••`）、来源（比如「环境「3.40」」）；
    - 选中之后补全成 `{{name}}`；如果光标后面已经有 `}}`，就不要再补一对；
    - 列表按「环境 → 目录 → 项目」排序，也就是优先显示生效的那个；同名变量只列出生效的那一个；
    - 在 mock 示例编辑器（`CodeEditor`）里，输入 `{{@` 时补全 mock 占位符，数据来自 `/meta` 的 `placeholders`，每一项显示占位符的名字和说明。请求区不补全 mock 占位符，因为发送请求时不会渲染它们。
  - **悬停提示**：鼠标移到变量上时显示提示。已定义的，显示「值（secret 遮住）· 来源」；未定义的，显示「未定义 —— 在环境、目录或项目变量里添加」。
  - **单行**：通过 transactionFilter 把换行去掉。补全列表没打开时按回车，触发 `enter` 事件交给父组件处理；中文输入法组字过程中按回车，不触发这个事件。
  - **属性**：`modelValue`、`placeholder`、`readonly`、`scope`（也就是 `resolveScope` 的结果）。
- [ ] **使用的地方**：
  - 地址栏；
  - 参数、请求头、表单这三类键值表格的「值」这一列，「键」这一列可以不用，性能要求见审阅重点第 3 条；
  - 鉴权里的 token、用户名、密码、key、value；
  - WebSocket 标签页的地址栏。
- [ ] **未定义变量的提示移到请求区**：现在响应区里那条「以下变量未定义」，移到地址栏的正下方，改成一行紧凑的黄色提示。发送之前就要显示，用 `findVariables` 和 `scope` 在前端直接算出来，不用等发送之后。提示里保留「去环境管理」这个入口。响应区里的这条提示删掉。
- [ ] 执行 `npm run build:web`，然后提交：`feat(web): 变量高亮、补全与发送前的未定义提示`。

### Task 3：请求区——页签计数、键值表格、批量编辑

- [ ] **页签标题带状态**，和 Postman 一样：
  - `Params`、`Headers` 后面显示已启用的行数，比如 `Headers (8)`；
  - `Body` 不是 none 时，显示一个小圆点；
  - `Auth` 显示当前的鉴权类型，选了「继承」时显示「继承」；
  - `Scripts` 里有内容时，显示一个小圆点。
- [ ] **键值表格**：
  - 末尾那行空的占位行，**不显示复选框**（截图里它是勾选状态，看起来像一条已启用的空参数），填写之后才出现复选框，并且默认勾选；
  - 表头用 12px 的灰色字；
  - 删除按钮在悬停时才出现；
  - 停用的行，文字半透明。
- [ ] **请求头的名字补全**：请求头表格的「键」这一列，输入时补全常用的请求头名称，比如 `Content-Type`、`Authorization`、`Accept`、`User-Agent`、`Cookie`、`Cache-Control`、`X-Requested-With`。选中 `Content-Type` 后，「值」这一列补全常用的类型：`application/json`、`application/x-www-form-urlencoded`、`multipart/form-data`、`text/plain`。
- [ ] **批量编辑**：表格右上角加一个「批量编辑」切换按钮，切换到一个多行文本框：
  - 每行一条，格式为 `key: value`；
  - 以 `//` 开头的行，表示停用的行；
  - 切换回表格时解析回来，描述字段要保留，找不到对应描述的就留空。
- [ ] 执行 `npm run build:web`，然后提交：`feat(web): 请求页签计数、键值表格打磨、请求头补全与批量编辑`。

### Task 4：响应区——一行式状态栏、可拖动的上下分栏

- [ ] **响应区顶部合并成一行**：左边是页签（Body、Headers、测试结果、控制台、耗时、请求），右边依次是带颜色的状态码、耗时、大小，和 Postman 一样。
- [ ] **上下分栏可以拖动**：请求区和响应区之间加一条分隔线，可以上下拖动，拖动的位置按标签页类型记在 `localStorage` 里，读写都要包在 `try/catch` 里。响应区最少占 120px 的高度。
- [ ] **空状态**：还没有发送过请求时，响应区显示居中的灰色提示：「点击发送，或按 Enter，查看响应」。
- [ ] 执行 `npm run build:web`，然后提交：`style(web): 响应区状态栏与可拖动分栏`。
