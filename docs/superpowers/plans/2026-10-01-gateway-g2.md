# 本地网关 G2：前端（网关状态、cURL 导入重做、JSON 美化）实施计划

> 给 session2。只用 `git commit -m ... -- <文件>` 提交自己的文件，不推送。不写新测试；既有测试（`npm test`）要通过。每个 Task 提交前执行 `npm run build:web`，`lib/web` 一起提交。**不要用浏览器自动化去验证界面**，界面交给用户看。

**目标：**
1. 页面知道自己是「从本机网关打开」还是「直接打开云端」，并给出对应的状态和提示；
2. 重做 cURL 导入：现在的解析器会丢请求头、丢主机、拆散 JSON、乱改路径（下面「问题清单」）；
3. 请求体的 JSON 加「美化」。

**设计稿：** `docs/design/2026-10-01-local-agent.md` 第 4 节。服务端的配套改动在 G1（`docs/superpowers/plans/2026-10-01-gateway-g1.md`），**两边同时做**，接口以本文「依赖的服务端接口」为准。

## 依赖的服务端接口（G1 和 G0 提供，前端按这个写）

- `GET /__gateway/status` → `{ version, cloudUrl, cloudReachable }`。**只有网关上才有这个地址**；直接打开云端时，这个请求会返回 404 或一个 HTML 页面，前端据此判断「不是网关」。
- `POST /__gateway/setup`，请求体 `{ cloudUrl }` → `{ ok: true, cloudUrl }`（必须带 `X-Apiloop: 1`，`client.js` 已经统一带上）。
- `GET /__admin/api/meta` 多一个字段 `serverSend: true|false`（G1 加）。G1 没合进来之前这个字段不存在，**按 `true` 处理**。
- 发送结果（`ExecResult`）里可能出现的新字段：
  - `result.error.localNetworkHint === true`：Mac 第一次访问局域网被系统拦下（G0 已有）；
  - `result.recordError`（字符串）：请求发成功了，但历史和变量没存到云端（G1 加）；
  - 错误码 `SERVER_SEND_DISABLED`（409）：直接打开云端时，云端不发送请求（G1 加）。

## 全局约束

- 视觉沿用 P2c 的规范：主色 `--apiloop-primary`；naive-ui 组件的颜色、边框一律走 `theme-overrides`，不要在样式表里改 `--n-*` 变量。
- `/__gateway/*` 这两个地址**不在** `/__admin/api` 下面，不能用 `client.js` 里那个带前缀的 `request`。在 `web/src/api/gateway.js` 里单独写，同样带上 `CUSTOM_HEADERS`。

## 审阅重点

1. **直接打开云端时**不能因为 `/__gateway/status` 返回 HTML 而报错或卡住：判断要稳（看状态码，以及返回的是不是带 `version` 字段的 JSON）。
2. **cURL 解析：** 下面「cURL 解析要求」里的每一条，审阅方都会拿真实的复制结果去试。
3. **JSON 美化遇到 `{{变量}}`：** `{"id": {{id}}, "name": "{{name}}"}` 美化之后，两个变量必须原样保留，不能被加引号、不能丢。
4. 粘贴 cURL 到地址栏时，**普通地址的粘贴不受影响**。

### Task 2：cURL 导入重做

**问题清单（审阅方用三段真实的「复制为 cURL」实测过，现在的 `lib/importers.js` 的 `curlToRoute` 会这样）：**
1. 丢掉所有请求头（`Authorization`、`Content-Type`、`Cookie` 都没了）；
2. 丢掉主机和端口（`https://192.168.3.40:9091` 只剩路径）；
3. JSON 请求体被拆成一个个字段，嵌套的对象和数组被压成字符串，原来的 JSON 没了；
4. 数字路径段被改成 `:id`（`/users/42` → `/users/:id`）；
5. `$'...'` 写法完全解析错（Chrome 遇到特殊字符时就这么复制），地址变成 `//example.com`，请求体乱码。

根本原因：`curlToRoute` 是给「造 mock 路由」写的，产出的是路由草稿，不是请求。**这次在前端新写一个解析器，产出请求（spec），老的 `curlToRoute` 和 `/import/curl` 不动**（老接口不再被页面调用即可）。

**文件：**
- 新建 `web/src/utils/curl.js`：`parseCurl(text) → { name, method, url, params: { path, query, headers }, body, auth }`，解析失败时 `throw new Error('<给用户看的原因>')`；
- 修改 `web/src/components/importExport/ImportDialog.vue` 的 cURL 页签；
- 修改 `web/src/stores/tabs.js`：`openDraft(folderId, spec?)`，传了 `spec` 就用它代替空请求；
- 修改 `web/src/components/request/UrlBar.vue` 和 `RequestTab.vue`：地址栏粘贴 cURL。

**cURL 解析要求：**
- **切词：**
  - 单引号 `'...'`：里面原样，不处理转义；
  - 双引号 `"..."`：`\"`、`\\`、`\$`、`` \` `` 转义；
  - **`$'...'`**（ANSI-C 写法）：支持 `\n`、`\t`、`\r`、`\\`、`\'`、`\"`、`\xHH`、`\uXXXX`；
  - 行尾的 `\` 续行（含 `\r\n`）；
  - **Windows cmd 的写法**（Chrome「复制为 cURL (cmd)」）：`^` 是转义符，`^"` 表示引号，行尾 `^` 续行。识别方式：文本里出现 `^"` 或行尾的 `^`。
- **参数：**
  - `-X` / `--request`；`-I` / `--head`（方法设为 HEAD）；
  - `-H` / `--header`；`-A` / `--user-agent`；`-e` / `--referer`；`-b` / `--cookie`（变成 `Cookie` 请求头）；
  - `-d` / `--data` / `--data-raw` / `--data-binary` / `--data-ascii`：多个时用 `&` 连起来；以 `@` 开头的（读文件）不支持，抛错说明「请求体来自本地文件 xxx，请导入后手动粘贴内容」；
  - `--data-urlencode`：按 curl 的规则编码后再连起来；
  - `--json`：等于 `--data-raw` 加上 `Content-Type: application/json` 和 `Accept: application/json`（只补空缺）；
  - `-F` / `--form`：变成 form-data 行，`key=@文件` 是文件行（`kind: 'file'`，`src: null`，用户自己选文件），其余是文本行；
  - `-u` / `--user user:pass`：变成 Basic 鉴权（`auth` 的形状照 `lib/api/dto.js` 的 `toAuth`）；
  - `-G` / `--get`：数据变成查询参数；
  - `--url`；
  - 参数和值连写也要认：`-XPOST`、`-H'Accept: */*'`、`--request=POST`；
  - 带值但用不上的参数要连值一起跳过：`-o`、`--output`、`-m`、`--max-time`、`--connect-timeout`、`-w`、`--write-out`、`-x`、`--proxy`、`--retry`、`--cacert`、`--cert`、`--key`、`-T`、`--upload-file`、`-c`、`--cookie-jar`、`-K`、`--config`；不带值的开关直接忽略（`--compressed`、`-k`、`--insecure`、`-L`、`--location`、`-s`、`-S`、`-v`、`-i`、`--http1.1`、`--http2` 等）；
  - 认不出的参数：以 `-` 开头、后面一个词不以 `-` 开头、看起来也不像网址时，当成「带值的参数」一起跳过，并且记进 `warnings`。
- **产出：**
  - `method`：显式写了以显式为准；`-I` 是 HEAD；有请求体或 form 是 POST；否则 GET；
  - `url`：`origin + pathname`，**保留协议、主机、端口**，路径原样（**不改成 `:id`**）；查询串放进 `params.query`（解码后的键值）；没写协议时补 `http://`；
  - `params.headers`：所有请求头原样保留，顺序不变。去掉 `Content-Length` 和 HTTP/2 的伪头（以 `:` 开头的）；
  - `body`：
    - `Content-Type` 含 `json`，或者请求体能被 `JSON.parse`：`{ mode: 'raw', language: 'json', raw: <原文> }`，**原文不改动**；
    - `x-www-form-urlencoded`（含 curl 默认的 `-d` 且没写 Content-Type、内容形如 `a=1&b=2` 的情况）：`{ mode: 'urlencoded', form: [...] }`，键值解码；
    - `-F`：`{ mode: 'formdata', form: [...] }`；
    - 其它：`{ mode: 'raw', language: 'xml' 或 'text', raw }`（`Content-Type` 含 `xml` 就是 xml）；
  - `name`：`<方法> <路径最后一段>`，比如 `POST page`；
  - 另外返回 `warnings: string[]`（跳过的不认识的参数等）。
- **行的形状：** 请求头、查询参数、表单行的字段，照 `lib/api/dto.js` 的 `toRows` / `toFormRows`（`key`、`value`、`enabled`、`desc`，表单多 `kind`、`src`）。

**导入弹窗的 cURL 页签：**
- 粘贴后自动解析（停止输入 300ms 后），下方预览：
  - 方法加完整地址（方法按颜色显示）；
  - 「请求头 N 个 · 查询参数 N 个 · 请求体：JSON / 表单 / 文本 / 无 · 鉴权：Basic / 无」；
  - `warnings` 用灰色小字列出来；
  - 解析失败时显示原因，不弹全局报错。
- 两个按钮：
  - 「在新标签页打开」：`tabs.openDraft(当前选中的目录, spec)`，**不保存**，用户确认后自己保存；
  - 「导入到当前目录」：用 `tree.createApi` 直接建成接口（`folderId` 是当前选中的目录，没选就是根目录），然后打开它的标签页。
  - 只读角色只显示第一个按钮。

**地址栏粘贴 cURL（Postman 的做法）：**
- 在地址栏里粘贴、而且粘贴的内容（去掉首尾空白后）以 `curl ` 开头时：拦下这次粘贴，调 `parseCurl`。
  - 成功：用解析出的 `method`、`url`、`params`、`body`、`auth` 替换当前标签页的请求（名字不变），提示「已从 cURL 填充」；
  - 失败：提示原因，地址栏不变。
- 其它内容的粘贴照旧。

### Task 3：JSON 美化

**文件：**
- 新建 `web/src/utils/jsonFormat.js`：`formatJson(text, indent = 2) → { ok: true, text } | { ok: false, error }`；
- 修改 `web/src/components/request/BodyEditor.vue`（JSON / 文本模式）；
- 修改 `web/src/components/mock/ExampleEditor.vue`（示例的响应体）；
- 修改 `web/src/components/common/CodeEditor.vue`：加快捷键。

**`formatJson` 的要求：**
- **`{{变量}}` 原样保留：**
  - 字符串外面的 `{{xxx}}`（比如 `"id": {{id}}`）：先换成唯一的占位字符串 `"__APILOOP_VAR_<序号>__"`，`JSON.parse` 加 `JSON.stringify(…, null, indent)` 之后，再把带引号的占位换回 `{{xxx}}`；
  - 字符串里面的 `{{xxx}}` 不用处理，它本来就是合法的字符串内容。
- 失败时 `error` 写成「第 N 行第 M 列：<原因>」。行列号从 `JSON.parse` 的报错位置换算过来；拿不到位置时就只给原因。
- 空文本返回 `{ ok: true, text: '' }`。

**界面：**
- **请求体：** 模式是「JSON / 文本」、语言是 JSON 时，语言下拉框右边出现一个「美化」按钮（`quaternary`、`size="small"`）。
  - 点击：成功就替换内容；失败就用 `message.error` 显示 `error`，内容不动。
- **示例编辑器：** 响应体的编辑器上方加同样的「美化」按钮（`Content-Type` 是 JSON 或者内容看起来是 JSON 时显示）。
- **快捷键：** `CodeEditor` 在 `language === 'json'` 时，`Shift+Alt+F`（Mac 上是 `⇧⌥F`，和 VS Code 一样）触发美化，行为和按钮一样。由组件发出 `format-error` 事件，让外面去提示错误。
- 美化不改变缩进以外的东西：键的顺序、数字的写法（比如 `1.0` 会变成 `1`，这是 `JSON.stringify` 的行为，可以接受，在按钮的悬停提示里写一句「数字会按标准格式输出」）。

## 附录：检查用的 cURL

审阅方就是用这三段确认了问题清单。新的解析器对它们的期望结果写在每段下面。

**一：Chrome「复制为 cURL (bash)」，带 Cookie 和 JSON 请求体**
```
curl 'https://192.168.3.40:9091/jbcs/jbcs-cic-service/cic/staff/info/page?size=10&page=1' \
  -H 'Accept: application/json, text/plain, */*' \
  -H 'Authorization: Bearer eyJhbGciOi.xx.yy' \
  -H 'Content-Type: application/json;charset=UTF-8' \
  -b 'JSESSIONID=ABC123; lang=zh' \
  --data-raw '{"name":"张三","orgId":12,"tags":["a","b"],"inner":{"x":1}}' \
  --compressed \
  --insecure
```
期望：
- `POST`；`url` 是 `https://192.168.3.40:9091/jbcs/jbcs-cic-service/cic/staff/info/page`；
- 查询参数 `size=10`、`page=1`；
- 请求头 4 个：Accept、Authorization、Content-Type、Cookie；
- `body` 是 raw json，原文和 `--data-raw` 的值完全一样。

**二：`$'...'` 写法，带转义**
```
curl $'https://example.com/api/users/42/orders' -X PUT -H $'content-type: application/json' --data-raw $'{"note":"it\'s ok\\nline2"}'
```
期望：
- `PUT`；`url` 是 `https://example.com/api/users/42/orders`（**42 不改成 `:id`**）；
- 请求头 1 个；
- `body.raw` 是 `{"note":"it's ok\nline2"}`，也就是 JSON 字符串里是「反斜杠 + n」两个字符。

**三：表单**
```
curl "https://example.com/api/login" -H "Content-Type: application/x-www-form-urlencoded" --data-raw "username=admin&password=a%26b"
```
期望：
- `POST`；`body` 是 urlencoded；
- 表单行 `username=admin`、`password=a&b`（已解码）。
