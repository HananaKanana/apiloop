> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **本项目约定**
> - **不写新测试**，也不装浏览器驱动做验证，既有的 `npm test` 必须全部通过。
> - 审阅用的一次性探测脚本放在 `/tmp`，跑完删掉。
> - **只提交自己的文件**：用 `git commit -m ... -- <文件>` 提交，不要用 `git add -A`、`commit -a`、`git stash`。

**来源**：用户反馈的 bug。接口的鉴权可以选「继承父级」，但界面上**没有任何地方可以配置目录的鉴权**，只能在项目设置里配置项目级的鉴权。另外，审阅时发现目录上的变量在发送时**完全没有参与替换**。以「导入到当前项目」的方式导入 Postman 集合时，集合变量存在顶层目录上，结果全部丢失。

**依据**：契约第 3 节 `PUT /folders/:id`（后端早就支持修改 `auth` 和 `variables`），以及第 5 节第 1 步（2026-09-30 修订的变量优先级：项目 < 外层目录 < 内层目录 < 环境）。

**排期**：
- **F1**：由 session1 负责，排在 P7b 的 A2 之后；
- **F2**：由 session2 负责，排在 P7b 的 B2 之后。

两个任务互不依赖。

## 审阅重点

1. **变量顺序**：项目变量、目录链变量（从外到内）、环境变量依次拼接，后面的覆盖前面的。反了的话，内层目录的变量会被外层覆盖，或者环境变量压不住目录变量。
2. **三处共用同一段代码**：`/send`、`/send/stream`、WebSocket 会话，这三处都必须让目录变量生效。
3. **viewer 只能看**：viewer 能打开目录设置查看，但不能改。
4. **鉴权来源要说清楚**：选了「继承父级」时，要写明这次实际用的是哪一级的哪种鉴权。现在只写了一句「沿用上一级的鉴权设置」，用户不知道这个「上一级」到底有没有配置。

### Task F1（session1）：发送时目录变量参与替换

**Files:** `lib/api/send.js`（A1 抽出来的公共准备函数）

- [ ] 在构造 `vars` 的地方插入目录链的变量。目录链的取法和 `inheritAuth` 一样：`[folder].concat(tree.ancestors(handle, folder.id))` 得到的是**从内到外**的顺序，拼接前要**反转成从外到内**。
- [ ] 把这条目录链抽成一个小函数，让 `inheritAuth` 和变量共用，不要写两遍。
- [ ] **自测**，脚本放在 `/tmp`：
  - 项目变量 `host=p`，外层目录 `host=o`，内层目录 `host=i`，不选环境时，实际发出的是 `i`；
  - 选了一个带 `host=e` 的环境，实际发出的是 `e`；
  - 删掉内层目录上的这个变量后，实际发出的是 `o`；
  - 缺失变量的提示里，不再出现已经在目录上定义过的变量；
  - `/send/stream` 同样要生效；WebSocket 会话如果已经交付，也要一起验证。
- [ ] `npm test` 全部通过。
- [ ] 提交：`fix: 发送时目录变量参与替换（项目 < 目录链 < 环境）`。

### Task F2（session2）：目录设置标签页

**Files:** `web/src/components/tree/ApiTree.vue`、`web/src/stores/tabs.js`，新建 `web/src/components/folder/FolderTab.vue`（名字可以自定）

- [ ] **入口**：
  - 目录的右键菜单加一项「目录设置」；
  - viewer 现在的右键菜单是整个不弹出来的，改成只弹出这一项，打开后是只读的。
- [ ] **打开方式**：作为一种新的标签页类型 `folder` 打开，和接口标签页并列，这样和 Postman 的习惯一致。同一个目录只能打开一个标签页。
- [ ] **内容**：
  - 名称和描述；
  - 鉴权：复用 `AuthEditor`，选项里同样有「继承父级」；
  - 变量：复用 `VarTable`；
  - 如果目录上有脚本（是导入进来的），只读展示，并注明「脚本已保存，但不会执行」。
- [ ] **保存**：调用 `PUT /folders/:id`，保存按钮和 `Ctrl+S` 的行为与接口标签页一致，包括「未保存」标记和切换项目时的提醒。保存成功后刷新目录树里这个目录的数据。
- [ ] **鉴权的实际来源**（审阅重点第 4 条）：接口和目录的鉴权选了「继承父级」时，下方的提示改成显示实际生效的那一级：
  - 继承到了：「继承自 目录「人员信息」：Bearer Token」，或者「继承自 项目：Basic Auth」；
  - 一路找上去都没有配置：「上级都没有配置鉴权，这次请求不带鉴权」。

  用目录树 store 里已有的 `folders`（带着 `auth` 字段）和 `project.auth` 在前端计算，规则与契约第 5 节第 2 步相同。
- [ ] **只读**：`projects.canEdit` 为 false 时，所有控件都禁用，不显示保存按钮。
- [ ] **（用户追加）点击目录整行就能展开 / 收起**：现在只有点左边的小三角才行，很麻烦。
  - 给 `n-tree` 加上 `expand-on-click`。目录树已经开了 `block-line`，整行都可以点击。
  - 点击目录时，「选中这个目录」的逻辑要照常执行（导入 cURL / OpenAPI 时，会落到这个目录里）。
  - 点击接口时，照常打开标签页，不受影响。
  - 空目录点击后没有东西可以展开，不要报错。
  - 右键打开「目录设置」时，不能顺带把目录折叠或展开。
- [ ] 执行 `npm run build:web`，把源码和 `lib/web` 放在同一个提交里：`feat(web): 目录设置标签页（鉴权 / 变量）；点整行展开目录`。
