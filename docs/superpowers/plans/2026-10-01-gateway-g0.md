# 本地网关 G0：技术验证 实施计划

> 给 session1。只用 `git commit -m ... -- <文件>` 提交自己的文件，不推送。不写新测试；既有测试（`npm test`）必须全部通过。

**目标：** 做一个最小但结构正确的本地网关，再打一个 Mac 的 `.pkg` 安装包。用户装好后，用 Chrome 和 Safari 打开 `http://127.0.0.1:47321`，登录云端账号，发一个同网段请求（比如 `http://192.168.17.3:8080`），系统弹授权框，点允许后发送成功。

**设计稿：** `docs/design/2026-10-01-local-agent.md`。必读第 2、3、5 节，第 3.1 节的安全要求必须全部做到。

**为什么这样做：** D0 已经实测过，没有苹果签名的程序访问不了同网段地址；而官方 Node 作为 launchd 后台任务运行，可以拿到授权（`reviews/2026-10-01-desktop-d0-review.md` 第 3、4 轮）。G0 要验证完整的链路：安装包 → 后台服务 → 浏览器 → 转发登录 → 本机发请求。

## 全局约束

- **安装包里的 node 必须是 nodejs.org 的官方构建**，用国内镜像下载，例如 `https://npmmirror.com/mirrors/node/v24.x.y/node-v24.x.y-darwin-arm64.tar.gz`，选当前最新的 v24 LTS。
  - `codesign -dv` 必须显示 `TeamIdentifier=HX7739G8FX`；
  - 打包流程里**任何一步都不能对它重新签名**。
  - 不能用 Homebrew 的 node。
- **G0 只打 Mac arm64 的包。** x64 和 Windows 留到 G3。
- **根目录 `package.json` 不加依赖。** 打包工具只用系统自带的 `pkgbuild`、`productbuild`、`osacompile`。
- **G0 的发送是「原样发送」：** 只把页面给的请求按原样发出去，不解析 `{{变量}}`、不跑脚本、不带 Cookie、不写历史。完整的发送流程（`send/prepare` 和 `send/record`）在 G1 做。
- **打出来的安装包不进仓库**，放在 `agent-installer/dist/`，加进 `.gitignore`。

## 审阅重点

1. **安全（设计稿第 3.1 节）：** 别的网站不能借网关读数据，也不能借网关发请求。审阅方会用 curl 模拟以下情况，每一种都必须被拒绝（返回 403）：
   - `Host` 不是 `127.0.0.1:<端口>` 或 `localhost:<端口>`；
   - 带了 `Sec-Fetch-Site: cross-site`；
   - 非 GET 请求没有带 `X-Apiloop: 1`；
   - 跨域预检（`OPTIONS`），并且不能返回任何 `Access-Control-Allow-*` 响应头。
2. **会话 Cookie 转发：**
   - 云端返回的 `Set-Cookie` 要去掉 `Domain`；
   - 云端是 https 时，还要去掉 `Secure`（网关是 http）；
   - 浏览器发来的 `Cookie` 原样转给云端。
3. **流式接口不能被缓冲：** 转发 `/ws/:id/events` 这类长连接时，要边收边发，不能等全部收完再一起返回。
4. **端口被占用时：** 依次尝试 47322–47329，把实际用的端口写进端口文件。启动器读这个文件来打开正确的地址。
5. **安装后的 node 签名：** 用 `pkgutil --expand-full` 展开安装包，核对里面的 node。

### Task 1：`apiloop gateway` 命令

**文件：**
- 新建 `lib/gateway/index.js`
- 修改 `bin/server`：新增 `gateway` 命令，参数有 `--cloud <地址>`、`--port`
- 修改 `lib/command.js`：分发到 gateway
- 修改 `web/src/api/client.js`、`web/src/api/stream.js`：所有请求都加上 `X-Apiloop: 1` 请求头。直接访问云端时，云端会忽略这个头。

**接口：**
- `createGateway({ cloudUrl, port, dataDir }) → Promise<{ server, port, close() }>`
- **配置文件** `<dataDir>/gateway.json`：`{ cloudUrl }`。
  - `dataDir` 默认用 `appInfo.DATA_DIR`（`~/.apiloop`）。
  - 启动参数 `--cloud` 会覆盖配置文件，并写回配置文件。
- **端口文件** `<dataDir>/gateway.port`：启动后写入实际使用的端口。
- **路由（按顺序）：**
  1. 安全检查：设计稿第 3.1 节和上面审阅重点第 1 条。不通过就返回 403，返回内容是 JSON `{ error }`。
  2. `GET /__gateway/status` → `{ version, cloudUrl, cloudReachable }`。`cloudReachable` 通过请求云端的 `/__admin/api/meta` 来判断，超时时间 3 秒。
  3. **没有配置云端地址时**，所有页面请求都返回一个最简单的设置页：一个输入框加「保存」按钮。设置页 POST 到 `/__gateway/setup`，同样要带 `X-Apiloop: 1`，然后跳回首页。
  4. `POST /__admin/api/projects/:pid/send/stream` → **在本机执行**：用请求体里的 `request` 调 `lib/executor.js`，按现在的 NDJSON 格式（`head`、`chunk`、`result` 事件）流式返回。
     - 返回的结果里要标注 `gatewayRawSend: true`，前端暂时不用处理。
     - 第一次访问局域网被拒绝的情况：目标是私有地址（10/8、172.16/12、192.168/16、169.254/16），而且错误码是 `EHOSTUNREACH`，就把错误信息换成设计稿第 3.3 节的那段提示。
  5. 其余的 `/__admin/api/*` → **转发到云端**（审阅重点第 2、3 条）。
  6. 页面静态资源：和云端一样，用 `lib/web`，根路径跳转到 `/index.html`。
- **只监听 `127.0.0.1`。**

- [ ] 用本机的 Docker apiloop（`http://localhost:8080`）当云端：执行 `node bin/server gateway --cloud http://localhost:8080`，然后用 curl 跑一遍以下检查，结果贴进回报：
  - `GET /__gateway/status`
  - 通过网关登录 `POST /__admin/api/auth/login`，带 `X-Apiloop: 1`，拿到 `Set-Cookie`；
  - 带着这个 Cookie 请求 `GET /__admin/api/projects`，返回 200；
  - 审阅重点第 1 条里的四种情况，都返回 403；
  - `POST /__admin/api/projects/<pid>/send/stream`，目标是本机临时起的一个 HTTP 服务，拿到 `result` 事件。
- [ ] 执行 `npm run build:web` 和 `npm test`，全部通过。
- [ ] 提交：`feat(gateway): apiloop gateway——本地网关（转发云端 + 本机原样发送）（G0）`

### Task 2：Mac 安装包

**文件：**
- 新建 `agent-installer/mac/build.sh`
- 新建 `agent-installer/mac/com.apiloop.gateway.plist`
- 新建 `agent-installer/mac/scripts/postinstall`
- 新建 `agent-installer/mac/launcher.applescript`
- 新建 `agent-installer/mac/uninstall.command`
- 修改 `.gitignore`

**安装后的位置：**
- `/Library/Application Support/apiloop/node/`：官方 node，原样解压；
- `/Library/Application Support/apiloop/app/`：`bin/`、`lib/`（含 `lib/web`）、`package.json`，以及 `npm ci --omit=dev` 安装的生产依赖；
- `/Library/LaunchAgents/com.apiloop.gateway.plist`：
  - `ProgramArguments` 是「node 的绝对路径 + `app/bin/server` + `gateway`」；
  - `RunAtLoad` 和 `KeepAlive` 都设为 `true`；
  - 日志写到 `/tmp/apiloop-gateway.log`；
- `/Applications/apiloop.app`：用 `osacompile` 编译 `launcher.applescript` 得到。它读取 `~/.apiloop/gateway.port`（读不到就用 47321），然后用默认浏览器打开 `http://127.0.0.1:<端口>/`。
- `/Library/Application Support/apiloop/卸载 apiloop.command`：停止服务（`launchctl bootout`），删除上面所有文件。
  - **不删除** `~/.apiloop`，里面是用户数据。卸载完提示这一点。

**postinstall：**
1. 找到当前登录的用户：`stat -f %Su /dev/console`；
2. 如果服务已经在运行（覆盖安装的情况），先 `bootout`；
3. 用 `launchctl bootstrap gui/<uid> /Library/LaunchAgents/com.apiloop.gateway.plist` 启动服务；
4. 以这个用户的身份 `open /Applications/apiloop.app`。

**build.sh：**
1. 下载并校验官方 node；
2. 暂存 app，生产依赖用 `npm ci --omit=dev` 安装；
3. 用 `pkgbuild` 加 `productbuild` 打出 `agent-installer/dist/apiloop-gateway-<版本>-arm64.pkg`；
4. 最后用 `pkgutil --expand-full` 展开刚打好的包，用 `codesign -dv` 核对里面的 node。`TeamIdentifier` 不是 `HX7739G8FX` 就报错退出。

- [ ] 执行 `bash agent-installer/mac/build.sh`，产出安装包，最后的签名核对通过。回报里写：文件名、大小、核对输出。
- [ ] **不要自己安装这个包。** 安装要输入管理员密码，而且会动用户的系统，交给用户来装。
- [ ] 提交：`build(gateway): Mac pkg 安装包（官方 Node + LaunchAgent + 启动器）（G0）`
