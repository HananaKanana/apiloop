# Mac 原生壳 实施计划

> 执行方式：session1 做 Task 1（壳子本身 + 打包），session2 做 Task 2（页面给壳子留的一个钩子）。两个可以同时开工，Task 1 按 Task 2 的接口写。
> **一个 Task 一个提交，只提交、不推送；提交时只写自己改的路径（`git commit -- <路径>`）。** 改了前端的，提交前重新 `npm run build:web`，并把 `lib/web` 一起提交。

**目标：** 点「应用程序」里的 apiloop，打开一个独立窗口（不再跳到默认浏览器），用起来和 Postman 一样。

**架构：** 一个很小的 Swift 程序，用系统自带的 AppKit + WKWebView 开一个窗口，加载 `http://127.0.0.1:<网关端口>/`。命令行工具里的 `swiftc` 编译，不需要 Xcode。它**替换**现在 `osacompile` 出来的启动器：位置（`/Applications/apiloop.app`）、bundle id（`com.apiloop.launcher`）都不变，安装包的其它部分不动。

**设计稿：** `docs/design/2026-10-01-local-first.md` 第 9 节最后一条。

## 全局约定

- 不写新测试，`npm test`（71 个）必须全过。验证用一次性脚本，跑完删掉。**不要自己装 pkg、不要打开编出来的 .app 去点**，界面行为由用户确认。
- 用户看得到的文字一律中文。
- 壳子**只连 127.0.0.1**。访问内网、访问云端都还是网关（官方签名的 node）的事，所以壳子不用签名（ad-hoc 就行），也不会触发「本地网络」权限。
- 最低系统版本 **macOS 12.0**（`LSMinimumSystemVersion`、`swiftc -target` 都用它）。

## 审阅重点

1. **复制粘贴必须能用。** WKWebView 的 ⌘C / ⌘V / ⌘Z / ⌘A 靠菜单栏里的「编辑」菜单才生效，漏了用户在输入框里连粘贴都不行。
2. **页面自己的快捷键不能被菜单抢走：** ⌘S（保存）、⌘K（搜索）、⌘\（侧栏）、⌘Enter（发送）。菜单里不要用这几个键。
3. **关窗口、⌘Q、⌘R 不能悄悄丢掉没保存的修改**（问 Task 2 的钩子）。页面还没加载出来、钩子不存在、JS 出错，都按「没有」处理，直接关。
4. **别的地址不能在壳子里打开：** 不是网关地址的链接、`target=_blank`、`window.open` 一律交给系统浏览器，壳子窗口始终停在 apiloop 上。
5. **网关没起来时不能白屏：** 显示一页中文说明和「重试」，后台自动重试。

### Task 1（session1）：Swift 壳子，接进打包脚本

**文件：**
- 新建 `agent-installer/mac/shell/main.swift`（壳子，全部代码一个文件）
- 新建 `agent-installer/mac/shell/make-icon.swift`（打包时画图标）
- 修改 `agent-installer/mac/build.sh`（`osacompile` 那段换成 `swiftc`；第 5 步的核对项）
- 修改 `agent-installer/mac/scripts/preinstall`（退掉正在运行的壳子）
- 删除 `agent-installer/mac/launcher.applescript`

**Interfaces：**
- 用到 Task 2 的：页面上 `window.apiloopShell.hasUnsavedChanges()` → `boolean`。不存在就当 `false`。
- 给页面的：User-Agent 末尾追加 ` apiloop-shell/<版本>`（`WKWebViewConfiguration.applicationNameForUserAgent`）。现在页面不用它，留着以后判断「是不是在壳子里」。

**壳子要做的事（`main.swift`）：**

1. **启动：**
   - 先做现在 `launcher.applescript` 里 `ensureGateway` 那段：网关不在 launchd 里就 `launchctl bootstrap`，最多等 5 秒端口文件。用 `Process` 跑 `/bin/sh -c`，脚本原样搬过来。
   - 读 `~/.apiloop/gateway.port`，只留数字，读不到用 `47321`。
   - 加载 `http://127.0.0.1:<端口>/`。
2. **网关连不上**（`didFailProvisionalNavigation`）：
   - `loadHTMLString` 一页中文：「apiloop 本机服务还没启动」，下面一个「重试」按钮，再加一行小字「多次重试仍然不行，请重新安装 apiloop」。
   - 后台每 2 秒自动重试一次（每次重读端口文件），连上了就自动加载。按钮用 `WKScriptMessageHandler` 收消息，不要自定义 URL scheme。
3. **导航：**
   - 主框架导航时，只放行 host 是 `127.0.0.1` / `localhost`、端口等于网关端口的地址，以及 `about:blank` 和上面那页说明。
   - 其它 `http(s)` 地址：`NSWorkspace.shared.open(url)`，取消这次导航。
   - `target=_blank` 和 `window.open`（`createWebViewWith`）：一律交给系统浏览器，返回 `nil`。
   - 不是 http(s) 的（`mailto:` 之类）也交给系统处理。
4. **下载：**
   - 这几种都转成下载：`navigationAction.shouldPerformDownload`（`<a download>`、blob 地址，页面导出就是这么做的）；响应带 `Content-Disposition: attachment`；响应 `canShowMIMEType` 为 false。
   - `WKDownloadDelegate`：弹 `NSSavePanel`，默认文件名用 `suggestedFilename`，默认目录是「下载」。用户取消就 `completionHandler(nil)`。
   - 下载失败弹一个中文 `NSAlert`。
5. **选文件：** `runOpenPanelWith` → `NSOpenPanel`，按 `parameters` 设多选、能不能选目录。页面里导入 Postman 文件、请求体选文件都靠它。
6. **JS 弹窗：** `alert` / `confirm` / `prompt` 都用 `NSAlert` 实现。按钮叫「好」「取消」，`prompt` 里放一个 `NSTextField`。
7. **关窗口、退出、刷新：**
   - 关最后一个窗口就退出应用（`applicationShouldTerminateAfterLastWindowClosed` 返回 true）。网关是 launchd 管的，不受影响。
   - `windowShouldClose`、`applicationShouldTerminate`（返回 `.terminateLater`）、菜单的「重新加载」：都先 `evaluateJavaScript` 问 Task 2 的钩子。
   - 钩子返回 true：弹 `NSAlert`「还有没保存的修改」/「关闭后这些修改会丢失。」，按钮「仍然关闭」（刷新时叫「仍然刷新」）和「取消」。
   - 钩子不存在、JS 报错、1 秒内没回答：都当没有，直接关（审阅重点 3）。
8. **窗口：**
   - 第一次是 1280×800 居中，最小 900×600；用 `setFrameAutosaveName("apiloop.main")` 记住大小和位置。
   - 标题固定是「apiloop」。
   - 缩放比例（`pageZoom`）存在 `UserDefaults`，下次打开还是它。
9. **菜单栏**（审阅重点 1、2）：
   - **apiloop**：关于 apiloop（标准关于面板，版本取自 Info.plist）、隐藏 apiloop ⌘H、隐藏其他 ⌥⌘H、退出 apiloop ⌘Q。
   - **编辑**：撤销 ⌘Z、重做 ⇧⌘Z、剪切 ⌘X、拷贝 ⌘C、粘贴 ⌘V、全选 ⌘A。用标准 selector（`undo:`、`redo:`、`cut:`、`copy:`、`paste:`、`selectAll:`），目标 nil，交给响应链。
   - **显示**：重新加载 ⌘R、实际大小 ⌘0、放大 ⌘=、缩小 ⌘-、在浏览器中打开（用系统浏览器打开当前网关地址，**没有快捷键**）。
   - **窗口**：最小化 ⌘M、关闭窗口 ⌘W。
   - **不要**给任何菜单项设 ⌘S、⌘K、⌘\、⌘Enter。
10. **数据：** 用 `WKWebsiteDataStore.default()`（持久化）。登录状态、页面的 localStorage 关掉再开都还在。

**打包（`build.sh`）：**
- `osacompile` 那一段换成：
  - 用 `swiftc -O -target <arm64|x86_64>-apple-macos12.0 -framework AppKit -framework WebKit` 编 `shell/main.swift`，输出到 `apiloop.app/Contents/MacOS/apiloop`；架构跟着 `NODE_ARCH`（x64 → `x86_64`）。
  - `Contents/Info.plist` 由脚本写出：
    - `CFBundleIdentifier=com.apiloop.launcher`（**不能变**，覆盖安装和 `BundleIsRelocatable` 都靠它）；
    - `CFBundleExecutable=apiloop`、`CFBundleName=apiloop`、`CFBundleDisplayName=apiloop`、`CFBundlePackageType=APPL`；
    - `CFBundleShortVersionString` 和 `CFBundleVersion` 都用 `$VERSION`；
    - `CFBundleIconFile=apiloop`、`LSMinimumSystemVersion=12.0`、`NSHighResolutionCapable=true`；
    - `NSAppTransportSecurity` → `NSAllowsLocalNetworking=true`。
  - 图标：`swiftc` 编 `make-icon.swift`，跑它画一张 1024×1024 的 PNG：圆角方块、品牌主色渐变，中间白色 `{ }` 或一个环形箭头，你定。然后用 `sips` 出 iconset 的 10 个尺寸，`iconutil -c icns` 生成 `Resources/apiloop.icns`。图标编一次就够，两种架构共用。
  - 最后 `codesign --force --sign - apiloop.app`。
- 第 5 步的核对，把 `Contents/MacOS/applet` 换成 `Contents/MacOS/apiloop`，另外加三条：
  - `lipo -archs` 等于这个包的架构；
  - `plutil -lint` 通过，而且 `CFBundleIdentifier` 是 `com.apiloop.launcher`；
  - `codesign -v` 通过。
- 载荷清单、注释里提到「启动器 / applet / osacompile」的地方一并改掉。
- **`preinstall`**：现在只 `pkill` 了 `applet`。新的壳子是常驻的，覆盖安装时它很可能正开着，要把 `Contents/MacOS/apiloop` 也退掉（同样按路径 `pkill -f`，不用 AppleScript）。`postinstall` 不用改，它打开的还是 `/Applications/apiloop.app`。

**回报：**
1. `build-all.sh` 打出两个包，第 5 步的核对全过（贴出那几行）。
2. 两个包里的 `apiloop.app`：`file`、`lipo -archs`、`codesign -v`、`plutil -p Info.plist` 的输出。
3. 写清楚哪些行为只能由用户在界面上确认（审阅方会整理成清单交给用户）。

### Task 2（session2）：给壳子留一个「有没有没保存的修改」的钩子

**文件：** `web/src/views/WorkbenchView.vue`

**做什么：**
- `onMounted` 里挂上：

  ```js
  window.apiloopShell = {
    /** 壳子关窗口、退出、刷新之前问一句（Mac 原生壳，见 docs/superpowers/plans/2026-10-01-mac-shell.md） */
    hasUnsavedChanges: function () { return Boolean(tabs.hasDirty); }
  };
  ```

- `onBeforeUnmount` 里删掉（`delete window.apiloopShell`）。原来的 `beforeunload` 照旧保留，浏览器里还要用。

**回报：** 浏览器里打开工作台，改一个接口不保存，控制台 `window.apiloopShell.hasUnsavedChanges()` 是 `true`；保存后是 `false`；回到登录页后 `window.apiloopShell` 是 `undefined`。
