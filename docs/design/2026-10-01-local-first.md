# apiloop 本地优先：跳过登录、本机存数据、登录后自动同步

> 状态：草稿，等用户审阅（2026-10-01）。
> 取代 `2026-10-01-local-agent.md` 的第 6、7 节（第二期）以及第 8 节里的 G4、G5。那份设计稿其余部分（网关、安全、安装包）继续有效。

## 1. 用户的要求和已确认的决定

**原话：**「本地安装完，登录页面可以选择跳过登录；所有数据都保存在本地，如果登录后，所有数据自动同步到云上；如果没有网络的情况下，本地所有改动暂存，等网络恢复自动同步。」

**讨论中确认的（2026-10-01）：**

| 问题 | 决定 |
|---|---|
| 不登录时建的项目，登录后怎么办 | **全部自动上传**到这个账号，你是所有者 |
| 换账号 | 每个账号在本机一份独立数据；另有一份「未登录」数据。未登录时的数据归下一个登录的账号；账号之间互相看不到 |
| 两边改了同一处 | 不同字段自动合并；同一字段两边改得不一样时，让用户选「用我的 / 用云端的 / 另存为副本」 |
| 整体做法 | 网关自带本机数据库，页面读写都走本机，网关在后台和云端同步（方案一） |
| mock 地址 | 从 `/mock/<短名>` 改成 `/mock-<项目ID>/<接口路径>` |
| 要不要拆成两个项目 | 不拆。一套代码两种运行方式：云端 `apiloop web`，本机 `apiloop gateway` |
| 云端发送 | 保留（之前已决定）。直接打开云端网页照常能编辑、发送 |
| 同步范围 | 项目、目录、接口、示例、mock 期望、环境双向同步；用户、成员、角色只从云端拉取；历史请求、Cookie、上传的文件只存本机 |

## 2. 整体结构

```
浏览器页面 ──► 本机网关（127.0.0.1:47321）
                ├─ 当前空间的 SQLite（表结构和云端相同）◄── 页面所有读写都落这里
                ├─ 本机发请求（send-core，已有）
                └─ 同步引擎 ──（有网、已登录时）──► 云端 /__admin/api/sync/*
                                                     云端 SQLite + 变更记录
```

- 页面调的接口和直接打开云端时**完全一样**（`/__admin/api/projects/...`）。网关用同一份 `lib/admin.js`，只是背后是本机的库。
- 网关不再把数据接口转发给云端。只有「登录」和「同步」这两类请求会连云端。
- **代码怎么分：**
  - `lib/gateway/`：只在本机跑的代码（空间、跳过登录、同步引擎）；
  - `lib/sync/`：只在云端跑的代码（同步接口）；
  - 其余两边共用。

## 3. 空间

### 3.1 存放位置

```
~/.apiloop/spaces/local/data.db                  未登录
~/.apiloop/spaces/<云端主机>~<端口>~<账号ID>/      每个登录过的账号一个目录
    data.db          同步的数据 + 只存本机的历史、Cookie
    files/           上传的文件
    session.json     云端会话（权限 0600）和离线校验用的密码摘要
~/.apiloop/gateway.json                           当前空间（以及开发时手动覆盖的云端地址）
```

- 目录名里带云端地址，连不同的云端（测试环境、正式环境）不会混。
- 同一时间只打开一个空间的库。切换空间要先关掉当前的库，再打开另一个，然后让页面整页刷新。

### 3.2 未登录空间

- 库里有一个固定的「本机用户」：`id = 'u_local'`，没有密码，系统角色 admin，是这个空间所有项目的 owner。
- 点「跳过登录」，网关给浏览器发一个本机会话，身份就是这个用户。全程不需要联网，也不需要配置云端地址。
- 能用：项目、目录、接口、环境、导入导出、发请求、历史。
- **mock 不可用**（mock 服务在云端）。项目设置里的 mock 地址显示「登录后可用」。
- 成员管理、用户管理入口隐藏。

### 3.3 账号空间

- `users`、`project_members` 从云端拉取，本机只读；
- 在某个项目里是 viewer 的，页面上照旧不能改，和直接打开云端时一样；
- 系统角色以云端为准。

## 4. 登录、退出、上传

### 4.1 云端地址：打包时写死

用户 2026-10-01：「这个流程只是暂时的。后续部署到云端，这个地址就固定下来，只跟随版本变化而改动。」

- 打安装包时，用 `APILOOP_CLOUD_URL=<地址> bash agent-installer/mac/build.sh` 把云端地址写进安装包，写到 `app/cloud.json`。没给这个变量就拒绝打包。
- 网关读云端地址的优先级：
  1. 启动参数 `--cloud`；
  2. `gateway.json` 里的 `cloudUrl`。这两个只给开发用；
  3. 安装包里的 `app/cloud.json`。
- **用户界面上不再有任何填写或修改云端地址的地方：**
  - 现在的首次设置页 `/__apiloop/setup` 取消；
  - 顶栏菜单里的「云端地址…」去掉。
- 换云端地址就是发一个新版本的安装包。

### 4.2 登录页（网关上）

- 账号密码表单，和云端网页上的一样。
- 下面加一个链接「跳过登录，先在本机用」。

### 4.3 登录流程

1. 网关拿账号密码去云端登录（`POST /__admin/api/auth/login`），保存云端会话。
2. **连不上云端时：**
   - 这个账号以前在本机登录过：用 `session.json` 里的密码摘要离线校验。scrypt 算法，带随机盐；摘要在网关本机生成，不是云端那份。校验通过就进入，状态显示「离线」；
   - 以前没登录过：提示「连不上云端，第一次登录需要联网」。
3. 打开这个账号的空间。第一次登录就全量下载它能看到的项目；以后只拉增量（见第 5 节）。
4. **未登录空间里有项目时，上传：**
   - 按项目逐个上传：一个项目的全部行一次推送，云端以客户端给的 ID 建行，项目的 owner 是当前账号；
   - 一个项目推送成功后，把它的行搬进账号空间的库，标成「已同步」并记下基线；再从未登录空间删掉。历史请求跟着项目一起搬过去，上传的文件也一起搬，但都不上传；
   - 中途断网：已经搬走的不会再传；没搬的留在未登录空间，下次登录或者联网时继续。云端重复收到同一个 ID 时按「更新」处理，所以重试是安全的；
   - 页面上显示「正在上传本机的 N 个项目」。

### 4.4 退出

- 账号菜单里有「退出登录」和「退出并删除本机数据」。
- 还有没同步的改动时，提示「还有 N 项没同步，下次登录这个账号时会继续同步」。选「退出并删除本机数据」时，改为提示这 N 项会丢失，需要确认。
- 退出后回到未登录空间。账号空间的数据留在磁盘上，选了删除的除外。

### 4.5 云端会话过期

- 同步暂停，状态显示「登录已过期」，点一下重新输入密码。本机照常使用，改动先暂存。
- 重新登录后，继续同步暂存的改动。

## 5. 同步

### 5.1 云端（迁移 v6，`lib/sync/`）

- **版本号和删除标记：** `projects`、`folders`、`apis`、`examples`、`mock_expectations`、`environments` 各加两列：
  - `rev INTEGER NOT NULL DEFAULT 1`：每改一次加一；
  - `deleted INTEGER NOT NULL DEFAULT 0`：删除只打标记。
- **变更记录：** 新表 `changes(seq INTEGER PRIMARY KEY AUTOINCREMENT, project_id, entity, entity_id, rev, at)`，每次增删改记一条。
- **改在仓储层统一做：** 所有写这些表的地方都经过 `lib/db/repos/`，在那里统一加 `rev`、写 `changes`。这样云端网页上的修改也自动带上。
- **读的地方：** 所有现有查询都要加 `deleted = 0`。审阅时逐个核对。
- **删除标记的清理：** 30 天后真正删除。超过 30 天没同步的设备，下次只能全量重新下载（见 5.3）。
- **接口**（都要求登录，挂在 `requireLogin` 之后）：
  - `GET /__admin/api/sync/state`：返回这个用户能访问的项目 `[{ id, role }]`，以及当前最大的 `seq`；
  - `GET /__admin/api/sync/projects/:pid/snapshot`：返回一个项目的全部行（不含已删除的）和当前 `seq`，用于第一次下载，或者新加入一个项目时；
  - `GET /__admin/api/sync/changes?since=<seq>&limit=500`：返回 `since` 之后、这个用户能访问的项目里变化过的**完整行**（包括已删除标记），以及 `nextSeq`、`hasMore`；
  - `POST /__admin/api/sync/push`：请求体是 `{ items: [{ entity, id, baseRev, row, deleted }] }`，按顺序处理，每条返回：
    - `ok`：附新的 `rev`；
    - `conflict`：附云端当前那一行（`baseRev` 和云端的 `rev` 对不上）；
    - `forbidden`：没有编辑权限；
    - `invalid`：附原因，比如父目录不存在。
    - 新建的行 `baseRev = 0`。ID 已经存在并且 `rev` 对得上，就按更新处理（上传重试的情况）。新建项目时，当前用户自动成为 owner。
- 用户、成员不走变更记录：每轮同步时用 `sync/state` 对比。

### 5.2 本机（`lib/gateway/sync/`）

- **待同步列表：** 新表 `sync_outbox(entity, entity_id, PRIMARY KEY(entity, entity_id))`，本机每写一行就记一条，同一行改多次只算一条。也在仓储层统一记。只在账号空间里记。
- **基线：** 新表 `sync_base(entity, entity_id, rev, row_json)`，存「上次和云端对齐时这一行是什么样」。
- **游标：** `meta` 里记 `sync_seq`。
- **一轮同步：**
  1. `sync/state`：
     - 新出现的项目，下载 snapshot；
     - 没有权限了的项目，从本机删掉。如果里面有没同步的改动，状态栏提示「项目 X 已不能访问，N 项本机改动没能同步」。
  2. 拉取 `sync/changes`，直到 `hasMore = false`：
     - 本机没改过的行（不在待同步列表里），直接用云端的，并更新基线；
     - 本机也改过的，按 5.3 合并。
  3. 推送待同步列表，每批最多 200 条。
     - 父级排在前面：项目 → 环境 → 目录（父目录在前）→ 接口 → 示例、mock 期望；
     - `ok`：更新基线，清掉这一条；
     - `conflict`：按 5.3 合并，然后下一轮再推；
     - `forbidden`：改回云端的版本，提示「你在项目 X 里是只读成员，改动没有保存到云端」；
     - `invalid`：留在列表里，状态栏显示错误。
- **什么时候同步：**
  - 网关启动时、登录后；
  - 本机写入后约 2 秒（多次写入合并成一次）；
  - 每 30 秒一次；
  - 连不上云端时，每 10 秒试一次 `/health`，一连上就立刻同步。
- **同一时间只跑一轮。** 这一轮还没跑完时又被触发，就等这一轮跑完后再跑一次。

### 5.3 合并和冲突

- **字段的单位是「列」。** 例如接口的 `name`、`method`、`url` 各算一个字段；`headers`、`params`、`body`、`auth`、`scripts` 这类 JSON 列，各自整块算一个字段，不深入到里面的某一行。
- 对每一列，比较「基线 / 我的 / 云端的」三份：
  - 只有一边改了：用改了的那边；
  - 两边改成一样：没问题；
  - 两边改得不一样：**冲突**。
- **位置类的列**（`folder_id`、`parent_id`、`position`）冲突时，用云端的（云端代表「后推上去的」），不提示。
- **有冲突的行：**
  - 本机保留我的版本，写进 `sync_conflicts(entity, entity_id, fields_json, remote_row_json)`；
  - 这一行暂停推送，其他行照常同步；
  - 用户的选择：
    - 「用我的」：基线更新成云端的版本，再推送我的；
    - 「用云端的」：直接用云端的覆盖本机；
    - 「另存为副本」：只对接口有效。我的版本新建一个「原名（我的副本）」，原行用云端的版本。
- **一边删了、一边改了：** 保留改了的那份（取消删除，或者在本机重新建出来），提示一下。
- **很久没同步，删除标记已经被清理了**（`since` 早于云端保留的最早 `seq`）：云端返回 `410`。网关把还没同步的改动先另存出来，然后全量重新下载，再把这些改动按「新建」重新推上去，最后提示用户。

## 8. 安全

- 网关的安全措施不变：只监听 127.0.0.1，校验 Host、Origin，要求 `X-Apiloop` 请求头。
- `session.json` 的权限是 0600。云端会话令牌只在网关和云端之间用，不交给浏览器；浏览器拿到的是网关自己发的会话。
- 未登录空间不需要密码。网关只监听本机，这台电脑的使用者本来就能读 `~/.apiloop`。

## 9. 分阶段

| 阶段 | 内容 | 谁来做 |
|---|---|---|
| **L1 本机数据库和未登录模式** | 网关改成读写本机库（`lib/admin.js` 接到空间的库上）；未登录空间和本机用户；跳过登录；云端地址打包时写死（4.1），去掉设置页和「云端地址…」菜单；mock 地址改成 `/mock-<项目ID>/`。**这一步还不同步**：未登录时读写本机库；登录后仍是现在的转发模式，L3 再换成账号空间加同步 | session1 后端，session2 登录页和「仅本机」状态 |
| **L2 云端同步接口** | 迁移 v6（rev、deleted、changes），仓储层统一维护；所有查询加 `deleted = 0`；四个同步接口；删除标记 30 天清理 | session1（和 L1 同时做） |
| **L3 同步引擎** | 账号空间、待同步列表、基线、拉取、推送、三方合并、冲突表；登录时上传未登录空间；离线登录；断网暂存、恢复后自动同步；`/__apiloop/sync/status` | session1（L1、L2 之后） |
| **L4 同步界面** | 顶栏同步状态、树上的标记、冲突对比和处理、账号菜单、退出 | session2（L3 的接口定下来就能开始） |

- **L1 做完就能用：** 装好后跳过登录，完全在本机用，不需要云端。
- L3 完成后，第一期的「转发模式」整个删掉（`lib/gateway/cloud.js` 里的转发器，以及 `send/prepare`、`send/record` 在网关这一侧的调用）。云端的这两个接口留着，没有坏处。
- G3（Mac 安装包收尾、下载入口）不受影响，可以先做。G3 Task 3 下载对话框里「填云端地址」那一步去掉，改成「装完可以直接用，要同步就登录」。

## 10. 风险和审阅重点

- **仓储层有没有漏掉的写入：** 只要有一处直接写表、绕过了仓储层，云端那一行就不会进变更记录，本机那一行也不会进待同步列表，这一行就永远不会同步。审阅时要 grep 所有 `INSERT`、`UPDATE`、`DELETE`。
- **`deleted = 0` 有没有漏：** 漏一处，已删除的东西就会重新出现在页面上。
- **`lib/admin.js` 能不能换库：** 现在的代码可能在启动时就固定了库（比如 `project-stores.js`）。L1 的计划要先查清楚，切换空间时怎么换库。
- **同步正确性：** 审阅时专门推演这些情况，并用一次性脚本，起两个网关加一个云端实际跑一遍：
  - 断网期间两边都改了同一行；
  - 推送到一半断网；
  - 同一个账号在两台电脑上用；
  - 一边删除、一边修改；
  - 上传未登录空间到一半断网；
  - 换账号以后，A 的数据 B 看不到。
- **离线登录：** 密码摘要只存在本机。云端改了密码以后，本机离线时仍然能用旧密码进入；下次联网登录时，用新密码校验通过后会更新本机的摘要。这一点要写进使用说明。
