# apiloop 本地优先：本机存数据、登录后自动同步

> 状态：第 2 版（2026-10-01，用户选了「方案 1」之后重写）。L1、L2 已经按第 1 版完成，第 3、4、5.2、7、9 节按第 2 版改写。
> 取代 `2026-10-01-local-agent.md` 的第 6、7 节（第二期）以及第 8 节里的 G4、G5。那份设计稿其余部分（网关、安全、安装包）继续有效。

## 1. 用户的要求和已确认的决定

**原话：**
- 「本地安装完，登录页面可以选择跳过登录；所有数据都保存在本地，如果登录后，所有数据自动同步到云上；如果没有网络的情况下，本地所有改动暂存，等网络恢复自动同步。」
- 「上传后本机保留一份，而且登录后理论上要从线上同步到本地吧。如果下次退出登录，本地的不能丢掉啊。」（选了方案 1）

**讨论中确认的（2026-10-01）：**

| 问题 | 决定 |
|---|---|
| 本机数据和账号的关系 | **方案 1：本机只有一份数据，跟着最后登录的账号走。** 登录了就和这个账号双向同步；退出登录后数据全都还在，照常能看、能改、能发请求，只是不同步；下次登录同一个账号，把退出期间的修改同步上去 |
| 没登录过时建的项目 | 第一次登录时**全部自动上传**到这个账号，你是所有者；本机保留，之后照常同步 |
| 换另一个账号登录 | 上一个账号的数据收起来，仍然存在本机，不删除，换回来时还在；页面显示新账号的数据 |
| 公用电脑 | 账号菜单里有「退出并删除本机数据」 |
| 两边改了同一处 | 不同字段自动合并；同一字段两边改得不一样时，让用户选「用我的 / 用云端的 / 另存为副本」 |
| 整体做法 | 网关自带本机数据库，页面读写都走本机，网关在后台和云端同步 |
| mock 地址 | `/mock-<项目ID>/<接口路径>`（L1 已完成） |
| 要不要拆成两个项目 | 不拆。一套代码两种运行方式：云端 `apiloop web`，本机 `apiloop gateway` |
| 云端发送 | 保留。直接打开云端网页照常能编辑、发送 |
| 同步范围 | 项目、目录、接口、示例、mock 期望、环境双向同步；用户、成员、角色只从云端拉取；历史请求、Cookie、上传的文件只存本机 |

## 2. 整体结构

```
浏览器页面 ──► 本机网关（127.0.0.1:47321）
                ├─ 当前空间的 SQLite（表结构和云端相同）◄── 页面所有读写都落这里
                ├─ 本机发请求（send-core，已有）
                ├─ 只有云端有的功能 ──（已登录时转给云端）──► 修改密码、用户管理、成员管理、mock 日志、安装包列表
                └─ 同步引擎 ──（已登录、有网时）──► 云端 /__admin/api/sync/*
```

- 页面调的接口和直接打开云端时**完全一样**（`/__admin/api/projects/...`）。网关用同一份 `lib/admin.js`，背后是本机的库。
- **L3 起，网关不再把数据接口转发给云端**，第一期的「转发模式」整个删掉。连云端的只有三类：登录、只有云端有的功能（见 4.5）、同步。
- **代码怎么分：** `lib/gateway/`（只在本机）、`lib/sync/`（只在云端），其余两边共用。

## 3. 空间

### 3.1 存放位置

```
~/.apiloop/spaces/local/                         从没登录过时用的空间（「未绑定」）
~/.apiloop/spaces/<云端主机>~<端口>~<账号ID>/      每个登录过的账号一个
    data.db          同步的数据 + 只存本机的历史、Cookie + 同步用的表（sync_base、sync_conflicts）
    session.json     云端会话（权限 0600）；退出登录时清掉
~/.apiloop/gateway.json                          当前空间（以及开发时手动覆盖的云端地址）
```

- 目录名里带云端地址，连不同的云端（测试环境、正式环境）不会混。
- 上传的文件仍然放在 `~/.apiloop/files/<项目ID>/`。项目 ID 全局唯一，不会混。
- **同一时间只有一个「当前空间」**，网关只打开它的库。切换空间时先关掉当前的库，再打开另一个，页面整页刷新。

### 3.2 当前空间的三种状态

| 状态 | 身份 | 同步 | 什么时候进入 |
|---|---|---|---|
| **未绑定**（`spaces/local`） | 本机用户 `u_local`（没有密码，系统角色 admin） | 不同步；本机的修改照常记在变更记录里，第一次登录时一起上传 | 装好后第一次打开；「退出并删除本机数据」之后 |
| **已登录** | 云端账号（`users` 表从云端镜像） | 双向自动同步 | 登录成功 |
| **已退出** | 仍是这个账号（本机库里的那一行） | 暂停；修改照常记下，下次这个账号登录时推上去 | 退出登录；云端会话过期 |

- **打开 apiloop 直接进入当前空间的数据，不需要先登录。** 浏览器没有本机会话时，网关直接发一个当前空间身份的会话。登录只在想同步时，从菜单进入。
- **未绑定状态下 mock 不可用**（mock 服务在云端，页面上显示「登录后可用」）。已登录、已退出时都能用：mock 地址指向云端，那里的数据是同步上去的。

## 4. 登录、退出

### 4.1 云端地址：打包时写死（L1 已完成）

打安装包时用 `APILOOP_CLOUD_URL` 写进 `app/cloud.json`。网关读地址的优先级：`--cloud` → `gateway.json` → `app/cloud.json`。界面上没有改地址的地方。

### 4.2 登录页

- 账号密码表单。只能从菜单进入。
- 下面一个链接「不登录，继续在本机使用」，回到工作台。
- 登录**必须联网**。连不上云端时提示「连不上云端，登录需要联网。不登录也可以继续在本机使用」。（第 1 版的「离线登录」去掉：退出后数据照样能用，不需要离线登录。）

### 4.3 登录流程（网关自己处理 `POST /__admin/api/auth/login`）

1. 网关拿账号密码去云端登录，拿到云端会话和账号 U。失败就把云端的错误原样返回。
2. 决定登录后用哪个空间：
   - **当前就是 U 的空间：** 直接用，继续同步。
   - **当前是未绑定空间：**
     - U 在本机还没有空间：把 `spaces/local` 改名成 U 的空间目录，库里的 `u_local` 换成 U（成员、创建人、历史、Cookie 里的用户 ID 一起换）；
     - U 在本机已经有空间（以前登录过）：把未绑定空间里的项目整个搬进 U 的空间，连历史一起搬；搬进去的行都算「本机新建、还没同步」，然后删掉未绑定空间。
   - **当前是另一个账号 V 的空间：** V 的空间原样留在磁盘上；切换到 U 的空间，本机没有就新建一个空的。
3. 写 `session.json`，把 `gateway.json` 的当前空间改成 U 的，给浏览器发一个 U 身份的本机会话。
4. 立刻开始一轮同步：本机还没同步的（包括刚上传的那些项目）推上去，云端有、本机没有的项目下载下来。页面上显示「正在同步」。
5. 云端返回「需要先改密码」时：本机库里 U 的那一行打上同样的标记，页面跳到「请先修改密码」。改密码的请求转给云端（见 4.5），成功后清掉本机的标记，并换上云端发的新会话。

### 4.4 退出

- 账号菜单：
  - 「**退出登录**」：清掉 `session.json` 里的云端会话（顺手通知云端注销），**当前空间不变，数据全都在**，状态变成「已退出 · 不同步」。
  - 「**退出并删除本机数据**」：先提示「还有 N 项没同步，删除后会丢失」，确认后关掉库、删除当前空间目录，换成一个新的空的未绑定空间。
- 云端会话过期（同步时云端返回 401）：同步暂停，状态显示「登录已过期」，点一下去登录页。本机照常使用，修改先记着。

### 4.5 只有云端有的功能

这些数据不同步，只在云端：修改密码、用户管理、成员管理、mock 日志、安装包列表。

- **已登录时：** 网关把请求转给云端，带上 `session.json` 里的云端会话（浏览器手里只有本机会话）。成员变了以后，立刻同步一轮，让本机的成员表跟上。
- **未绑定、已退出时：** 返回 409 `{ code: 'LOGIN_REQUIRED', error: '这个功能要先登录' }`，页面上这些入口提示「登录后可用」。
- 涉及的接口：`PUT /auth/password`、`/users`（含 `/users/lookup`）、`/projects/:pid/members…`、`/projects/:pid/mock-log…`、`/downloads`。

## 5. 同步

### 5.1 云端（L2 已完成：迁移 v7，`lib/sync/`）

- 6 张表各有 `rev`；`changes` 表由触发器维护，删除真删并写一条删除记录；30 天前的记录定期清理。
- 接口：`GET /sync/state`、`GET /sync/projects/:pid/snapshot`、`GET /sync/changes?since=`、`POST /sync/push`。细节见 `docs/superpowers/plans/2026-10-01-local-first-l1-l2.md` Task 7。

### 5.2 本机（`lib/gateway/sync/`）

- **待同步列表就是本机库自己的 `changes` 表**（v7 的触发器在本机库里同样会记下每次修改）。不另建表。
  - 待同步的行 = `changes` 里出现过的 `(entity, entity_id)`；
  - 推送成功后删掉这一行在 `changes` 里的记录；
  - **从云端拉下来、应用到本机的修改不能算成待同步**：应用时在同一个事务里，记下应用前的最大 `seq`，应用完删掉比它大的那些记录。
- **基线：** 网关建的表 `sync_base(entity, entity_id, rev, row_json)`，存「上次和云端对齐时这一行是什么样」，包括云端的 `rev`。推送时的 `baseRev` 就从这里取，没有就是 0（本机新建的）。
- **游标：** `meta` 里记 `sync_seq`（拉到了云端的哪一条）。
- **把云端的行应用到本机：**
  - 行已存在就 UPDATE 所有列（包括 `rev`），不存在才 INSERT；**不能用 `INSERT OR REPLACE`**，REPLACE 会先删行，外键级联会把子行一起删掉；
  - 插入按「父级在前」，删除按「子级在前」。
- **一轮同步：**
  1. `sync/state`：
     - 镜像用户和成员表（本机库里的 `users`、`project_members` 改成和云端一致；镜像来的用户 `password_hash` 为空串）；
     - 云端有、本机没有的项目：下载 snapshot，全部应用，记下基线；
     - 本机有基线、云端不再列出的项目（被删了，或者自己被移出了成员）：从本机删掉；里面有没同步的修改时，提示「项目 X 已不能访问，N 项本机修改没能同步」。
  2. 拉取 `sync/changes`，直到 `hasMore = false`：
     - 本机没改过的行（不在待同步列表里）：直接应用，更新基线；
     - 本机也改过的：按 5.3 合并。
  3. 推送待同步列表，每批最多 200 条，父级在前（项目 → 环境 → 目录（父目录在前）→ 接口 → 示例 → 期望），删除的子级在前：
     - `ok`：更新基线，删掉这一行的待同步记录；
     - `conflict`：按 5.3 合并；
     - `forbidden`：用云端的版本覆盖本机，提示「你在项目 X 里是只读成员，修改没有保存到云端」；
     - `invalid`：留着，状态栏显示错误。
- **什么时候同步（只在已登录时）：** 登录后；网关启动时；本机写入后约 2 秒（多次写入合并成一次）；每 30 秒一次；连不上云端时每 10 秒试一次，一连上立刻同步。**同一时间只跑一轮**，跑的时候又被触发，就等这一轮跑完再跑一次。

### 5.3 合并和冲突

- **字段的单位是「列」。** 接口的 `name`、`method`、`url` 各算一个字段；`headers`、`params`、`body`、`auth`、`scripts` 这类 JSON 列，各自整块算一个字段。
- 对每一列，比较「基线 / 我的 / 云端的」三份：只有一边改了，用改了的那边；两边改成一样，没问题；两边改得不一样，**冲突**。
- **位置类的列**（`folder_id`、`parent_id`、`position`）冲突时用云端的，不提示。
- **有冲突的行：** 本机保留我的版本，写进网关建的表 `sync_conflicts(entity, entity_id, fields_json, remote_row_json, created_at)`；这一行暂停推送，其他行照常同步。用户选：
  - 「用我的」：基线换成云端的版本，再推送我的；
  - 「用云端的」：用云端的覆盖本机；
  - 「另存为副本」：只对接口有效。我的版本新建成「原名（我的副本）」，原行用云端的版本。
- **一边删了、一边改了：** 保留改了的那份（取消删除，或者在本机重新建出来），提示一下。
- **很久没同步，云端的变更记录已经被清理**（返回 410）：把还没同步的修改先另存出来，全量重新下载，再把这些修改按「新建」推上去，最后提示用户。

## 7. 页面

- **打开就进入工作台**，不经过登录页。登录页只能从菜单进入，带「不登录，继续在本机使用」。L1 的「跳过登录，先在本机用」按钮去掉。
- **顶栏状态：**

  | 状态 | 显示 | 点开 |
  |---|---|---|
  | 未绑定 | 灰点「仅本机」 | 「登录以同步到云端」 |
  | 已退出 | 灰点「未登录 · 不同步」 | 「登录」 |
  | 已登录、已同步 | 绿点「已同步」 | 最近同步时间 |
  | 正在同步 | 转圈「同步中」 | |
  | 有修改没同步上 | 黄点「N 项待同步」；连不上云端时「离线 · N 项待同步」 | |
  | 有冲突 | 红点「N 个冲突」 | 冲突列表 |
  | 登录过期 | 红点「登录已过期」 | 去登录页 |

  网关提供 `GET /__apiloop/status`，在原有字段上加 `space: { state: 'unbound'|'signedIn'|'signedOut', user }` 和 `sync: { running, online, pending, conflicts, lastSyncAt, lastError, expired }`。页面每 3 秒问一次。
- **账号菜单：**
  - 未绑定：「登录以同步到云端」「关于」；
  - 已登录：「修改密码」「用户管理」（admin）「关于」「退出登录」「退出并删除本机数据」；
  - 已退出：「登录」「关于」「删除本机数据」。
- **只有云端有的功能**（4.5）在未绑定、已退出时，入口显示「登录后可用」。
- **目录树：** 待同步的行名字后面加一个小点；有冲突的显示红色感叹号。
- **冲突处理：** 打开有冲突的接口，顶部一条红色提示；点开是对比窗口，左「我的」右「云端的」，只列冲突的字段；三个按钮「用我的」「用云端的」「另存为副本」。
- **直接打开云端网页：** 不变。

## 8. 安全

- 网关的安全措施不变：只监听 127.0.0.1，校验 Host、Origin，要求 `X-Apiloop` 请求头。
- `session.json` 权限 0600。云端会话只在网关和云端之间用，不交给浏览器；浏览器拿到的是网关自己发的本机会话。云端会话不写进日志。
- 打开就进入数据、不需要密码：网关只监听本机，能打开这个页面的人本来就能读 `~/.apiloop`。

## 10. 风险和审阅重点

- **应用云端的行不能用 `INSERT OR REPLACE`**（会级联删掉子行）。
- **拉下来的修改不能被当成待同步推回去**，否则两台电脑会来回推同一行。
- **同步正确性：** 审阅时用一次性脚本起两个网关加一个云端，实际跑这些情况：
  - 断网期间两边都改了同一行；
  - 推送到一半断网；
  - 同一个账号在两台电脑上用；
  - 一边删除、一边修改；
  - 第一次登录上传到一半断网；
  - 换账号以后，A 的数据 B 看不到；换回 A，A 的数据还在；
  - 退出登录后修改，再登录同一个账号，修改推了上去。
- **账号切换时关库、改名目录：** 改名前一定先关掉库连接（WAL 文件也要一起搬）；改名失败要能退回。
