# apiloop 本地网关：网页版 + 本机发请求 + 断网可用（完整设计）

> 取代 `2026-10-01-desktop-sync.md`（Electron 桌面版），它的同步协议（第 5、6 节）在本文第 7 节里沿用、并按新形态调整。

## 1. 背景和已确认的事

**为什么不做 Electron 桌面版：** D0 实测，在 macOS 15 及以后的版本上，没有苹果签名的程序访问同网段地址时，系统直接拒绝，也不弹授权框。用户不签名。（`reviews/2026-10-01-desktop-d0-review.md` 第 3 轮）

**找到的出路：** 让**官方 Node**（Node.js 基金会签名，Team ID `HX7739G8FX`）作为 launchd 后台任务运行。第一次访问局域网时系统会弹授权框，允许之后就能访问同网段地址。（同一份文档第 4 轮，实测通过）

**用户确认过的事：**

| 问题 | 结论 |
|---|---|
| 形态 | 「网络版最好，本地加个代理直接发送」 |
| 安装 | 一次性安装包，没有依赖，不签名。Mac 和 Windows |
| 云端协议 | 现在是 http，以后可能改成 https |
| 浏览器 | 所有浏览器都要能用：Chrome、Edge、Safari、Firefox |
| 授权框里显示「node」 | 可以接受 |
| 断网可用 | **要一起设计完整**（分期实现） |
| 账号 | 在云端。登录后信息存本地；数据拉到本地，有网时同步 |
| Mock | 在云端 |
| 只同步什么 | 项目（包括目录树）、请求（包括示例、mock 期望）、环境；历史、Cookie、上传的文件只存本机 |

## 2. 核心决定：本地网关，页面从本机打开

一开始的想法是：用户打开**云端**页面，页面跨域调用本机的代理。这条路有三个绕不过去的坑：
- Safari 不允许 HTTPS 页面访问 `http://127.0.0.1`（混合内容），而云端以后会改 https；
- Chrome 会对「公网页面访问本机」额外弹一次授权；
- 断网时，云端页面根本打不开。

所以改成：**本地网关自己提供 apiloop 的页面**，用户打开 `http://127.0.0.1:47321`（安装包会在桌面、启动台、开始菜单放一个「apiloop」图标，点它就用默认浏览器打开这个地址）。

- **页面和发请求在同一个来源下，**不存在跨域、混合内容、浏览器授权这些问题。所有浏览器都一样，云端是 http 还是 https 都无所谓。
- **数据接口由网关转发给云端。**第一期是在线转发；第二期改成本地数据库加同步，界面和用法完全不变。
- **直接访问云端地址也照样能用**：查看、编辑、管理账号都可以，只是没有「发送」（页面上提示「请从本机的 apiloop 打开」，并给出链接）。

```
浏览器 ── http://127.0.0.1:47321 ──▶ 本地网关（每台电脑一个，开机后在后台运行）
                                     ├─ 页面：现有的 Vue 前端（随安装包带上，和云端版本一致）
                                     ├─ 发请求：现有的执行器、脚本沙箱、流式发送、WebSocket，在本机执行
                                     ├─ 数据接口：
                                     │    第一期 在线转发到云端
                                     │    第二期 读写本地数据库，后台和云端同步
                                     └─ 运行在官方 Node 上（Mac 借用 Node 的签名拿到本地网络权限）
                                         ⇅ http(s)
                                     云端：账号、成员、权限、项目数据、mock、mock 日志
```

## 3. 本地网关（`apiloop gateway`）

现有 `lib/` 增加一种运行模式。它和云端是**同一套代码**，用启动参数区分：

| | 云端模式（现在的 `apiloop web`） | 网关模式（新的 `apiloop gateway --cloud <地址>`） |
|---|---|---|
| 监听 | 对外开放 | 只监听 `127.0.0.1:47321`（被占用时依次试 47322–47329） |
| 页面 | 提供 | 提供 |
| 账号、成员管理 | 自己负责 | 转发给云端 |
| 项目数据 | 自己的数据库 | 第一期：转发给云端；第二期：本地数据库加同步 |
| 发请求 | **关闭**（`--server-send` 才打开，留给本机自用） | **在本机执行** |
| 历史、Cookie、上传的文件 | 第一期：仍然存云端；第二期起不再存 | 第二期起存本机（用户确认：只存本机） |
| mock | 提供 | 不提供（mock 地址在云端） |

### 3.1 安全

本地网关能访问你的内网，必须保证**只有你自己从浏览器打开的 apiloop 页面**能用它：

- 只监听 `127.0.0.1`。
- **拦住其他网站：**
  - 所有 `/__admin/api/*` 接口都要求带自定义请求头 `X-Apiloop: 1`，并且 `Origin`（如果有的话）必须是网关自己的地址。
  - 其他网站的页面如果想带这个请求头跨域调用，浏览器会先发预检请求，网关一律拒绝。这样别的网站既读不到数据，也没法借网关发请求。
- **防 DNS 重绑定：** 检查 `Host` 必须是 `127.0.0.1:<端口>` 或 `localhost:<端口>`。
- 不需要配对对话框：页面和接口同源，上面这几条已经够了。

### 3.2 登录

- **第一期（在线转发）：** 浏览器在网关页面上登录，网关把登录请求转发给云端，把云端返回的会话 Cookie 改写成网关自己的 Cookie。之后的数据请求，网关带上对应的云端会话再转发。效果等于「在本机打开了云端」。
- **第二期（本地数据）：** 网关用设备令牌和云端同步（沿用旧设计稿第 6 节）：
  - 令牌加密保存在本机：Mac 用钥匙串，Windows 用 DPAPI。Node 没有现成的接口，要通过系统命令 `security` 或 PowerShell 来调用；
  - 离线时用本地缓存的用户信息进入；
  - 换账号时，每个账号各用一个本地数据库。
- **多用户的电脑：** LaunchAgent 是按登录用户分别启动的，每个用户各自一个网关，端口各自探测，数据各自独立。

### 3.3 一次「发送」（第一期）

数据还在云端，所以：
1. 网关向云端要发送上下文：`POST /projects/:pid/send/prepare`，返回合并好的变量、继承的鉴权、脚本链、Cookie、代理设置，以及文件内容（如果有）。
2. 在本机执行，把结果流式返回给页面（NDJSON，格式和现在的 `/send/stream` 一样）。
3. 把结果交给云端：`POST /projects/:pid/send/record`，由云端写历史、落库变量修改（只有 editor 才写）、保存 Cookie。

为此，`lib/api/send.js` 要拆成三段纯函数：「准备上下文」「执行」「记录结果」。云端用一、三两段，网关用第二段；`--server-send` 模式三段串起来用，行为和现在完全一样，**现有测试都要继续通过**。

第二期数据都在本地，三段都在网关里执行，不需要再跟云端来回。

**第一次访问局域网（Mac）：** 授权框还没点掉时，请求必然失败，报 `EHOSTUNREACH`。网关识别出「目标是私有地址，而且是这个错误」，就返回明确的提示：「请在系统弹出的『本地网络』授权框中点允许，然后重试。如果没看到弹框，到『系统设置 → 隐私与安全性 → 本地网络』里打开 node。」

## 4. 页面（前端）

- 页面运行在网关上，大部分代码不用改。要改的有：
  - **顶栏状态：**「已连接云端」或者「离线 · N 项待同步」（离线状态是第二期的），以及冲突提示；
  - **直接访问云端时：**「发送」按钮不可用，提示「请从本机的 apiloop 打开」，并附安装包下载链接；
  - **版本提示：** 网关和云端的版本不一致时，提示去下载新的安装包。
- **第二期：** 冲突处理界面（用我的 / 用云端的 / 另存为副本）、树上标记未同步的项。

## 5. 安装包

| | Mac | Windows |
|---|---|---|
| 格式 | `.pkg`，用系统自带的 `pkgbuild` / `productbuild` 制作；arm64、x64 各一个 | `.exe`（NSIS）。在这台 Mac 上制作需要 Rosetta，或者在 Windows 上制作 |
| 内容 | 官方 Node（nodejs.org 的构建，**签名原样保留**）+ `lib/`（含页面）+ 生产依赖 | 官方 `node.exe` + 同样的内容 |
| 位置 | `/Library/Application Support/apiloop/` | `%LOCALAPPDATA%\apiloop\` |
| 后台运行 | `/Library/LaunchAgents/com.apiloop.gateway.plist`，登录后启动，崩溃后自动重启；安装完立即启动 | 当前用户的「启动」项，用隐藏窗口的启动脚本，不弹黑色窗口 |
| 入口 | 「应用程序」里一个 `apiloop.app`：一个很小的启动器，作用就是用默认浏览器打开网关地址。它不发请求，所以签不签名都没关系 | 桌面和开始菜单的「apiloop」快捷方式 |
| 云端地址 | 安装后第一次打开时，在网关页面里填写，保存在本机 | 同左 |
| 第一次使用 | 打开安装包时点「仍要打开」；第一次发局域网请求时，系统弹「允许 node 访问本地网络」 | 无。只监听 127.0.0.1，不会触发防火墙提示 |
| 卸载 | 安装目录里的 `卸载 apiloop.command` | 系统的「卸载程序」 |
| 更新 | 手动下载新的安装包，覆盖安装 | 同左 |

**硬性要求：** Mac 安装包里的 node，`codesign -dv` 必须显示 `TeamIdentifier=HX7739G8FX`。审阅时逐个核对，打包流程里任何一步都不能对它重新签名。

## 6. 第二期：断网可用（本地数据库加同步）

网关改成「本地优先」：页面的所有读写都走网关的本地数据库（SQLite，现有的表结构），网关在后台和云端同步。有网没网用起来一样。

**同步范围：**
- 双向同步：项目（含变量、鉴权、脚本、mock 设置）、目录、接口、示例、mock 期望、环境；
- 只拉取、不上传：用户、成员、角色；
- 只存本机：历史、Cookie、上传的文件；
- 联网时直接读云端：mock 日志。

## 7. 同步协议（第二期，沿用旧设计稿第 5 节并调整）

- **云端：**
  - 需要同步的表加 `rev`（每改一次加一）和 `deleted`（删除只打标记，定期清理）；
  - 新表 `changes(seq, project_id, entity, entity_id)`；
  - 接口：
    - `GET /sync/projects/:pid/changes?since=<seq>`：返回这之后变化过的完整行；
    - `POST /sync/projects/:pid/push`：批量提交，每条返回 `ok`（新的 rev）、`conflict`（附云端当前那一行）或 `forbidden`；
    - 设备令牌的签发和吊销。
  - **这些放在迁移 v6。** 现有数据都是测试数据，不用为旧数据补版本号，上线时可以清空重建。
  - 云端网页上的增删改也要维护 `rev` 和 `changes`。
- **网关：**
  - 主键在本地生成（现有的 `newId()` 不会撞）；
  - `sync_outbox` 记录待同步的行，同一行改多次只算一条；
  - `sync_base` 存「上次和云端对齐时的版本」，用于三方合并。
- **一轮同步：**
  1. 先拉取：本地没改过的直接覆盖，改过的走合并；
  2. 再推送；
  3. 根据结果更新基线、清掉已完成的标记。
- **什么时候同步：** 启动时；本地写入后约 2 秒；每 30 秒一次；网络恢复时立刻同步。判断有没有网，以能不能访问云端的 `/health` 为准。
- **冲突：**
  - 按字段三方合并：两边改了不同字段，自动合并；
  - 同一个字段两边改得不一样：标红，让用户选「用我的 / 用云端的 / 另存为副本」（另存为副本只用于接口）；
  - 一边删除、一边修改：保留修改的那份，并提示用户；
  - 目录树里的位置和排序冲突：以后改的为准，不提示。
- **第一期到第二期的切换：** 第一期本地没有数据。第二期第一次启动时全量拉取，之后增量同步。用户无感。

## 9. 风险

- **G0 要验证的：**
  - 官方 Node 作为 LaunchAgent 长期运行时，授权会不会一直有效；
  - 覆盖安装新版本（node 还是同一个官方构建）之后，要不要重新授权。
  - 如果升级了 Node 的版本，授权框可能会再弹一次，使用说明里要写。
- **在线转发第一期**：会话 Cookie 的改写、大文件上传的转发、流式接口的转发，都要仔细处理。
- **同步正确性（第二期）**：审阅时专门推演这几种情况：断网期间两边都改了同一行；推送到一半断网；同一个账号在两台电脑上用；一边删除一边修改。
- **安装包不签名**：Mac 和 Windows 第一次运行都会被拦一次，使用说明里配截图。
