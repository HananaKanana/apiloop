# apiloop 本地代理：网页版 + 本机发请求（设计稿）

> 状态：草稿，等用户确认。
> 取代 `2026-10-01-desktop-sync.md`（Electron 桌面版）。那份设计稿的第 5 节（同步协议）留给本设计的第二期参考。
> 优先级：**最高**。

## 1. 为什么改方案

桌面版（Electron 安装包）在 D0 实测时卡住了，详见 `reviews/2026-10-01-desktop-d0-review.md` 第 3、4 轮：

- **问题：** 在 macOS 15 及以后的版本上，没有苹果签名的程序访问同网段地址时，系统直接拒绝，也不弹授权框。用户不想花钱签名。
- **找到的出路（已实测）：** 让**官方 Node**（Node.js 基金会签名）作为 launchd 后台任务运行，系统会正常弹授权框，用户允许一次之后就能访问同网段地址。
- **同时也更符合用户想要的形态：** 「网络版最好，本地加个代理直接发送」，也就是 Postman 网页版加 Desktop Agent 那种模式。

## 2. 用户的要求

| 要求 | 本方案怎么满足 |
|---|---|
| 请求从本机发出，能访问内网 | 本地代理在本机发请求 |
| 平时用网页版 | 浏览器打开云端地址，界面、账号、数据都和现在一样 |
| 一次性安装包，没有依赖 | Mac 用 `.pkg`，Windows 用 `.exe`，里面自带官方 Node，双击安装 |
| 不签名 | 我们自己的东西都不签名；Mac 上真正发请求的是官方 Node，借用它的签名 |
| 断网也能用（最早的三点要求） | 第二期：本地代理同时提供一份本地镜像，并负责同步 |

## 3. 整体架构

```
浏览器 ── 打开 https://<云端地址>（apiloop 网页版，和现在一样）
  │  ① 数据读写：项目、接口、环境、历史 → 云端
  │  ② 点「发送」：先向云端要「发送上下文」→ 交给本地代理执行 → 把结果交回云端记录
  ▼
本地代理（每台电脑一个，开机自动在后台运行，只监听 127.0.0.1:47321）
  ├─ 自带官方 Node 运行时（Mac：Node.js 基金会签名，原样保留）
  ├─ 执行器、脚本沙箱、流式发送、WebSocket 调试会话：都是现有 lib/ 的代码，直接复用
  └─ 不连云端、不存数据：只负责「按页面给的东西发请求，把结果还给页面」

云端：apiloop 服务端（现有代码）
  ├─ 账号、成员、权限、项目数据、历史、Cookie、mock：都不变
  └─ 不再自己发请求，改成提供「发送上下文」和「记录结果」两个接口
```

### 3.1 为什么本地代理不直接连云端

如果本地代理自己去连云端，它就得有云端的登录凭证，还要处理登录过期、多账号这些事。改成由**页面来居中协调**：
- 页面本来就登录着，由它向云端要数据，再交给本地代理；
- 本地代理拿到结果后还给页面，页面再交给云端保存。

这样本地代理就是一个**无状态的执行器**：没有账号，不存数据，非常简单。

### 3.2 一次「发送」的流程

1. 页面调用云端 `POST /projects/:pid/send/prepare`，提交 `{ request, environmentId, apiId }`。云端返回**发送上下文**：
   - 合并好的各层变量（项目 → 目录链 → 环境）；
   - 继承下来的鉴权；
   - 前后置脚本链；
   - 这个项目的 Cookie；
   - 代理设置；
   - 如果 form-data 里有文件：文件内容（base64）。
   这一步就是现在 `send.js` 里 `prepareSend` 所做的事，从里面拆出来。
2. 页面把发送上下文交给本地代理：`POST http://127.0.0.1:47321/agent/send/stream`（NDJSON 流，格式和现在的 `/send/stream` 一样）。本地代理执行脚本、发出请求，把结果流式返回。返回的结果里包括：
   - 响应；
   - 脚本运行结果；
   - 脚本对变量的修改；
   - 新收到的 Cookie。
3. 页面把结果交给云端 `POST /projects/:pid/send/record`。云端：
   - 写入历史（保持现在的脱敏规则）；
   - 落库脚本对变量的修改（保持现在的规则：只有 editor 才写）；
   - 保存新的 Cookie。
4. 云端原来的 `/send`、`/send/stream` 默认关闭。只有启动参数 `--server-send` 打开时才可用，留给本机自用的场景。

**WebSocket 调试会话**：会话放在本地代理里。页面直接连本地代理的 `/agent/ws/...`，接口和现在云端的 `/ws/...` 一样。

### 3.3 页面怎么找到本地代理

- 本地代理固定监听 `127.0.0.1:47321`。如果端口被占用，就用后面几个备用端口，比如 47322、47323。页面依次探测 `/agent/hello`。
- 页面右上角显示状态：
  - 「本地代理已连接 v2.x」；
  - 「未检测到本地代理」，附下载链接和启动方法；
  - 版本和云端不一致时，提示更新。
- 没有本地代理时，「发送」按钮不可用，并提示去安装。

### 3.4 安全：不能让任意网站借本地代理访问内网

本地代理能访问你的内网。如果任何网页都能调用它，恶意网站就能借它扫描内网。所以：

- **只监听 127.0.0.1。**
- **按来源（Origin）放行：** 只接受白名单里的网站发来的请求。浏览器发出的 `Origin` 请求头，网页没法伪造。
- **第一次配对：** 某个网站第一次连接本地代理时，本地代理弹一个**系统对话框**：「是否允许 https://<云端地址> 使用 apiloop 本地代理？」。Mac 用 `osascript`，Windows 用 PowerShell 弹窗。点「允许」后，这个网站写入白名单。
- **跨域和浏览器限制：**
  - 正确回应 CORS 预检；
  - 正确回应 Chrome 的「访问本地网络」预检（`Access-Control-Request-Private-Network` → `Access-Control-Allow-Private-Network: true`）。

### 3.5 浏览器侧的限制（第一步就要验证）

- **Chrome / Edge：** HTTPS 的公网页面访问 `http://127.0.0.1`，浏览器会弹一次「允许此网站访问本地设备上的应用和服务」，允许后就可以了。
- **Safari：** HTTPS 页面访问 `http://127.0.0.1` 可能被当作「混合内容」拦截，需要实测。如果不行，就让本地代理同时提供 `https://localhost`（安装时生成证书并加入信任），或者在使用说明里写明请用 Chrome / Edge。
- **云端如果是 http 而不是 https**，不存在混合内容的问题。

## 4. 安装包

| | Mac | Windows |
|---|---|---|
| 格式 | `.pkg`。用系统自带的 `pkgbuild` / `productbuild` 制作，不需要额外工具；arm64 和 x64 各一个 | `.exe`（NSIS）。在这台 Mac 上制作需要装 Rosetta，或者在 Windows 电脑上制作 |
| 内容 | 官方 Node（nodejs.org 的构建，**签名原样保留**，不经过任何重新签名）+ `lib/` + 生产依赖 | 官方 `node.exe` + `lib/` + 生产依赖 |
| 安装位置 | `/Library/Application Support/apiloop/` | `%LOCALAPPDATA%\apiloop\` |
| 开机自动运行 | `/Library/LaunchAgents/com.apiloop.agent.plist`（登录后运行）；安装完立即启动 | 当前用户的「启动」项。用一个隐藏窗口的启动脚本，不弹黑色命令行窗口 |
| 第一次使用 | 打开安装包时点「仍要打开」（安装包没签名）；第一次发局域网请求时，系统弹「允许 node 访问本地网络」 | 无特别操作。只监听 127.0.0.1，不会触发防火墙提示 |
| 卸载 | 安装目录里放一个 `卸载 apiloop.command` | 系统自带的「卸载程序」 |
| 预计大小 | 约 40–50 MB | 约 35–45 MB |

**两条硬性要求：**
- **Mac 上必须用官方 Node，并且保持签名有效。** Homebrew 的 node 是 ad-hoc 签名，会被拦。审阅时要用 `codesign -dv` 确认 `TeamIdentifier=HX7739G8FX`。
- **第一次发往局域网的请求必然失败**，因为授权框还没被点掉。本地代理要识别出 `EHOSTUNREACH`，并且目标是局域网地址的情况，返回明确的提示：「请在系统弹出的『本地网络』授权框中点允许，然后重试」。

## 5. 现有代码要改的

- **新增：**
  - `lib/agent/`：本地代理的 HTTP 服务、来源白名单、配对对话框、`/agent/hello`、`/agent/send/stream`、`/agent/ws/...`；
  - 命令行入口 `apiloop agent`。
- **重构 `lib/api/send.js`：**
  - 把「准备上下文」拆成纯函数（云端 `send/prepare` 用）；
  - 把「执行并产出结果」拆成纯函数（本地代理用）；
  - 把「记录结果」拆成纯函数（云端 `send/record` 用）。
  - 本机自用的 `--server-send` 模式用这三段拼起来，行为和现在一样。
  - **现有的测试都要继续通过。**
- **WebSocket 调试会话**（`lib/ws-sessions.js`）：搬到本地代理里运行。
- **前端：**
  - 发送、流式发送、WebSocket 改为走本地代理；
  - 新增本地代理状态和下载入口；
  - 第一次局域网授权的提示。
- **打包：**
  - 新目录 `agent-installer/`：Mac pkg 和 Windows NSIS 的脚本；
  - D0 的 `desktop/`（Electron）不再需要，确认新方案可行后删除。

## 6. 分阶段

| 阶段 | 内容 | 负责 |
|---|---|---|
| **A0 验证** | 最小的本地代理（`/agent/hello` + 发一次请求 + CORS 和 PNA 预检）、Mac pkg（官方 Node + LaunchAgent）。用户安装后，在**云端网页**上用 Chrome 和 Safari 各试一次：探测本地代理 → 发同网段请求 | session1 出代码和安装包，用户在浏览器里验证 |
| **A1 服务端** | 拆分 `send.js`、新增 `send/prepare` 和 `send/record`、完整的本地代理（流式、WebSocket、配对、白名单）、关闭云端发送 | session1 |
| **A2 前端** | 本地代理探测和状态、发送改走本地代理、下载入口、授权提示 | session2 |
| **A3 安装包** | Mac pkg（arm64 和 x64）、Windows exe、卸载、使用说明 | session1 |
| 第二期 | 断网镜像 + 同步：本地代理提供本地界面和本地数据库，同步协议参考旧设计稿第 5 节 | 以后再排 |
