# 管理台接口 v2 契约

> 状态：**定稿**（2026-09-30）。后端（接入计划）和前端（P2 计划）都以本文为准。
> 实现过程中，任何一方觉得这份契约有问题，**先提出来，由我改文档，不要各自改代码**。
> 上游设计：[调研文档](2026-09-30-api-workbench-research.md)，第 3 节是数据模型。

## 0. 通用约定

- **前缀**：所有接口都挂在 `/__admin/api` 下；下文写的路径都省略这个前缀。
- **请求与响应格式**：请求体和响应体都是 JSON（上传文件的接口例外）。成功返回 `{ ok: true, ...数据 }`，失败返回 `{ ok: false, error: '可以直接给用户看的中文' }`。
- **状态码**：`400` 参数错误，`401` 未登录，`403` 权限不够，`404` 找不到，`500` 服务端异常。
- **登录**：用 session cookie（`apiloop_sid`）。已有的 `/auth/*` 和 `/users/*` 接口保持不变，见 `lib/admin-auth.js`。
- **权限**：P6 之前的简化规则：任何已登录用户都能读写所有项目；**只有 admin** 能管理用户、删除项目。
- **字段命名**：一律用 camelCase。时间一律是毫秒时间戳。
- **旧接口**（`/routes`、`/groups`、`/import/routes`、`/export`）继续保留，只作用于根项目，供旧版管理台使用，直到 P2 完成切换。`/preview`、`/import/curl`、`/import/openapi` 这三个是纯解析接口，新版管理台也会继续用。

## 1. 数据形状（DTO）

以下 DTO 统一定义行、请求、鉴权、项目、目录、接口、示例、环境、执行结果的形状。

```js
Row      = { key, value, type?: 'string', required?: false, desc?: '', enabled: true }
FormRow  = Row & { kind: 'text' | 'file', src: string | null }
VarRow   = { key, value, enabled: true, secret?: true, desc?: '' }

RequestSpec = {                      // 和 P3/P4 计划的「共享数据形状」完全一致
  method, url,
  params: { path: Row[], query: Row[], headers: Row[] },
  body: { mode: 'none'|'raw'|'urlencoded'|'formdata'|'binary'|'graphql',
          raw?, language?, form?: Row[]|FormRow[], file?: { src }, graphql?: { query, variables } },
  auth: null | { type: 'noauth'|'inherit'|'bearer'|'basic'|'apikey'|<其他>, ... }
}

Project = { id, slug, name, description, sourceDir, isDefault, isRoot,   // isRoot 表示在当前进程里挂在根路径
            variables: VarRow[], auth, createdAt, updatedAt }
Folder  = { id, parentId, name, description, position, auth, variables: VarRow[],
            scripts: [{ listen, exec }] }        // 只读展示；2026-09-30 修订：补上目录脚本
ApiSummary = { id, folderId, name, method, url, position, mockEnabled, mockPath }
Api = { id, projectId, folderId, name, description,
        method, url, params, body, auth,           // 这几个字段合起来就是 RequestSpec
        scripts: [{ listen, exec }],               // 只读展示，不会执行
        mock: { enabled, path, delay, cors, exampleId },
        examples: Example[], createdAt, updatedAt }
Example = { id, apiId, name, position, status, headers: Row[], body, responseType: 'json'|'text'|'html',
            isTemplate, source: 'manual'|'recorded'|'imported', createdAt }
Environment = { id, projectId, name, position, variables: VarRow[] }
ExecResult = 执行器 execute() 的返回值，原样透传（见 lib/executor.js 文件头）
```

**目录树的排序规则**：同一个父目录下，先按 position 列出子目录，再按 position 列出接口。position 只在同一父目录内部有意义。

## 3. 目录树、接口、示例

| 方法与路径 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- |
| `GET /projects/:pid/tree` | — | `{ folders: Folder[], apis: ApiSummary[] }` | 返回扁平列表，由前端组装成树 |
| `POST /projects/:pid/folders` | `{ name, parentId? }` | `{ folder }` | 同一个父目录下不允许重名 |
| `PUT /folders/:id` | `{ name?, description?, auth?, variables? }` | `{ folder }` | |
| `DELETE /folders/:id?apis=move\|delete` | — | `{}` | `move`（默认）：子目录和接口移到被删目录的父目录；`delete`：递归删除 |
| `POST /projects/:pid/move` | `{ kind: 'folder'\|'api', id, parentId: string\|null, index }` | `{ folders, apis }` | 把节点移到 `parentId` 下同类节点中的第 `index` 位，并重排该父目录的 position。把目录移进它自己或它的子孙目录，返回 400 |
| `GET /apis/:id` | — | `{ api: Api }` | |
| `POST /projects/:pid/apis` | `{ api: Api 的部分字段 }` | `{ api }` | 默认值：method `GET`，url `''`，`mock.enabled=false`，`mock.path = deriveMockPath(url)` |
| `PUT /apis/:id` | `{ api: Api 的部分字段 }` | `{ api }` | 见下方「mock.path 跟随规则」和「启用 mock 的前提」 |
| `DELETE /apis/:id` | — | `{}` | |
| `POST /apis/:id/duplicate` | — | `{ api }` | 示例整份复制，名字后面加「 副本」 |
| `POST /apis/:id/examples` | `{ example }` | `{ example, api }` | 如果这是该接口的第一个示例，并且 `mock.exampleId` 为空，就自动指向它 |
| `PUT /examples/:id` | `{ example: 部分字段 }` | `{ example }` | |
| `DELETE /examples/:id` | — | `{ api }` | 删掉的如果正是 mock 在用的示例：还有别的示例就改指第一个，没有了就把 mock 关掉 |
| `POST /projects/:pid/import/routes` | `{ routes, folderId? }` | `{ apis: ApiSummary[] }` | 把 `/import/curl`、`/import/openapi` 解析出来的 route 落进这个项目；传了 `folderId` 就落在该目录下，否则按 route.group 建顶层目录 |

**mock.path 跟随规则**：`PUT` 改了 url 而没有传 `mock.path` 时，只有旧的 `mock.path` 等于 `deriveMockPath(旧 url)`（说明用户没有手动改过它），才按新 url 重新推导；否则保持不变。

**校验规则**（2026-09-30 修订）：
- `mock.path` 必须是 Express 能编译的路由路径，例如括号要成对。不合法返回 400「mock 路径不合法：<原因>」。
- 示例的 `status` 必须是 100–599 之间的整数，否则返回 400「状态码必须是 100~599 的整数」。
- 导入时遇到这两类非法值不报错：状态码改成 200，路径照原样保存但该接口不挂到 mock 上，并在 warnings 里列出这些接口。

**启用 mock 的前提**：
- 把 `mock.enabled` 设为 true 时，接口必须至少有一个示例，否则返回 400「请先保存一个示例」。
- `exampleId` 为空时，自动指向第一个示例。
- `exampleId` 必须是这个接口自己的示例，否则返回 400。

## 5. 发送、历史、文件

### `POST /projects/:pid/send`

- **请求**：`{ request: RequestSpec, apiId?, environmentId?, options?: { timeoutMs?, followRedirects? } }`
- **响应**：`{ result: ExecResult, historyId }`
- **服务端依次做这几件事**：
  1. **变量**：`variables.fromRows(project.variables.concat(environment ? environment.variables : []))`，环境变量覆盖同名的项目变量。
  2. **鉴权继承**：`request.auth` 为 null 或 `inherit` 时，逐级向上找：先看接口所在的目录（传了 `apiId` 才有），再看它的父目录，依此类推，最后看项目。第一个既不是 null 也不是 `inherit` 的 auth 就用它。找到 `noauth` 也算找到，意思是不加鉴权。
  3. **执行选项**：`timeoutMs` 限制在 1–300000 之间，默认 30000；`rejectUnauthorized` 固定为 false；`fileRoots` 为 `[project.sourceDir（如果有）, <DATA_DIR>/files/<pid>]`，**必须传**。
  4. **取消**：浏览器断开连接时（`res` 的 `close` 事件触发，但响应还没写完），通过 `AbortController` 取消这次请求。
  5. **历史**：写入一条历史，内容是 `{ request: 原始的、未替换变量的 RequestSpec 加上 environmentId, result }`。其中 `result.response.body` 超过 256KB 的部分截断，并标记 `historyTruncated: true`。每个项目只保留最新的 500 条。

### 历史

| 方法与路径 | 响应 |
| --- | --- |
| `GET /projects/:pid/history?limit=50&before=<id>` | `{ items: [{ id, apiId, userId, method, url, status, errorCode, totalMs, createdAt }], nextBefore }` |
| `GET /history/:id` | `{ entry: { id, apiId, request, result, createdAt } }` |
| `DELETE /projects/:pid/history` | `{}` |

- 历史按 id 倒序返回。`limit` 最大 200。
- `status`：没拿到响应时为 null。
- `errorCode`：请求成功时为 null。

### 文件上传（给 formdata 和 binary 用）

- **请求**：`POST /projects/:pid/files`，请求体是文件的原始字节，`Content-Type: application/octet-stream`；请求头 `X-Filename` 是经过 `encodeURIComponent` 编码的原文件名。
- **响应**：`{ src: 服务端的绝对路径, name, size }`
- 文件存到 `<DATA_DIR>/files/<pid>/<8 位随机串>-<清理过的文件名>`。清理规则：去掉路径分隔符和控制字符，长度截到 100。
- 单个文件上限 50MB。

## 6. Postman 导入导出

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /import/postman/preview` | `{ text }` | `{ kind, name, stats, warnings }`，**不写库** |
| `POST /import/postman` | `{ text, projectId?, mode?: 'new'\|'into' }` | `{ project, stats, warnings }` |
| `GET /projects/:pid/export/postman` | — | `{ filename, json }` |
| `GET /environments/:id/export/postman` | — | `{ filename, json }` |

**导入规则**（整个导入放在一个事务里完成）：
- **collection 且 `mode` 为 `new`（默认）**：新建一个项目，名字取集合名。集合上的 `variables`、`auth`、`scripts`、`extra` 分别存到项目的对应字段。
- **collection 且 `mode` 为 `into`**：需要传 `projectId`。在该项目下建一个与集合同名的顶层目录，集合上的 `auth`、`variables`、`scripts`、`extra` 存到这个目录上。
- **environment**：需要 `projectId`，新建一个环境。
- **globals**：需要 `projectId`，并入项目变量，同名的覆盖。
- **导入进来的接口的 mock 设置**：有示例的，`mock.enabled = true`，`exampleId` 指向第一个示例；没有示例的，`mock.enabled = false`。`mock.path` 取解析结果里的 `mockPath`。
- 缺少 `projectId`，或者 `projectId` 找不到，返回 400。

**导出规则**：把目录和接口按排序规则组装成树，交给 `postman.toCollection`。示例的 `extra` 原样带回。文件名为 `<项目 slug>.postman_collection.json`。

## 8. 智能模板化（P5，2026-09-30 追加）

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /templatize` | `{ body: string }` | `{ body: string, replacements: [{ path, from, placeholder }], skipped: string\|null }` |

- 这是一个纯计算接口，**不写库**：把 JSON 文本里的「可以随机化的值」换成 `{{@...}}` 占位符。
- 输入不是合法 JSON，或者换完之后渲染一次不能得到合法 JSON 时，原样返回 body，并在 `skipped` 里说明原因。
- `replacements` 列出每一处替换，前端展示给用户确认。`path` 用 `data.list[0].phone` 这种写法。
- 替换规则只有一条原则：**宁可少换，不要换错**。凡是带业务含义的值都保持原样：状态码、`code`、`msg`、`success`、枚举、分页参数、布尔值。具体规则见 P5 计划。

## 9. Mock 期望（P5，2026-09-30 追加）

```js
Expectation = { id, apiId, name, position, enabled, exampleId,
                conditions: [{ in: 'query'|'header'|'body'|'path', key, op, value }] }
op 的取值：'eq' | 'ne' | 'contains' | 'regex' | 'exists' | 'notExists' | 'gt' | 'lt'
```

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `GET /apis/:id` | — | 在 `Api` 上**新增** `expectations: Expectation[]`，按 position 排序 |
| `POST /apis/:id/expectations` | `{ expectation }` | `{ expectation, api }` |
| `PUT /expectations/:id` | `{ expectation: 部分字段 }` | `{ expectation }` |
| `DELETE /expectations/:id` | — | `{ api }` |
| `POST /apis/:id/expectations/reorder` | `{ ids: string[] }` | `{ api }` |

**匹配规则**：
- 同一条期望里的多个条件是「且」的关系；多条期望按 position 顺序依次检查，**第一条命中的生效**，返回它指向的示例；一条都没命中时，返回 `mock.exampleId` 指向的默认示例。
- `key` 的查找方式：
  - `body` 支持用 `a.b` 取嵌套字段；
  - `header` 的 key 不区分大小写；
  - `path` 指路由上的 `:name` 参数。
- 比较方式：
  - 取到的值和 `value` 一律转成字符串后比较；
  - `gt` / `lt` 按数字比较，任一方不是数字就算不命中；
  - `exists` / `notExists` 忽略 `value`；
  - `regex` 的正则表达式在保存时校验，不合法返回 400。
- `exampleId` 必须是这个接口自己的示例，否则返回 400。示例被删除时，指向它的期望会随之删除（数据库外键级联）。
- mock 响应多带一个响应头 `X-Apiloop-Mock`：命中期望时值为 `expectation:<期望名，经 encodeURIComponent 编码>`，否则为 `default`。方便前端开发时确认命中的是哪一条。
