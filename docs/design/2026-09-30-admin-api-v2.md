# 管理台接口 v2 契约

> 状态：**定稿**（2026-09-30）。后端（接入计划）和前端（P2 计划）都以本文为准。
> 实现过程中，任何一方觉得这份契约有问题，**先提出来，由我改文档，不要各自改代码**。
> 上游设计：[调研文档](2026-09-30-api-workbench-research.md)，第 3 节是数据模型。

## 0. 通用约定

- **前缀**：所有接口都挂在 `/__admin/api` 下；下文写的路径都省略这个前缀。
- **请求与响应格式**：请求体和响应体都是 JSON（上传文件的接口例外）。成功返回 `{ ok: true, ...数据 }`，失败返回 `{ ok: false, error: '可以直接给用户看的中文' }`。
- **状态码**：`400` 参数错误，`401` 未登录，`403` 权限不够，`404` 找不到，`500` 服务端异常。
- **登录**：用 session cookie（`apiloop_sid`）。已有的 `/auth/*` 和 `/users/*` 接口保持不变，见 `lib/admin-auth.js`。
- **权限**：P6 之前的简化规则：任何已登录用户都能读写所有项目；**只有 admin** 能管理用户、删除项目。
- **字段命名**：一律用 camelCase。时间一律是毫秒时间戳。
- **旧接口**（`/routes`、`/groups`、`/import/routes`、`/export`）继续保留，只作用于根项目，供旧版管理台使用，直到 P2 完成切换。`/preview`、`/import/curl`、`/import/openapi` 这三个是纯解析接口，新版管理台也会继续用。

## 1. 数据形状（DTO）

以下 DTO 统一定义行、请求、鉴权、项目、目录、接口、示例、环境、执行结果的形状。

```js
Row      = { key, value, type?: 'string', required?: false, desc?: '', enabled: true }
FormRow  = Row & { kind: 'text' | 'file', src: string | null }
VarRow   = { key, value, enabled: true, secret?: true, desc?: '' }

RequestSpec = {                      // 和 P3/P4 计划的「共享数据形状」完全一致
  method, url,
  params: { path: Row[], query: Row[], headers: Row[] },
  body: { mode: 'none'|'raw'|'urlencoded'|'formdata'|'binary'|'graphql',
          raw?, language?, form?: Row[]|FormRow[], file?: { src }, graphql?: { query, variables } },
  auth: null | { type: 'noauth'|'inherit'|'bearer'|'basic'|'apikey'|<其他>, ... }
}

Project = { id, slug, name, description, sourceDir, isDefault, isRoot,   // isRoot 表示在当前进程里挂在根路径
            variables: VarRow[], auth, createdAt, updatedAt }
Folder  = { id, parentId, name, description, position, auth, variables: VarRow[],
            scripts: [{ listen, exec }] }        // 只读展示；2026-09-30 修订：补上目录脚本
ApiSummary = { id, folderId, name, method, url, position, mockEnabled, mockPath }
Api = { id, projectId, folderId, name, description,
        method, url, params, body, auth,           // 这几个字段合起来就是 RequestSpec
        scripts: [{ listen, exec }],               // 只读展示，不会执行
        mock: { enabled, path, delay, cors, exampleId },
        examples: Example[], createdAt, updatedAt }
Example = { id, apiId, name, position, status, headers: Row[], body, responseType: 'json'|'text'|'html',
            isTemplate, source: 'manual'|'recorded'|'imported', createdAt }
Environment = { id, projectId, name, position, variables: VarRow[] }
ExecResult = 执行器 execute() 的返回值，原样透传（见 lib/executor.js 文件头）
```

**目录树的排序规则**：同一个父目录下，先按 position 列出子目录，再按 position 列出接口。position 只在同一父目录内部有意义。

| `GET /apis/:id` | — | `{ api: Api }` | |

| `PUT /apis/:id` | `{ api: Api 的部分字段 }` | `{ api }` | 见下方「mock.path 跟随规则」和「启用 mock 的前提」 |
| `DELETE /apis/:id` | — | `{}` | |
| `POST /apis/:id/duplicate` | — | `{ api }` | 示例整份复制，名字后面加「 副本」 |
| `POST /apis/:id/examples` | `{ example }` | `{ example, api }` | 如果这是该接口的第一个示例，并且 `mock.exampleId` 为空，就自动指向它 |
| `PUT /examples/:id` | `{ example: 部分字段 }` | `{ example }` | |
| `DELETE /examples/:id` | — | `{ api }` | 删掉的如果正是 mock 在用的示例：还有别的示例就改指第一个，没有了就把 mock 关掉 |
| `POST /projects/:pid/import/routes` | `{ routes, folderId? }` | `{ apis: ApiSummary[] }` | 把 `/import/curl`、`/import/openapi` 解析出来的 route 落进这个项目；传了 `folderId` 就落在该目录下，否则按 route.group 建顶层目录 |

**mock.path 跟随规则**：`PUT` 改了 url 而没有传 `mock.path` 时，只有旧的 `mock.path` 等于 `deriveMockPath(旧 url)`（说明用户没有手动改过它），才按新 url 重新推导；否则保持不变。

**校验规则**（2026-09-30 修订）：
- `mock.path` 必须是 Express 能编译的路由路径，例如括号要成对。不合法返回 400「mock 路径不合法：<原因>」。
- 示例的 `status` 必须是 100–599 之间的整数，否则返回 400「状态码必须是 100~599 的整数」。
- 导入时遇到这两类非法值不报错：状态码改成 200，路径照原样保存但该接口不挂到 mock 上，并在 warnings 里列出这些接口。

**启用 mock 的前提**：
- 把 `mock.enabled` 设为 true 时，接口必须至少有一个示例，否则返回 400「请先保存一个示例」。
- `exampleId` 为空时，自动指向第一个示例。
- `exampleId` 必须是这个接口自己的示例，否则返回 400。

## 5. 发送、历史、文件

### `POST /projects/:pid/send`

- **请求**：`{ request: RequestSpec, apiId?, environmentId?, options?: { timeoutMs?, followRedirects? } }`
- **响应**：`{ result: ExecResult, historyId }`
- **服务端依次做这几件事**：
  1. **变量**（2026-09-30 修订，原来漏掉了目录变量）：按下面的顺序拼接，**后面的覆盖前面同名的**：
     - 项目变量；
     - 接口所在目录链上的变量，**从最外层到最内层**（传了 `apiId` 才有）；
     - 当前环境的变量。

     也就是说，优先级是「项目 < 外层目录 < 内层目录 < 环境」。这样和 Postman「环境覆盖集合变量」的习惯一致；Postman 以 `into` 方式导入时，集合变量存在顶层目录上，也能生效。目录链和第 2 步的鉴权继承用的是同一条。WebSocket 会话（第 15 节）和流式发送（第 14 节）走的是同一段代码，所以同样适用。
  2. **鉴权继承**：`request.auth` 为 null 或 `inherit` 时，逐级向上找：先看接口所在的目录（传了 `apiId` 才有），再看它的父目录，依此类推，最后看项目。第一个既不是 null 也不是 `inherit` 的 auth 就用它。找到 `noauth` 也算找到，意思是不加鉴权。
  3. **执行选项**：`timeoutMs` 限制在 1–300000 之间，默认 30000；`rejectUnauthorized` 固定为 false；`fileRoots` 为 `[project.sourceDir（如果有）, <DATA_DIR>/files/<pid>]`，**必须传**。
  4. **取消**：浏览器断开连接时（`res` 的 `close` 事件触发，但响应还没写完），通过 `AbortController` 取消这次请求。
  5. **历史**：写入一条历史，内容是 `{ request: 原始的、未替换变量的 RequestSpec 加上 environmentId, result }`。其中 `result.response.body` 超过 256KB 的部分截断，并标记 `historyTruncated: true`。每个项目只保留最新的 500 条。

### 历史

| 方法与路径 | 响应 |
| --- | --- |
| `GET /projects/:pid/history?limit=50&before=<id>` | `{ items: [{ id, apiId, userId, method, url, status, errorCode, totalMs, createdAt }], nextBefore }` |
| `GET /history/:id` | `{ entry: { id, apiId, request, result, createdAt } }` |
| `DELETE /projects/:pid/history` | `{}` |

- 历史按 id 倒序返回。`limit` 最大 200。
- `status`：没拿到响应时为 null。
- `errorCode`：请求成功时为 null。

### 文件上传（给 formdata 和 binary 用）

- **请求**：`POST /projects/:pid/files`，请求体是文件的原始字节，`Content-Type: application/octet-stream`；请求头 `X-Filename` 是经过 `encodeURIComponent` 编码的原文件名。
- **响应**：`{ src: 服务端的绝对路径, name, size }`
- 文件存到 `<DATA_DIR>/files/<pid>/<8 位随机串>-<清理过的文件名>`。清理规则：去掉路径分隔符和控制字符，长度截到 100。
- 单个文件上限 50MB。

## 6. Postman 导入导出

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /import/postman/preview` | `{ text }` | `{ kind, name, stats, warnings }`，**不写库** |
| `POST /import/postman` | `{ text, projectId?, mode?: 'new'\|'into' }` | `{ project, stats, warnings }` |
| `GET /projects/:pid/export/postman` | — | `{ filename, json }` |
| `GET /environments/:id/export/postman` | — | `{ filename, json }` |

**导入规则**（整个导入放在一个事务里完成）：
- **collection 且 `mode` 为 `new`（默认）**：新建一个项目，名字取集合名。集合上的 `variables`、`auth`、`scripts`、`extra` 分别存到项目的对应字段。
- **collection 且 `mode` 为 `into`**：需要传 `projectId`。在该项目下建一个与集合同名的顶层目录，集合上的 `auth`、`variables`、`scripts`、`extra` 存到这个目录上。
- **environment**：需要 `projectId`，新建一个环境。
- **globals**：需要 `projectId`，并入项目变量，同名的覆盖。
- **导入进来的接口的 mock 设置**：有示例的，`mock.enabled = true`，`exampleId` 指向第一个示例；没有示例的，`mock.enabled = false`。`mock.path` 取解析结果里的 `mockPath`。
- 缺少 `projectId`，或者 `projectId` 找不到，返回 400。

**导出规则**：把目录和接口按排序规则组装成树，交给 `postman.toCollection`。示例的 `extra` 原样带回。文件名为 `<项目 slug>.postman_collection.json`。

## 8. 智能模板化（P5，2026-09-30 追加）

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /templatize` | `{ body: string }` | `{ body: string, replacements: [{ path, from, placeholder }], skipped: string\|null }` |

- 这是一个纯计算接口，**不写库**：把 JSON 文本里的「可以随机化的值」换成 `{{@...}}` 占位符。
- 输入不是合法 JSON，或者换完之后渲染一次不能得到合法 JSON 时，原样返回 body，并在 `skipped` 里说明原因。
- `replacements` 列出每一处替换，前端展示给用户确认。`path` 用 `data.list[0].phone` 这种写法。
- 替换规则只有一条原则：**宁可少换，不要换错**。凡是带业务含义的值都保持原样：状态码、`code`、`msg`、`success`、枚举、分页参数、布尔值。具体规则见 P5 计划。

## 9. Mock 期望（P5，2026-09-30 追加）

```js
Expectation = { id, apiId, name, position, enabled, exampleId,
                conditions: [{ in: 'query'|'header'|'body'|'path', key, op, value }] }
op 的取值：'eq' | 'ne' | 'contains' | 'regex' | 'exists' | 'notExists' | 'gt' | 'lt'
```

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `GET /apis/:id` | — | 在 `Api` 上**新增** `expectations: Expectation[]`，按 position 排序 |
| `POST /apis/:id/expectations` | `{ expectation }` | `{ expectation, api }` |
| `PUT /expectations/:id` | `{ expectation: 部分字段 }` | `{ expectation }` |
| `DELETE /expectations/:id` | — | `{ api }` |
| `POST /apis/:id/expectations/reorder` | `{ ids: string[] }` | `{ api }` |

**匹配规则**：
- 同一条期望里的多个条件是「且」的关系；多条期望按 position 顺序依次检查，**第一条命中的生效**，返回它指向的示例；一条都没命中时，返回 `mock.exampleId` 指向的默认示例。
- `key` 的查找方式：
  - `body` 支持用 `a.b` 取嵌套字段；
  - `header` 的 key 不区分大小写；
  - `path` 指路由上的 `:name` 参数。
- 比较方式：
  - 取到的值和 `value` 一律转成字符串后比较；
  - `gt` / `lt` 按数字比较，任一方不是数字就算不命中；
  - `exists` / `notExists` 忽略 `value`；
  - `regex` 的正则表达式在保存时校验，不合法返回 400。
- `exampleId` 必须是这个接口自己的示例，否则返回 400。示例被删除时，指向它的期望会随之删除（数据库外键级联）。
- mock 响应多带一个响应头 `X-Apiloop-Mock`：命中期望时值为 `expectation:<期望名，经 encodeURIComponent 编码>`，否则为 `default`。方便前端开发时确认命中的是哪一条。

## 10. 项目权限（P6，2026-09-30 追加）

**可见性（用户已拍板）**：一个项目**只有它的成员能看到**。admin 始终能看到、管理所有项目。

**角色与能力**（高级角色包含低级角色的全部能力）：

| 角色 | 能做什么 |
| --- | --- |
| `viewer` | 查看项目、目录树、接口、示例、期望、环境、历史；发请求（`/send`，以及发请求要用的文件上传）；导出 Postman |
| `editor` | 在 viewer 的基础上：增删改目录、接口、示例、期望、环境；修改项目的 `variables` / `auth` / `description`；把数据导入到这个项目（`import/routes`，以及 Postman 的 `into` 模式、environment、globals）；清空历史 |
| `owner` | 在 editor 的基础上：修改项目的 `name` / `slug`；管理成员；删除项目 |
| admin（系统角色） | 对所有项目都拥有 owner 的全部能力 |

**判定规则**：
- **不是成员**，或者**对象不存在**：统一返回 404，错误信息「项目不存在」或「接口不存在」等。这样不会暴露「这个项目存在，只是你看不到」。
- **是成员但角色不够**：返回 403「需要 <角色> 权限」。
- **不属于任何项目的接口**（`/templatize`、`/preview`、`/import/curl`、`/import/openapi`、`/import/postman/preview`，以及 `mode: 'new'` 的 Postman 导入）：只要登录了就能用。
- **新建项目**（`POST /projects`、Postman 的 new 导入）：任何登录用户都可以，创建者自动成为 owner。
- **旧接口**（`/routes`、`/groups`、`/import/routes`、`/export`）：作用于根项目，读操作要求 viewer，写操作要求 editor。
- **mock 接口本身始终不鉴权。**

**项目 DTO 新增字段**：`myRole: 'admin' | 'owner' | 'editor' | 'viewer'`。

**成员接口**：

| 方法与路径 | 权限 | 请求 | 响应 |
| --- | --- | --- | --- |
| `GET /projects/:pid/members` | viewer | — | `{ members: [{ userId, username, displayName, role, disabled }] }` |
| `PUT /projects/:pid/members/:userId` | owner | `{ role }` | `{ members }`：用户不是成员就添加，是成员就修改角色 |
| `DELETE /projects/:pid/members/:userId` | owner，或者自己退出 | — | `{ members }` |
| `GET /users/lookup?q=` | 登录即可 | — | `{ users: [{ id, username, displayName }] }`：按用户名或显示名模糊匹配，最多 20 条，不含已禁用的用户。添加成员时用来搜人 |

- 任何操作都不能让一个项目的 owner 变成 0 个，否则返回 400「项目至少要保留一个 owner」。
- 删除用户时，他的成员关系随之删除（数据库外键级联）。如果因此导致某个项目没有 owner，由 admin 通过成员接口补上，接口本身不拦。

**存量数据迁移**：
- 所有现有项目 × 所有现有用户，全部设为 editor。
- 项目的创建者（`created_by`）设为 owner；legacy 导入时已经写入的 owner 保持不变。
- 仍然没有 owner 的项目，由最早创建的那个 admin 担任 owner。
- 迁移完成后新建的用户，不会自动加入任何项目。

## 11. Mock 调用日志（2026-09-30 追加）

```js
MockLogItem = { seq, time, method, url,          // url 是完整原始地址，含 /mock/<slug> 前缀和查询串
                query, headers: [[k, v]],        // Authorization / Cookie / Proxy-Authorization 的值替换成 '***'
                bodyPreview,                     // 请求体的前 4KB（文本）
                matched: null | { apiId, apiName, via: 'default' | 'expectation', expectationName? },
                status, durationMs, responsePreview }   // 响应体的前 4KB
```

| 方法与路径 | 权限 | 请求 | 响应 |
| --- | --- | --- | --- |
| `GET /projects/:pid/mock-log?after=<seq>&limit=100` | viewer | — | `{ items: MockLogItem[]（按 seq 升序）, lastSeq }` |
| `DELETE /projects/:pid/mock-log` | editor | — | `{}` |

- **存储**：日志**只保存在当前进程的内存里**，每个项目保留最近 200 条，服务重启后清空。多个进程共用同一个库时，各进程只记录打到自己端口上的请求。
- **seq**：在进程内单调递增，所有项目共用一个计数器。前端每 2 秒用 `after=lastSeq` 轮询一次，就能拿到新增的记录。
- **哪些请求会记录**：
  - 被 mock 运行时匹配到的请求，全部记录；
  - `/mock/<slug>/...` 下**没有**匹配到的请求，也要记录，此时 `matched: null`，这正是联调时最需要看到的；
  - 根路径下没有匹配到的请求**不记录**，因为里面混有大量静态文件请求。

## 12. Cookie 自动管理与代理（P7a，2026-09-30 追加）

### Cookie

**作用范围：每个用户在每个项目里各有一份 Cookie 库，互不可见。** Cookie 往往就是登录凭证，同一个项目的不同成员登录的是不同账号，所以不能共用。

```js
Cookie = { id, domain, path, name, value, expires /* 毫秒时间戳；null 表示会话 cookie */,
           hostOnly, secure, httpOnly, sameSite, createdAt, updatedAt }
```

| 方法与路径 | 权限 | 请求 | 响应 |
| --- | --- | --- | --- |
| `GET /projects/:pid/cookies` | viewer | — | `{ cookies }`（只返回自己的，已过期的不返回） |
| `POST /projects/:pid/cookies` | viewer | `{ cookie: { domain, path?, name, value, expires?, secure?, httpOnly? } }` | `{ cookie }`：按 `domain + path + name` 定位，已有就更新，没有就新增。`domain` 以 `.` 开头表示域 cookie（会发给子域名），否则是 host-only；返回的 `domain` 不带点，用 `hostOnly` 区分（2026-09-30 补充） |
| `DELETE /cookies/:id` | 只能删自己的 | — | `{}` |
| `DELETE /projects/:pid/cookies?domain=` | viewer | — | `{}`：清空自己在这个项目下的 Cookie；带 `domain` 参数时只清这个域名的 |

**`/send` 的变化**：
- `options.cookies` 默认为 `true`。开启时，每一跳请求（包括重定向后的请求）都会自动带上 Cookie 库里匹配的 cookie；每一跳响应里的 `Set-Cookie` 都会写回 Cookie 库。传 `false` 时，这次请求既不带 cookie，也不写回。
- 如果用户在请求头里手写了 `Cookie`，就以手写的为准：**整个请求的所有跳**都不再从 Cookie 库里补充 cookie，但响应里的 `Set-Cookie` 照样写回 Cookie 库。

**历史记录要打码**：历史会被项目里的所有成员看到，所以写入历史时（**只处理历史这一份**，返回给发送者本人的结果保持原样）：
- `result.request.headers` 里 `Cookie`、`Authorization`、`Proxy-Authorization` 的值替换成 `***`；
- `result.response.headers` 里每条 `Set-Cookie` 保留 cookie 名和各项属性，只把值替换成 `***`，例如 `sid=***; Path=/; HttpOnly`；
- （2026-09-30 修订）这次实际生效的鉴权是 apikey 时（取继承解析、变量替换之后的 `auth`；`key` 为空时执行器本来就不会加，这里也不处理）：
  - `in` 为 header：`result.request.headers` 里名为 `auth.key` 的请求头（不区分大小写）值替换成 `***`；
  - `in` 为 query：`result.request.url` 里执行器追加的那个 `auth.key` 参数，值替换成 `***`，URL 其余部分逐字保留。

**历史中的原始请求也要打码**（2026-09-30 修订，补上之前漏掉的情况）：

历史的 `request.spec` 保存的是用户输入的原始请求，里面可能有手写的凭据。它**完整入库**，因为发起人自己重放历史时需要完整内容。读取时按查看者区分：

- `GET /history/:id` 的查看者**不是这条历史的发起人**（包括 admin）时，返回前对副本做打码：
  - `spec.params.headers` 中 `Authorization`、`Cookie`、`Proxy-Authorization` 的值（不区分大小写）替换为 `***`；
  - `spec.auth` 中的敏感字段替换为 `***`：bearer 的 `token`、basic 的 `password`、apikey 的 `value`。
- 发起人本人查看时，返回完整内容。

### 代理（系统设置，仅 admin 可以修改）

```js
ProxySetting = { enabled, http: 'http://user:pass@host:port' | '', https: 同上 | '', noProxy: 'localhost,127.0.0.1,::1,.internal' }
```

| 方法与路径 | 权限 | 请求 | 响应 |
| --- | --- | --- | --- |
| `GET /settings/proxy` | 登录即可 | — | `{ proxy: ProxySetting }`：代理地址里的密码显示为 `***` |
| `PUT /settings/proxy` | admin | `{ proxy: 部分字段 }` | `{ proxy }`：如果提交的密码是 `***`，表示「密码不变」。**只有协议、主机、端口、用户名都和原地址相同时才保留原密码**，否则返回 400，要求重新输入密码，防止把旧密码带到另一台代理上（2026-09-30 修订） |

**规则**：
- **默认值**：数据库里还没有这项设置时，默认值从环境变量 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 读取（大小写两种写法都认）。只要读到任何一个，`enabled` 就为 true。
- **代理类型**：只支持 `http://` 形式的代理。目标是 https 时，通过 `CONNECT` 建立隧道。`socks://` 和 `https://` 形式的代理地址，在保存时返回 400。
- **`noProxy` 的写法**：用逗号分隔，每一项可以是精确的主机名、以 `.` 开头的后缀、`*`（全部不走代理），也可以是 `host:port`。
- **`/send` 新增选项** `options.proxy`，默认为 `true`：按系统设置决定是否走代理；传 `false` 时这次请求直连。
- **`ExecResult` 新增字段** `proxy: null | { url }`：显示这次请求实际使用的代理，地址里的密码打码。新增错误码 `PROXY`：连不上代理，或者 `CONNECT` 返回的不是 2xx，都用这个错误码。

## 13. HAR 导入（2026-09-30 追加）

把浏览器开发者工具导出的 HAR 文件（HAR 1.2），批量生成接口和示例。数据写入走和 Postman 导入完全相同的那条路（`tree.writeTree`，整个导入放在一个事务里）。

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /import/har/preview` | `{ text, options?: { keepCredentials?: boolean } }` | `{ name, stats, warnings }`，**不写库** |
| `POST /import/har` | `{ text, projectId?, mode?: 'new'\|'into', options? }` | `{ project, stats, warnings }` |

- **请求体上限**：这两个路径是 **50MB**，因为 HAR 文件经常有几十 MB。管理台其他接口仍然是 4MB。
- **`mode` 和权限**：和第 6 节 Postman 的 collection 导入一样。
  - `new`（默认）：新建一个项目，导入者成为 owner；
  - `into`：需要传 `projectId`，并且要求 editor 权限。项目不存在或者不是成员，都返回同一个 400。
- `stats = { hosts, apis, examples, skipped, examplesDropped, bodiesMissing, credentialsStripped, filesDropped }`

**识别**：顶层必须有 `log.entries` 数组，否则返回 400：「不是 HAR 文件」。

**过滤**（被过滤掉的条目计入 `stats.skipped`）：
- 请求地址不是 `http:` 或 `https:` 的，跳过（`ws:`、`data:`、`chrome-extension:` 等）。
- 条目上有 `_resourceType` 字段（Chrome 导出的有）时，只保留 `xhr` 和 `fetch`。
- 没有 `_resourceType` 字段时，按响应的 `content.mimeType` 跳过静态资源：`image/*`、`font/*`、`audio/*`、`video/*`、`text/css`、含 `javascript` 的、`text/html`、`application/wasm`。

**分组与合并**：
- **项目名**：取 `log.pages[0].title`，没有就用「HAR 导入 YYYY-MM-DD HH:mm」（导入时的本地时间）。
- **目录**：每个主机一个顶层目录，名字是 `host`，非默认端口要带上端口。`into` 模式下，先建一个以项目名命名的顶层目录，主机目录都放在它下面。
- **接口**：`方法 + origin + pathname` 相同的条目，合并成一个接口。
  - 名字是 `方法 pathname`，例如 `GET /api/users`；
  - 按 `startedDateTime` 排序后，由**第一条**决定接口的请求内容；
  - `url` 不带查询串，查询串放进 `params.query`；
  - 接口的 mock 设置按第 6 节的规则：`mockPath` 用 `urlUtils.deriveMockPath` 生成；有示例时启用 mock，默认示例是第一条。

**请求内容的清理**：
- **请求头**：
  - 去掉名字以 `:` 开头的（HTTP/2 的伪头）；
  - 去掉 `host`、`content-length`、`connection`、`keep-alive`、`transfer-encoding`、`te`、`upgrade`。
- **凭据**：`options.keepCredentials` 不为 true 时（**默认就是不保留**），去掉以下内容，每去掉一处 `stats.credentialsStripped` 加 1：
  - 请求头 `Cookie`、`Authorization`、`Proxy-Authorization`；
  - 示例响应头里的 `Set-Cookie`。

  原因：HAR 是从真实的浏览器会话里录下来的，里面带着登录态，而导入的项目是全体成员都能看到的。
- **请求体**：
  - mimeType 含 `x-www-form-urlencoded`，并且有 `postData.params`：用 `urlencoded` 模式；
  - mimeType 含 `multipart/form-data`：用 `formdata` 模式，只保留文本字段。文件字段的值置空，每个计入 `stats.filesDropped`；
  - 其他情况，只要有 `postData.text`，就用 `raw` 模式。`language` 的取法：mimeType 含 `json` 取 `json`，含 `xml` 取 `xml`，否则取 `text`；
  - 没有 `postData`：`none`。

**示例**（每一条被保留的条目，都尝试生成一个示例）：
- **不生成示例的情况**：
  - 状态码是 0（请求被拦截或失败）；
  - 响应不是文本类型；
  - 拿不到 `content.text`。

  除状态码为 0 以外，另外两种情况计入 `stats.bodiesMissing`。
- **文本类型**的判定：mimeType 是 `text/*`，或者含 `json`、`xml`、`javascript` 之一。如果 `content.encoding` 是 `base64`，按 utf8 解码。
- **去重和上限**：同一个接口下，`状态码 + 响应体` 完全相同的示例只保留最早的一条；每个接口**最多 5 条**示例。超出上限和重复的都计入 `stats.examplesDropped`。
- **示例内容**：
  - 名字：`<状态码> <HH:mm:ss>`，取 `startedDateTime` 的本地时间；
  - `source`：`'imported'`；
  - `responseType`：和 Postman 导入的判断方式一致；
  - 响应头：去掉 `content-length`、`content-encoding`（响应体已经是解码后的内容了）、`transfer-encoding`、`connection`，以及按凭据规则去掉的 `Set-Cookie`。

**警告**：`stats` 里每一项不为 0 的计数，都生成一句中文说明。例如：
- 「跳过了 37 条静态资源或非 http 请求」；
- 「已去掉 12 处 Cookie / Authorization 等凭据；如需保留，导入时勾选『保留凭据』」。

## 14. 流式发送：SSE 与大响应（P7b，2026-09-30 追加）

`POST /send` 保持不变。新增一个流式版本，前端所有「发送」都改走它：这样 SSE 能实时看到，并且任何请求都能随时取消。

| 方法与路径 | 请求 | 响应 |
| --- | --- | --- |
| `POST /send/stream` | 和 `POST /send` **完全相同** | `Content-Type: application/x-ndjson; charset=utf-8`，每行一个 JSON 事件 |

**开始流式输出之前出的错，按普通 JSON 返回**，状态码和文案都和 `/send` 一致（400、403、404 等）。一旦返回了 200，后面的一切都通过事件表达。

响应头：`Cache-Control: no-cache`、`X-Accel-Buffering: no`。每个事件写完之后立即 flush。

**事件**（按顺序出现）：

```js
{ type: 'head', response: { status, statusText, httpVersion, headers }, redirects }  // 最后一跳的响应头到达时，最多出现一次
{ type: 'chunk', text }            // 文本类型的响应：解压之后、按 UTF-8 解码的一段（用 StringDecoder，不能把多字节字符切断）
{ type: 'chunk', base64 }          // 非文本类型的响应
{ type: 'end', result, historyId } // 恰好一次，而且是最后一条。result 就是 /send 返回的那个 ExecResult
```

**规则**：
- **超时**：`options.timeoutMs` 只管到 `head` 为止。`head` 到达之后就不再有总超时，SSE 可以一直连着，由用户主动取消。
- **取消**：客户端断开连接（前端 abort 掉 fetch），服务端就中止上游请求。执行器照常给出 `error.code = 'ABORTED'` 的结果。**取消时历史照样记录**，里面带着已经收到的那部分响应体。这时连接已经断开，`end` 事件写不出去也没有关系。
- **`chunk` 全部转发**：已经发出去的数据不受 `maxBodyBytes` 限制。`result.response.body` 仍然按 `maxBodyBytes` 截断，并设置 `truncated` 标记。历史仍然按第 12 节打码，按 256KB 截断。
- 重定向中间那几跳不发 `chunk`，只有最后一跳的响应体会发 `chunk`。
- Cookie、代理、打码的行为都和 `/send` 完全一样，因为走的是同一段代码。

## 15. WebSocket 调试会话（P7b，2026-09-30 追加）

浏览器不能给 WebSocket 设置自定义请求头，也不能绕开跨域限制，所以由服务端作为客户端去连接目标，前端通过下面几个接口来操作。服务端使用 **Node 自带的 `WebSocket`**，不引入新依赖。

**v1 的范围**：WebSocket 是一种临时的调试标签页，**不存进目录树，不记录历史，也不做 mock**。

| 方法与路径 | 权限 | 请求 | 响应 |
| --- | --- | --- | --- |
| `POST /projects/:pid/ws` | viewer | `{ spec: { url, params: { headers, query }, auth }, environmentId?, options?: { cookies? } }` | `{ session: { id, url } }`，建好后立即开始连接 |
| `GET /ws/:id/events?after=<seq>` | 只有会话创建者 | — | NDJSON 长连接：先补发 `seq > after` 的缓冲事件，然后持续推送新事件 |
| `POST /ws/:id/send` | 只有会话创建者 | `{ text }` 或 `{ base64 }` | `{}`；连接还没有打开或者已经关闭时，返回 409 |
| `DELETE /ws/:id` | 只有会话创建者 | — | `{}`：用 1000 关闭，并立即销毁会话 |

**事件**：

```js
{ seq, time, type: 'open', protocol, note? }
{ seq, time, type: 'message', direction: 'in'|'out', text? , base64?, size, truncated }
{ seq, time, type: 'close', code, reason }
{ seq, time, type: 'error', message }
```

**规则**：
- **地址**：`url` 在变量替换之后，必须是 `ws://` 或 `wss://`，否则返回 400。变量、鉴权继承、bearer、basic、apikey 的处理方式都和 `/send` 相同。apikey 放在 query 时，拼接到地址上。
- **子协议**：`params.headers` 里如果有 `Sec-WebSocket-Protocol`，把它的值按逗号拆开，作为 protocols 参数传入，并从请求头里去掉这一项。
- **Cookie**：`options.cookies` 默认是 true。开启时，把目标地址换成对应的 http(s) 地址，按这个地址从 Cookie 库里取出匹配的 cookie，附加到 `Cookie` 请求头上。如果用户手写了 `Cookie`，就以手写的为准。**握手响应里的 `Set-Cookie` 拿不到，不会写回**，这一点要写进 README 的已知限制。
- **代理和证书**：WebSocket **不走系统代理**，也**不能关闭证书校验**。如果按系统设置，这个目标本来应该走代理，就在 `open` 事件的 `note` 里写明「系统代理不作用于 WebSocket，本次为直连」。
- **缓冲**：每个会话最多缓冲最近 500 个事件，`seq` 在会话内从 1 开始递增。单条消息超过 64KB 的部分截断，并设置 `truncated: true`；`size` 始终是原始大小。
- **归属**：会话只有创建者本人能访问，其他人一律返回 404，admin 也不例外，因为会话里带着创建者的凭据。另外，创建者如果已经不再是这个项目的成员，也返回 404。
- **生命周期**：会话只存在内存里，服务重启就没了。满足下面任一条件时销毁会话：
  - 上游关闭满 60 秒；
  - 没有任何 `events` 连接满 60 秒（浏览器标签页关掉之后，不能让连接一直挂在服务端）；
  - `DELETE`。

  每个用户同时最多保持 10 个会话，超出时返回 400。
- **`/events` 的 NDJSON 响应头**：和第 14 节相同。同一个会话允许多个 `events` 连接同时存在，比如刷新了页面的情况。
